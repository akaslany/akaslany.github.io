근거 소스 3편

과제별 개선과 평가

Poetiq 사례를 다룬 기사는 언어 모델 외부의 과제별 하네스가 평가, 수정, 재평가를 반복해 특정 작업의 최적화 절차를 다듬는다고 설명한다. 기사에 실린 Baluja의 설명에 따르면 Augur는 이 과정에서 모델별 강점 지도를 자동으로 만들던 내부 기능을 제품화한 것이다. 근거 C

Augur를 분석한 별도 보고서는 질문을 점차 정교하게 만들어 모델이 실패하는 경계를 탐색한다고 설명한다. 작성자는 이 방식이 고정 문항의 암기 위험을 줄일 수 있다고 보면서도, 데이터 오염에 대한 내성은 독립 검증 과제로 남겼다. 근거 B

완전 자율 개선의 실증 범위

OpenAI 인터뷰를 검토한 보고서 작성자는 제한된 자기 개선과 AI 보조 연구개발의 가능성을 뒷받침하는 사례를 제시하고, 완전 자율 재귀 개선은 아직 실증되지 않았다고 평가했다. 이후 비공개 시연을 검토한 별도 보고서는 파호츠키가 설명한 내부 연구 자동화 과제를 주어진 실험 아이디어의 구현, 실행, 결과 반환으로 정리했다. 재귀적 자기 개선이 시작됐다는 판단은 히스의 해석으로 분류했다. 근거 D · 근거 F

Poetiq 사례 보고서는 내부 기술 자료, 벤치마크 원자료, 외부 보안 평가 결과를 독립적으로 검증하지 않았다고 밝혔다. 작성자는 외부 판매 제한이 접근을 통제하는 조치이며 기술 자체의 안전성은 별도로 입증해야 한다고 평가했다. 근거 C

유한 시간 특이점의 조건

수학적 분석 보고서의 모형에서 유한 시간 특이점이 발생할 필요충분조건은 모든 세대에 걸리는 시간의 합이 유한하고 지능 향상분의 누적합이 한없이 커지는 것이다. 세대마다 일정한 최소 시간이 필요하면 시간 조건은 성립할 수 없으며, 지능이 일정한 배수로 늘어나는 데 걸리는 시간이 짧아지는 현상만으로는 특이점 발생을 판단할 수 없다. 근거 E

인용

**LLM 외부에서 작동하는 '좁은 과제용 하네스(Harness)'**가 **[평가 → 수정 → 재평가]** 과정을 반복하며 특정 작업의 최적화 절차를 다듬는 구조로 소개됩니다.
