Augur와 모델 평가

Augur는 질문을 점진적으로 정교화해 모델이 어느 지점에서 실패하는지 탐색한다. 맞춤형 벤치마크로 모델을 비교해 과업에 맞는 모델을 비용과 성능을 고려해 고를 수 있도록 돕는다. 근거 A · 근거 B

Poetiq은 모델이 필요한 개별 사실을 알고 있고 정답 일치 여부로 보상을 검증할 수 있는 추론 실패를 강화학습 후보로 본다. 이 분석에 쓰인 내부 측정 결과는 독립 검증을 거치지 않았다. 근거 A

과업별 반복 개선

보도에 따르면 Poetiq은 언어 모델 외부에서 평가, 수정, 재평가를 반복해 특정 과업의 최적화 절차를 다듬는다. 보고서 작성자는 공개된 절차만으로 강한 형태의 재귀적 자기 개선이 입증됐다고 판단하기 어렵다고 봤다. 근거 B · 근거 A

코드와 모델을 결합한 실행

Poetiq의 메타시스템은 설계 단계에서 언어 모델의 판단을 파이썬 코드로 옮기고, 배포 단계에서는 코드로 처리하기 어려운 입력에만 모델을 호출한다. 실험 보고서는 이 방식으로 불만 분류 비용을 줄였고 WikiRacer에서 이동 횟수와 의사결정 시간을 줄였다고 설명한다. 근거 C

인용

모델의 능력이 끝나는 지점(Capability boundary)을 찾기 위해 질문을 점진적으로 정교화하는 '날카롭게 만들기(Sharpening)' 메커니즘을 사용합니다.
