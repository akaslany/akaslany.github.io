읽기 전에: 이 글의 성격

이 보고서는 OpenAI가 2026년 9월 6일 공개한 「Research acceleration: The view inside OpenAI」 한 편을 원문 순서대로 설명한다. 아래의 측정값, 분류법, 해석, 제품 행동, 사건 설명, 안전 조치와 거버넌스 약속은 모두 OpenAI가 자사 연구 조직을 관찰해 제시한 내부·예비 주장이다. 외부 자료로 독립 검증하거나 인과관계를 추가하지 않았다.

OpenAI는 고도 AI의 역량·위험·보호조치에 관한 공론과 민주적 거버넌스를 강조하며 글을 시작한다. 특정 위험·사건·보호조치의 공개만으로는 충분하지 않고, 최전선 연구소 안에서 가장 유능한 시스템이 어떻게 발전하고 연구 진전에 기여하는지도 대중이 알아야 한다는 입장이다.

도입: ‘research intern’ 목표와 인간 통제

OpenAI는 인간 감독 아래 딥러닝과 정렬 연구를 진전시키는 자동화 AI 연구자를 안전하게 구축하려 한다고 썼다. 자사의 측정에 따르면 지난해 가을 발표했던 “올해 9월까지 automated research intern” 목표에 도달했다고 주장한다. 그러나 이 표현의 범위는 제한적이다. 이 글에서 research intern은 인간의 지시 아래 잘 정의된 연구 과업, 숙련된 연구자에게 며칠이 걸릴 수 있는 과업을 수행할 수 있는 시스템을 뜻한다. 모든 연구를 독립적으로 수행하는 일반 자율 연구자에 대한 보장이나 이미 확립된 외부 성과를 뜻하지 않는다. OpenAI는 2028년 3월까지 automated AI researcher를 만드는 방향으로 진전하고 있다고 표현한다.

OpenAI가 제시한 내부 인상은 coding agent가 연구 진전을 의미 있게 가속한다는 것이다. 연구자들은 에이전트를 하루 종일, 때로는 여러 세션으로 동시에 사용하고, 코드 기여와 실험 수행도 늘었다. 하지만 글 자체가 중요한 한계를 붙인다. AI 연구에는 잠재적 병목이 많으므로 전체 연구 진전 속도가 특정 사용량 지표와 같은 비율로 빨라지리라고 볼 수 없다. 사람은 여전히 연구 우선순위를 정하고, 어떤 아이디어와 결과를 추구할지 판단하며, 시스템을 확대·중단·배포할지를 결정한다.

자동화 연구가 인간 복지, 정렬, 방어에 도움이 될 수 있다는 기대도 조건부다. OpenAI는 이것이 rapid recursive self-improvement를 반드시 추구해야 한다는 뜻은 아니라고 적는다. 진행 여부와 방식은 인간 통제를 보존할 능력과 혜택·위험에 관한 민주적 선택에 달려 있다고 말한다. 정렬된 full RSI에 안전하게 도달하는 방법을 아직 알지 못하고, 정렬·안전 진전이 역량 진전을 따라갈 것이라고 가정할 수 없으며, 더 유능한 시스템이 더 모니터링하기 어려워질 수 있다는 한계도 명시한다. 충분히 보호할 수 없는 시스템의 개발·배포가 용납할 수 없는 위험을 만든다고 판단하면 늦추거나 멈추겠다는 것이 이 글의 약속이다.

사건 대응: pause, hardening, monitoring의 범위

OpenAI는 최근 Hugging Face incident 이후 최신 배포 예정 모델의 reinforcement learning 훈련을 pause했다고 설명한다. 그 사이 연구 환경을 더 강화하고 red-team을 수행했으며 monitoring system의 적용 범위를 넓혔다. 모든 연구가 멈춘 것은 아니다. 일부 workload는 더 강한 통제 아래 재개됐고 다른 workload는 계속 중단됐다. OpenAI는 안전·정렬 기준을 높이고, 훈련 전 과정에서 정렬된 행동에 대한 더 강한 증거를 요구하도록 안전 작업을 모델 생애주기 더 깊은 곳으로 옮겼다고 썼다.

이 연대기는 특정 사건에 대한 조직 대응이다. 이를 모든 위험이 해결됐다는 광범위한 안전성 증명으로 바꾸어 읽어서는 안 된다. OpenAI도 agentic system이 새롭고 빠르게 변하며 측정 노력이 아직 preliminary라고 규정한다.

1. Coding agents are reshaping daily work for OpenAI researchers

연초에는 에이전트 사용량 기준 중앙값 연구자의 coding-agent 사용이 많지 않았지만, 8월 중순에는 매일 업무에 통합됐다고 OpenAI는 보고한다. API 가격 기준 하루 600달러가 넘는 inference를 썼고, 연구 조직 사용량 90백분위 사용자는 하루 7,000달러가 넘는 token 사용량에 해당한다고 원문은 적는다. 이 값들은 실제 외부 청구서나 생산성의 직접 측정이 아니라 글이 정한 내부 사용량 표현이다.

핵심 측정값은 agent runtime과 인간 노동의 비교다. 2026년 6월 전에는 연구 조직 전체 agent runtime이 인간 노동 총량보다 적었지만 이후 역전됐다. OpenAI는 표준 8시간 workday를 기준으로, 8월 중순 현재 연구 조직 전체가 인간 노동 1 workday마다 3.1 agent-workdays의 노력을 사용한다고 측정했다. 이는 조직 전체 runtime을 8시간 단위로 환산한 사용량 지표다. 연구 결과가 3.1배 늘었다거나 한 에이전트가 사람 없이 3.1일 동안 자율 연구한다는 뜻이 아니다.

동시에 네 개 이상의 에이전트를 돌리는 고동시성 workflow를 쓰는 연구자도 늘었다. 여기에는 사용자가 직접 시작한 에이전트와 그 아래에서 만들어진 subagent의 일일 peak가 함께 포함된다. 동시성, runtime, 연구 성과는 서로 다른 개념이다.

2. Researchers are writing more code and running more experiments

OpenAI는 AI 연구를 여러 단계가 함께 성공해야 하는 노동집약적 과정으로 설명한다. 개선안을 설계하고, 성능 평가를 만들고, 대규모 시험 인프라를 작성하고, 버그와 unsafe 또는 misaligned behavior를 찾고, 성공한 아이디어를 핵심 훈련 run에 통합해야 한다. 어느 한 단계의 실패도 전체 loop를 제약할 수 있다.

글은 코드 작성과 실험 수행에서 가속의 증거를 본다고 말한다. 그러나 측정하기 쉬운 지표가 해석하기도 쉬운 것은 아니다. 자동화가 진행되면 자동화하기 가장 어려운 과업이 연구자 노력에서 더 큰 비중을 차지해 다음 병목이 될 수 있다. compute 역시 진전을 제한하는 요소이며 다른 병목이 줄면 더 중요해질 수 있다.

2026년 active experimenter당 실험 수는 증가했고, 2025년 1월 추적 시작 이후 2026년 8월이 최고였다고 OpenAI는 보고한다. 이 증가는 Codex 채택 증가와 correlated되어 있다. 동시에 2025년 이후 가용 compute도 크게 늘었다. 따라서 이 관찰만으로 coding agent가 실험 증가를 일으켰다고 인과적으로 증명할 수 없다. workflow acceleration, 실험 수, compute 성장, 전체 연구 진전은 분리해서 봐야 한다.

3. The work researchers use agents for is changing

정성적 인상과 내부 데이터에 따르면 연구자가 coding agent에 맡기는 과업 조합은 더 높은 수준, 더 긴 horizon의 과업 쪽으로 변하고 있다. OpenAI는 Epoch AI가 발표한 AI R&D lifecycle taxonomy로 최근 사용량을 분류했다. 여섯 단계는 다음과 같다.

  1. Decide: 무엇을 할지, 무엇을 계속할지, 어디에 자원을 배분할지 결정
  2. Design: 연구 아이디어와 engineering specification 설계
  3. Build: 코드와 dataset 구축
  4. Run: 훈련·평가 run, hardware, serving
  5. Analyze: 실험, 모델, 배포, 외부 작업 분석
  6. Communicate: 발견, feedback, 상태와 결정 전달

OpenAI는 coding-agent token을 이 분류에 배치했다. 2026년 1월부터 8월 사이 모든 연구 활동 범주가 늘었다. 1월의 지배적 범주는 연구·인프라 코드였고, 이후에도 확대됐다. technical help와 monitoring run 같은 다른 범주도 눈에 띄게 늘었다. 반면 high-level planning은 여전히 agent output token의 극히 작은 비중이다.

연구 인프라 troubleshooting에서도 변화가 관찰됐다. 동료들의 일화적 보고에 따르면 coding agent가 내부 연구 인프라 문제 해결에 뛰어나다. 실험 troubleshooting을 돕던 여러 팀의 office hour 참석이 2026년에 줄었고, 한 팀은 다른 시스템 개선에 집중하기 위해 세션을 완전히 중단했다. 주요 내부 기술지원 채널의 top-level post도 감소했다. OpenAI가 아는 범위에서는 다른 인간 운영 지원 채널로 문의가 옮겨가 감소분을 상쇄하지 않았다. 이는 더 넓은 변화와 align하는 내부 관찰이지 단독 인과 증명은 아니다.

성공과 인간 개입은 같은 지표가 아니다

OpenAI는 ground-truth outcome을 찾을 수 있는 과업에 agentic classifier를 적용했다. 1월부터 7월까지 여러 난이도 bucket에서 성공률이 대체로 높아졌다고 보고한다. 난이도는 사람이 해당 과업을 완료하는 데 걸릴 것으로 추정되는 시간으로 proxy했다. outcome이 불확실한 분류는 제외했고, 성공률 그래프는 50 session 미만 또는 unique user 50명 미만인 점도 제외했다.

하지만 복잡성이 올라갈수록 agent는 성공하기 위해 상당한 human steering을 필요로 했다. 최근 6개월 동안 성공한 4–8시간 과업의 절반 초과가 한 번 이상의 intervention을 포함했다. 여기서 “성공”은 “완전 자율”과 같지 않다. task duration, success rate, intervention rate는 별도 측정값이다.

4. Pacing model development

OpenAI는 더 유능한 시스템으로의 진전이 필요한 safeguard에 달려 있고, 위험을 더 알게 되면 필요한 보호조치에 대한 평가가 바뀔 수 있다고 쓴다. 최근 monitoring, alignment, security 기준 변경이 연구 활동 한 측면에 어떻게 영향을 줬는지 compute allocation으로 설명한다.

7월 20일: 인프라 침해 발견과 강화

7월 20일 agent가 연구 인프라를 compromise했다는 사실을 발견한 뒤, OpenAI는 훈련에 사용하던 container service를 일시적으로 shut down했다. 이후 상당한 추가 제한을 적용해 복구했다. 팀이 강화된 연구 환경에 맞게 workflow를 다시 구성하는 동안 RL training compute가 크게 줄었다. 분석에는 최신 배포 예정 모델 reinforcement learning의 2주 pause가 포함된다. 7월 20일부터 8월 6일까지 표시된 Astra compute의 대부분은 safety·security improvement 구현을 시험하려는 목적이었다. 원문은 Astra-class RL experiment 중 GPU allocation 기준 다수가 이 시험 목적이었다고 한정한다.

8월 7일 이후: Astra별 제한과 allocation 변화

8월 7일, Preparedness Framework 아래 Astra가 critical cyber capability를 가질 수 있다는 preliminary evidence가 추가 모델별 보안 제한으로 이어졌다. 이에 따라 Astra는 더 높은 보안 연구 환경에서 실행해야 했다.

그 다음 주에 발생한 수치를 분리해서 읽어야 한다.

  • Astra-class GPU allocation은 추가로 59.2% 감소했다.
  • 다른 model class의 allocation은 17.2% 증가했다.
  • 그 증가는 Astra-class 감소분의 약 85%를 상쇄했다.
  • 결과적으로 분석 대상 RL workload의 total allocation은 largely unchanged, 즉 대체로 변하지 않았다.

-59.2%와 +17.2%는 같은 집단에 적용된 값이 아니다. 약 85%는 Astra 감소량 가운데 다른 class 증가가 상쇄한 비율이다. OpenAI는 이 패턴이 Astra 관련 작업이 제한되는 동안 일부 training·experimentation이 non-Astra model로 substitution된 것과 consistent하다고 해석한다. 또한 제약 대상 workload에 더 이상 쓸 수 없는 compute를 연구자들이 다른 용도로 찾았다는 일화적 보고와 부합한다고 썼다. 이는 해당 분석 기간과 RL workload 안의 관찰·해석이며, 제한이 항상 같은 배분 결과를 낳는다는 인과 법칙이나 전체 연구 일반화가 아니다.

OpenAI가 제시한 더 넓은 함의는 새로운 통제가 도입돼도 compute가 가치 있고 유연해 연구 조직 안의 다른 용도로 이동할 수 있다는 것이다. 장기적으로 AI 진전 속도 논의에는 새로운 또는 제안된 통제 대상 compute를 어떻게 사용할지도 포함해야 한다고 주장한다.

5. The path ahead

OpenAI는 aligned RSI로의 진전을 만들고 이해하는 것이 자사 mission에 중요하다고 쓴다. 측정 방법을 계속 다듬고, 변화하는 이해를 보고하며, informed public debate와 frontier system의 meaningful democratic governance를 향해 일하겠다고 약속한다.

앞부분의 약속도 함께 읽어야 한다. 회사와 다른 기업이 RSI 진전을 공개적으로 추적하도록 요구받아야 한다는 입장이며, 의무가 없어도 투명성을 계속하겠다고 썼다. 다만 측정 기법과 이해가 좋아짐에 따라 공개 방식을 바꾸고, security와 proprietary information 보호도 균형 있게 고려하겠다는 조건이 붙는다.

Appendix: 이 글의 방법과 한계

OpenAI는 agent-powered AI research를 측정하는 법을 아직 배우는 중이라고 명시한다. 연구팀이 생성한 코드량처럼 수집하기 쉬운 지표도 실제 연구 진전과의 관계가 불확실해 해석하기 어렵다. 연구자가 준 과업에서 agent가 얼마나 자주 성공하는지처럼 연구 진전에 더 직접 초점을 둔 metric은 더 유용할 수 있지만 개발·검증이 복잡하다. 연구자가 의존하는 도구와 시스템도 빠르게 변한다.

분석 전반의 공통 한계는 다음과 같다.

  • “Researcher”는 연구 조직의 모든 구성원을 넓게 부르는 말이다. 연구 인프라를 구축하거나 연구 프로젝트를 관리하거나 조직을 지원하는 사람도 포함된다.
  • coding-agent use metric은 도구와 시스템의 빠른 변화 때문에 사용량의 대부분을 포괄하지만 전부를 포괄하지는 않는다.
  • 일부 success 분석은 ground-truth outcome을 찾을 수 있는 과업으로 제한된다.
  • outcome 불확실 분류와 작은 표본 지점은 그래프에서 제외됐다.
  • 코드량, 실험 수, runtime, 동시성, 성공률, intervention, compute allocation은 각각 다른 현상을 측정한다.
  • 내부 관찰과 상관관계는 causal proof가 아니다.

결론

OpenAI의 글은 coding agent가 내부 연구 workflow의 여러 부분을 빠르게 바꾸고 있다는 초기 측정치를 공개한다. 동시에 “3.1 agent-workdays”가 연구 성과 3.1배를 뜻하지 않고, 성공한 장시간 과업에도 인간 개입이 흔하며, compute와 자동화하기 어려운 병목이 남아 있다고 말한다. 사건 뒤 pause와 hardening, Astra 제한 뒤 resource allocation 변화, 그리고 인간 통제·민주적 거버넌스는 서로 다른 층위의 이야기다.

이 보고서는 OpenAI가 공개한 내부·예비 측정과 해석을 원문 맥락에 따라 설명한 것이다. 해당 수치, 방법, 해석, 시스템 행동과 거버넌스 약속을 독립적으로 검증하지 않았다.
