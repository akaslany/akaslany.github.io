1. 개요 (Overview)

본 보고서는 OpenAI가 2026년 10월 19일에 발표한 "Advancing coding in low‑resource programming languages" 연구 보고서를 바탕으로 작성되었습니다. 본 소스는 COBOL, Fortran, Visual Basic과 같은 저자원 프로그래밍 언어(low-resource programming languages) 분야에서 인공지능 모델의 신규 코드 작성 및 기존 코드 마이그레이션 역량을 대폭 향상시킨 연구 결과와 평가 지표를 기술하고 있습니다.

COBOL, Fortran, Visual Basic 등의 저자원 언어는 Python이나 JavaScript와 비교했을 때 모델이 학습에 활용할 수 있는 공개 코드와 문서의 양이 절대적으로 부족합니다. 그러나 이들 언어는 전 세계 주요 기반 시설과 핵심 서비스를 가동하는 중추 역할을 담당하고 있습니다. COBOL은 온라인 은행 시스템의 40% 초과(>40%), 대면 신용카드 거래의 80%, ATM 거래의 95%를 지원하며, Fortran은 기상 예측 및 핵반응로 안전 분석 등에 광범위하게 사용됩니다.

이처럼 중요한 레거시 시스템을 유지보수하고 현대화하는 과정에서는 문서화의 미비, 원래 개발자의 퇴직 및 이탈, 그리고 핵심 비즈니스 규칙이 오직 코드 형태로만 존재한다는 현실적인 어려움이 수반됩니다. OpenAI는 이러한 저자원 언어 코딩 역량을 검증하기 위해 신규 데이터베이스 엔진 구축 과제인 MultiLangBench와 기존 COBOL 코드 마이그레이션 평가 체계를 구축하였습니다. 최신 모델(GPT-6 Astra, GPT-6 Luna, GPT-6.1 Sol 등)을 적용한 평가 결과, 기존 GPT-5.6 Sol 모델 대비 정합성과 정확도가 비약적으로 상승했으며 API 비용 또한 대폭 절감되었음이 입증되었습니다.

2. 주요 논점 (Main Discussion Points)

2.1 논점 1: MultiLangBench를 통한 신규 데이터베이스 엔진 구축 능력 검증

[논점] 저자원 언어 기반 학습 데이터와 문서의 부족 문제를 극복하고, AI 모델이 백지 상태(from scratch)에서 고도의 데이터베이스 엔진을 구축할 수 있는지 검증하기 위해 MultiLangBench 평가 환경이 구축되었습니다.

[근거 및 평가 방식] MultiLangBench는 모델이 20개의 서로 다른 프로그래밍 언어를 사용하여 SQLite와 호환되는 데이터베이스 엔진을 바닥부터 구축하도록 요구하는 과제입니다. 모델은 코드베이스 구조화, 상태 관리, 에러 처리, 기존 기능 유지 및 신규 기능 추가를 완수해야 합니다. 언어 간 구현 성과를 객관적으로 비교하기 위해 데이터베이스 파일 자체를 공통 인터페이스로 활용하며, 후보 프로그램이 초기 데이터베이스와 SQL 쿼리를 받아 변경된 데이터베이스를 생성하면 참조(reference) SQLite 구현체와 비교하여 바이트 단위 및 동작 정합성을 검증합니다. 특히 본 평가는 SQLite의 기존 테스트 수트를 재가공하여 장시간의 코딩 세션(extended coding session) 동안 모델이 실제 작동 가능한 기능을 얼마나 구축할 수 있는지를 측정합니다.

[모델별 성능 및 비용 비교] MultiLangBench 평가에서 최신 모델들은 이전 세대 모델인 GPT-5.6 Sol에 비해 통과율과 비용 효율성 측면에서 획기적인 개선을 이루었습니다.

모델명 평균 테스트 통과율 (%) 샘플당 추정 API 비용 (USD)
GPT-5.6 Sol 26.8% $3.48
GPT-6 Luna 40.3% $0.77
GPT-6 Astra 87.4% 소스 내 텍스트 미기재 (차트 시각화로만 제시)

(참고: GPT-6 Luna는 GPT-5.6 Sol 대비 약 78% 저렴한 비용으로 향상된 성능을 제공합니다.)

[언어별 성과 및 사례] GPT-6 Astra는 최대 추론 노력 조건에서 20개 언어 중 19개 언어에서 83% 이상의 테스트 통과율을 달성하였습니다. 저비용 옵션인 GPT-6 Luna 역시 모든 평가 언어에서 GPT-5.6 Sol 대비 향상된 결과를 보여주었습니다. 주요 언어별 통과율 변화 수치는 다음과 같습니다.

  • COBOL: GPT-5.6 Sol 10.9% → GPT-6 Luna 17.1% → GPT-6 Astra 72.1%
  • OCaml: GPT-5.6 Sol 25.6% → GPT-6 Luna 34.1% → GPT-6 Astra 85.8%
  • Fortran: GPT-5.6 Sol 21.4% → GPT-6 Luna 31.4% → GPT-6 Astra 83.5%
  • Visual Basic: GPT-5.6 Sol 27.5% → GPT-6 Luna 41.6% → GPT-6 Astra 89.4%

평가 대상 20개 언어 중 COBOL은 GPT-6 Astra 기준 72.1%를 기록하며 여전히 가장 난이도가 높은 언어로 확인되었습니다.

2.2 논점 2: COBOL 마이그레이션 평가를 통한 기존 코드의 동작 보존 능력 검증

[기술적 특성 및 배경] COBOL 프로그램을 C++, Java, Kotlin, Python, Rust 등 현대적 언어로 이관할 때 핵심 과제는 비즈니스 로직과 언어 특유의 세부 동작을 원형 그대로 보존하는 것입니다. COBOL 시스템은 금융 거래 및 비즈니스 기록을 다루므로 올림/반올림 규칙이나 미존재 레코드 처리 방식 등에 핵심 비즈니스 규칙이 반영되어 있습니다. 특히 COBOL의 고정소수점 연산(fixed-point arithmetic)은 명시적인 반올림 요청이 없으면 초과 소수점 자리를 버립니다. 이를 마이그레이션 과정에서 임의로 반올림하도록 변경하면 프로그램이 에러 없이 실행되더라도 실제 금융 계산 결과에서 차이가 발생하게 됩니다. 또한 원 개발자의 퇴직/이탈 및 코드 내에만 존재하는 비즈니스 규칙 등으로 인해 엄격한 로직 보존이 필수적입니다.

[정합성 평가 및 성과 수치] OpenAI는 관측 가능한 출력값에 대한 바이트 단위 일치(byte-for-byte parity on observable outputs)를 요구하는 비공개 테스트 수트를 바탕으로 정합성을 평가했습니다. 마이그레이션의 성공 판정은 모든 테스트를 통과해야만 인정되는 엄격한 기준을 적용했습니다.

  • 낮은 추론 노력 (Low Reasoning Effort): GPT-6.1 Sol 모델은 86.6%의 정확도를 기록하여, 동일 설정에서 5.4%에 불과했던 GPT-5.6 Sol 대비 비약적인 성장을 이루었습니다. 이때 발생한 API 비용은 기존 GPT-5.6 Sol 대비 39% 절감된 비용(기존 비용의 61% 수준)에 불과했습니다.
  • 높은 추론 노력 (Higher Reasoning Effort): GPT-6.1 Sol 모델은 97.9%의 정확도를 달성하여 평가 지표 상한선에 다다르는 포화 상태를 나타냈습니다.
2.3 논점 3: 엔터프라이즈 소프트웨어 현대화 및 오픈소스 공개

OpenAI는 MultiLangBench의 평가 환경과 테스트 수트를 GitHub에 오픈소스로 공개했습니다. 이를 통해 개발자와 엔터프라이즈 고객이 평가 항목을 직접 검증하고, 자사에서 사용하는 언어에 대한 모델의 성능을 확인하며, 실제 업무 적용 시 해결해야 할 격차를 파악할 수 있도록 지원합니다.

본 연구의 최종 목표는 단순한 코드 생성을 넘어 엔터프라이즈 환경에서 필요한 종합적인 소프트웨어 엔지니어링 역량을 AI 모델에 갖추는 것입니다. 생소한 코드 저장소에 대한 전반적 이해, 변경 계획 수립, 빌드 도구 활용, 테스트 실행, 디버깅 및 오류 수정 등 복잡한 실무 과제를 완수할 수 있도록 모델의 기능을 지속 확장하고 있습니다.

5. 한계와 불확실성 (Limitations & Uncertainties)

  • 운영 상의 한계: AI 모델이 COBOL 마이그레이션 평가에서 97.9%의 높은 정확도를 달성했더라도, AI가 생성한 코드를 실제 운영 시스템(production)에 적용할 때에는 전문가의 면밀한 코드 검토와 비즈니스 규칙 및 시스템 의존성에 대한 정밀 테스트가 필수적으로 요구됩니다.
  • 언어별 난이도 한계: MultiLangBench 평가에서 COBOL의 통과율이 10.9%에서 72.1%(GPT-6 Astra 기준)로 상승했으나, 여전히 평가 대상 20개 언어 중 가장 낮은 통과율을 보여 가장 난이도가 높은 언어로 남아 있습니다.
  • 소스 내 확인 불가 사항:
    • AI 모델의 세부 트레이닝 방법론 및 학습 데이터 구성 방식 (소스에 언급 없음)
    • 연구에 참여한 개별 연구원 및 작성자 실명 (소스에 언급 없음)
    • GPT-6 Astra 및 GPT-6.1 Sol의 세부 인프라 비용 구조 (소스에 언급 없음)
