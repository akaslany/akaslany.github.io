다중 에이전트 자가 감독을 통한 재귀적 자가 개선(MASS) 해설 보고서

1. 개요 (Overview)

프론티어 인공지능(AI) 시스템이 과학적 연구 및 정밀 프로그래밍 과제에서 성과를 내기 시작함에 따라, 모델의 능력을 지속적으로 확장하기 위한 핵심 방법론으로 재귀적 자가 개선(Recursive Self-Improvement, RSI)에 대한 연구가 활발히 진행되고 있습니다. 그러나 오픈엔드(Open-ended) 연구 과제와 같이 정답을 수식이나 단일 정답 코드로 검증하기 어려운 비검증성 과제(Non-verifiable tasks)에서는 자가 개선의 심각한 '감독 병목(Supervision Bottleneck)' 현상이 발생합니다. 모델의 출력물이 인간 전문가조차 신뢰성 있게 평가할 수 있는 수준을 넘어서거나 피드백 수집에 과도한 비용이 소요되는 경우, 모델 스스로(Optimizee)가 최선의 최적화자(Optimizer)이자 평가자(Evaluator)로 기능해야 하는 상황에 직면합니다 (§1 INTRODUCTION).

이와 같이 단일 언어 모델 인스턴스가 수행자, 최적화자, 평가자 역할을 모두 맡는 동종(Homogeneous) 루프 환경에서는 모델이 동일한 학습된 사전 지식(Learned prior)을 공유하게 됩니다. 이로 인해 자가 피드백 과정에서 스스로의 오류를 수정하기보다는 편향을 강화하는 문제가 발생합니다. 소스 문맥은 이러한 한계를 극복하기 위해 Minsky의 '마음의 사회(Society of Mind)' 개념에서 영감을 얻어, 동일한 언어 모델의 복제본 다수를 조직화하고 협업하게 함으로써 단일 인스턴스에서는 나타나지 않는 집단적 능력을 끌어내는 접근 방식을 제안합니다 (§1 INTRODUCTION).

본 보고서가 다루는 핵심 기술인 MASS(Multi-Agent Self-Supervision, 다중 에이전트 자가 감독)는 이와 같은 다중 에이전트 협업 구조를 자가 개선 프레임워크로 정립한 기술입니다. MASS는 크게 내부 루프(Inner loop)와 외부 루프(Outer loop)의 교대 구조로 작동합니다. 내부 루프에서는 모델이 최적화자 및 평가자 역할을 수행하며 텍스트 기반의 다중 에이전트 워크플로 프롬프트를 진화론적 탐색(Evolutionary search) 방식으로 최적화합니다. 외부 루프에서는 최적화된 워크플로하에서 생성된 실행 궤적(Trajectories)을 바탕으로 지도 미세조정(Supervised Fine-Tuning, SFT)을 수행하여 에이전트 조정(Orchestration) 및 실행 능력을 모델의 가중치로 내재화합니다 (§1 INTRODUCTION, §3 METHOD, Figure 1).

결과적으로 MASS는 모델이 한 번의 개선 주기(Cycle)를 거친 후 더 우수한 수행자이자 동시에 더 뛰어난 최적화자 및 평가자로 진화하도록 만듭니다. 이를 통해 모델은 외부의 고성능 감독 신호나 인간의 세밀한 워크플로 개입 없이도 재귀적 부트스트래핑(Recursive bootstrapping)을 연속적으로 달성할 수 있게 됩니다 (§1 INTRODUCTION, §3 METHOD).

2. 주요 논점 및 근거·사례 분석 (Key Arguments, Evidence, and Examples)

2.1. 동종(Homogeneous) RSI 루프의 한계와 MASS 메커니즘
  • [사실 (Fact)]
    • 동일한 언어 모델이 수행자($L_{agent}$), 평가자($L_{eval}$), 최적화자($L_{opt}$) 역할을 모두 수행하는 동종 루프에서는 생성, 평가, 수정 작업이 동일한 사전 지식을 공유하므로 자가 피드백이 오류를 교정하지 못하고 강화하는 편향이 발생함 (§1 INTRODUCTION).
    • MASS 프레임워크는 내부 루프의 워크플로 탐색과 외부 루프의 모델 미세조정으로 구성된 순환 알고리즘을 따름 (§3 METHOD, Algorithm 1, 2, 3).
  • [소스의 주장 (Source Claim)]
    • 단일 언어 모델 인스턴스에 의존하는 대신 다중 에이전트 토폴로지(Multi-agent topology)로 통신 구조를 재조직함으로써 자가 감독 신호의 질을 높이고 동종 루프의 편향 한계를 극복할 수 있음 (§1 INTRODUCTION).
  • [작성자 해석 (Interpretation)]
    • 단일 프롬프트 형태의 긴 추론 체인보다 다중 에이전트 간 역할 분담과 통신 구조 명시가 모델 내부의 잠재된 다각적 검증 능력을 이끌어내는 데 유효함을 의미함.
MASS의 작동 메커니즘 단계
  1. 내부 루프 (진화적 워크플로 최적화, Algorithm 2):
    • 수행 에이전트는 현재의 워크플로 프롬프트($w_t$)하에서 과제를 수행하여 결과물(Workspace $y_t$)을 생성함.
    • 자가 평가자($L_{eval}$)는 현재 결과물과 기존 최선 결과물($y^*t$)을 쌍대 비교(Pairwise comparison)하여 피드백($d{t,i}$)을 생성함.
    • 자가 최적화자($L_{opt}$)는 평가 피드백 이력을 바탕으로 에이전트 간 통신 구조(호출 순서 $h_t$, 출력 계약 $c_{t,j}$)를 중심으로 워크플로 프롬프트($w_{t}^{(i+1)}$)를 수정 및 제안함 (§3 METHOD).
  2. 외부 루프 (워크플로 내재화 및 SFT, Algorithm 3):
    • 최적화된 워크플로 $w^*_t$를 적용하여 다수의 실행 궤적(Rollouts)을 수집함.
    • 자가 평가자가 궤적들의 결과물을 브래들리-테리(Bradley-Terry) 모델 기반으로 점수화하여 상위 $K-1$개 궤적을 SFT 데이터셋($D_{train}$)으로 선정함.
    • 오케스트레이터 및 하위 에이전트 대화 궤적에서 워크플로 프롬프트를 제거(Bare prompt 변환)한 후 공유 모델 $L_\theta$를 지도 미세조정함 (§3 METHOD).
  3. 재귀적 반복:
    • 미세조정된 모델 $L^{(g+1)}$이 다음 세대의 수행자, 최적화자, 평가자 역할을 다시 맡아 알고리즘을 재귀적으로 수행함 (§3 METHOD, Algorithm 1).
2.2. [가설 1] 정보 흐름(Information Flow) 최적화를 통한 자가 감독
  • [사실 (Fact)]
    • 워크플로 최적화가 진행됨에 따라(iteration $i = 3 \rightarrow 11$), 에이전트의 역할(Role) 및 지침(Instruction) 텍스트의 과제 특화 정보량(Mutual Information $\hat{I}_i$)은 감소하는 반면, 계약(Contract) 및 홉(Hop, 호출 순서) 구조의 과제 특화 정보량은 증가했음 (Figure 4, Table 12, §4.3).
    • 워크플로 구성요소 간의 전체적 정보 중복도(Total Correlation $\hat{TC}$) 및 과제 중심 중복도($\hat{TC}(Z|T)$)는 최적화가 진행됨에 따라 전반적으로 감소했음 (Figure 5, Table 13, §4.3).
  • [소스의 주장 (Source Claim)]
    • 에이전트 개수를 무작정 늘리는 것보다 "무엇을, 누구에게, 언제 전달할 것인가"라는 통신 구도 및 정보 흐름을 최적화하는 것이 자가 감독 신호의 질을 결정짓는 핵심 요인임 (Claim 1, §1 INTRODUCTION, §4.3).
  • [작성자 해석 (Interpretation)]
    • 초기 워크플로는 모든 에이전트가 과제 전반의 중복된 지침을 보유하여 비효율적이었으나, 진화적 탐색을 거치며 각 에이전트가 수행할 정밀한 입력/출력 규격(Contract)과 명확한 단계별 전달 체계(Hop) 중심으로 특화되었음을 보여줌.
2.3. [가설 2] 다중 에이전트 궤적의 높은 학습 효율성
  • [사실 (Fact)]
    • 동일한 베이스 모델(Qwen3.6-27B) 및 동일한 SFT 환경에서 단일 에이전트 궤적 데이터셋($S, S+, S++$)과 다중 에이전트 궤적 데이터셋($M, M+$)을 비교 실험함 (§4.4, Table 8).
    • 지도 학습 데이터셋의 저장 규모(Stored Tokens, 1,722만 토큰)와 복원 추출 및 서브에이전트/오케스트레이터 $2:1$ 리샘플링 기반의 1,624 스텝 후 실제 손실 계산에 소모된 처리 규모(Processed Tokens, 2,882만 토큰) 간에는 차이가 존재함 (Appendix B.2, D.2).
    • 다중 에이전트 데이터셋으로 학습한 학생 모델 $M+$는 2,882만 개의 처리된 지도 학습 토큰으로 68.3%의 승률을 기록하여, 약 1.4배 더 많은 4,200만 개의 토큰을 소모한 단일 에이전트 모델 $S++$(승률 64.0%)보다 4.3%p 높은 성과를 달성함 (Figure 6, Table 8).

2.4. 모델 역할 전반의 동시 향상 및 협업 행위 내재화(Internalization)
  • [사실 (Fact)]
    • MASS 학습 과정에서는 과제 수행 궤적(Task-solving traces)으로만 지도 미세조정(SFT)을 진행했으나, 모델의 3가지 역할인 수행자($L_{agent}$), 워크플로 최적화자($L_{opt}$), 자가 평가자($L_{eval}$) 성능이 모두 동시에 향상됨 (§4.2, Figure 3).
    • 자가 평가자 정확도(외부 평가자와의 일치율)는 $L(0)$ 73% $\rightarrow$ $L(1)$ 91% $\rightarrow$ $L(2)$ 93%로 크게 상승함 (Figure 3c).
    • 추론 시 워크플로 프롬프트를 전혀 제공하지 않은 상태(Bare task prompt)에서도 모델은 하위 에이전트 위임(Delegation) 및 코드 파일 전달(Code handoff) 행위를 자발적으로 수행함 (Table 2a, §5.2).

2.5. 워크플로 탐색의 주요 병목 요인 분석
  • [사실 (Fact)]
    • 동종 루프에서 평가자($L_{eval}$)만을 GPT-5.5로 교체했을 때보다, 평가자와 최적화자($L_{opt}$) 모두를 GPT-5.5로 교체했을 때 유의미하게 더 빠르게 고성능 워크플로를 발견함 (§5.1, Figure 7a).
    • 모든 역할을 $L(0)$로 유지한 동종 루프도 탐색 횟수를 늘리면 12개 과제 중 11개에서 최종적으로 우수한 워크플로를 찾아냈음 (Figure 7a).
  • [소스의 주장 (Source Claim)]
    • 동종 RSI 루프에서 개선 속도를 저해하는 주된 병목 요인은 자가 평가자의 평가 능력이 아니라 자가 최적화자의 탐색 및 워크플로 제안 능력임 (§5.1).
  • [작성자 해석 (Interpretation)]
    • 약한 모델이라도 시간을 충분히 부여하면 우수한 워크플로에 도달할 수 있으나, 탐색 효율성과 개선 속도를 올리기 위해서는 최적화 제안 능력을 강화하는 것이 핵심 과제임.

5. 한계점 및 불확실성 (Limitations & Uncertainties)

본 연구 및 소스 문맥에서 명시된 한계점 및 불확실성 요인은 다음과 같음.

  • 수학적/수식적 성능 증명의 부재: Gödel machine과 같이 수식이나 정형 검증(Formal proof)에 기반하여 자가 개선을 수학적으로 보증하는 체계와 달리, MASS는 경험적(Empirical) 진화 탐색 및 지도 미세조정에 의존하므로 모든 주기에 대한 이론적 개선 보장이 제공되지 않음 (§6 RELATED WORKS, §7 CONCLUSION).
  • 텍스트 편집 크기와 실제 성능 변화 간의 낮은 상관관계: 워크플로 프롬프트의 텍스트 수정 크기(Edit size)와 실제 외부 평가 결과 변화 간의 스피어만 상관계수가 매우 낮게 나타남 ($|\rho_{edit}| \le 0.12$). 즉, 프롬프트 문장을 크게 수정하더라도 성능 향상으로 직결되지 않으며, 반대로 매우 미세한 편집만으로도 급격한 성능 저하(Regression)가 발생할 수 있음 (§5.1, Table 10).
  • 실행 가변성(Execution Variability): 워크플로 및 프롬프트 설정이 동일하더라도, 에이전트의 런타임 수용 능력이나 도구 호출 중단(Loop halt) 등에 의해 결과물이 크게 변동할 수 있는 불확실성이 존재함 (§5.3, Table 11).
  • 벤치마크 간 성과 불균형 및 과제 특성별 한계: 오픈엔드 연구 과제(MLR-Bench, ScienceAgentBench 등)에서는 명확한 점수/토큰 효율성 및 성과 향상을 보였으나, 단일 에이전트 중심의 국소적 코드 수정 및 터미널 과제(SWE-bench Verified, Terminal-Bench 2.0)에서는 성과 향상이 관찰되지 않거나 소폭 감소함. 이는 MASS가 다단계 오케스트레이션 및 계층적 위임 구조 최적화에는 탁월하지만, 단일 모듈에 국한된 정밀 수정 과제에서는 다중 에이전트 오버헤드로 작용할 수 있음을 나타냄 (Figure 2, Table 7, §5.2).
