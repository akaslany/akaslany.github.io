1. 보고서 개요 및 면책 고지

본 보고서는 2026년 9월 1일 시점의 공개된 조사 답변 및 기술 문서를 바탕으로 재구성된 2차 분석 결과입니다.

  • 정보의 시점성: 보고서에 포함된 API 제공 여부, 호출 한도, 신청 조건, 출시 상태 등의 모든 정보는 영구적 사실이 아닌 해당 기준일 당시의 **'시점상 주장(point-in-time claim)'**입니다.
  • 검증 한계: 답변 및 문서 내 포함된 외부 링크와 개별 증권사의 주장은 제작 과정에서 별도로 실사(Due Diligence) 검증을 거치지 않았습니다.
  • 활용 주의: 실제 시스템 구축 전 반드시 해당 증권사의 최신 공식 명세서와 이용 약관을 재확인하십시오.

2. 조사 결론 및 확인된 7개 서비스

공식 기술 포털 및 개발자 문서를 통해 REST 방식의 거래 기능(시세, 계좌, 주문) 제공이 확인된 서비스는 다음과 같습니다.

  1. 한국투자증권: KIS Developers
  2. DB증권: OPEN API
  3. LS증권: OPEN API
  4. 키움증권: REST API
  5. NH투자증권: Namuh PLUG
  6. 토스증권: Open API
  7. KB증권: Open API

주의 사항(Caveat): 본 목록은 한국 내 모든 금융기관을 포함하는 전수 조사 결과가 아닙니다. 검색 결과에 노출되지 않은 비공개 API, 기관 전용 FIX/DMA 채널, 특정 법인 간의 BaaS 제휴 API 등은 분석 대상에서 제외되었습니다.

3. REST 판정 기준 및 제외 범주

본 보고서에서 'REST API'로 분류한 4가지 핵심 기준은 다음과 같습니다.

  • 공식성: 증권사 공식 채널에서 고객 또는 승인된 법인에 제공함을 명시.
  • HTTPS 기반: 로컬 모듈 없이 표준 웹 프로토콜(HTTPS/JSON)로 통신 가능.
  • 핵심 거래 기능: 단순 종목정보를 넘어 시세, 계좌, 주문 중 핵심 거래 기능을 지원.
  • 문서 존재 여부: 공식적인 신청 절차와 기술 명세서(API Spec)가 존재.

제외된 범주:

  • Windows 종속 모듈: OCX/DLL/COM 방식(예: 키움 Open API+, 유안타 tRadar 등).
  • HTS 연동형: 독립적인 HTTP 서비스가 아닌 HTS 엔진에 종속된 시스템트레이딩(예: 신한 i indi 등).
  • 플러그인/특수 함수: 영업점 문의와 별도 모듈 적용이 필요한 구조(예: 미래에셋 AnyLink 등).
  • 기타: 기관용 전용선 기반 FIX/DMA 채널.

특정 증권사에 대해 "API가 없다"는 단정적 표현 대신, **"공식 공개 고객용 REST 거래 API 근거를 확인하지 못했다"**는 신중한 판단을 유지합니다.

4. 7개 증권사 종합 비교

각 서비스의 운영 조건과 핵심 특이사항을 정리한 데이터입니다.

  • 한국투자증권 (KIS Developers)
    • 상품: 주식, 채권, 선물옵션 등 광범위한 멀티에셋.
    • 특징: 공식 AI/LLM 도구 및 백테스터 제공. 실전과 모의 환경의 엄격한 분리.
  • DB증권 (OPEN API)
    • 상품: 국내외 주식·파생, 장내채권, 야간 파생시장.
    • 특징: 앱 전체 및 API별 이중 유량 관리. 액세스 토큰 발급 분당 1회 제한.
  • LS증권 (OPEN API)
    • 상품: 국내외 주식 및 선물옵션.
    • 특징: xingAPI 선신청 구조. 토큰이 발급 시간과 무관하게 익일 07시 만료.
  • 키움증권 (REST API)
    • 상품: 국내 및 미국 주식 집중.
    • 특징: 호출 한도가 가장 투명하게 공개됨. 3개월간 실서버 미접속 시 서비스 자동 해지 정책.
  • NH투자증권 (Namuh PLUG)
    • 상품: 주식, 파생, 채권, 금현물.
    • 특징: 2026년 8월 10일 출시. KRX/NXT/통합 피드별 개별 구독 지원.
  • 토스증권 (Open API)
    • 상품: 국내/미국 주식 통합 모델.
    • 특징: 2026년 8월 13일 출시. 단순화된 인터페이스를 지향하나 운영 데이터 부족.
  • KB증권 (Open API)
    • 상품: 국내외 주식 중심.
    • 특징: 2026년 8월 초 오픈베타 시작. 현대적인 웹 표준 문서 환경 제공.

5. 상품 범위 비교

  • 최상위 멀티에셋 (한국투자·DB·NH): 주식, 해외주식, 국내외 선물옵션, 장내채권 등 자산군 전반을 지원합니다. 특히 NH는 금현물 지원이 명시되어 있으며, DB는 국내 파생 야간시장까지 커버합니다.
  • 중간 범위 (LS): 국내외 주식/파생을 지원하며, 거래원 및 프로그램 매매 등 한국 시장 특화 데이터 항목이 매우 풍부한 것이 특징입니다.
  • 주식 특화 (키움·토스·KB): 주식 중심의 단순화된 인터페이스를 제공합니다. 키움은 조건검색 기능이 강력하여 퀀트 전략 수립에 유리하며, 토스와 KB는 초기 MVP 개발에 적합한 구조를 가집니다.

6. REST와 WebSocket/실시간 시세

실시간 시세 수신을 위한 WebSocket 지원 현황 및 한도 분석입니다.

  • 지원 확인: 한국투자, DB, NH, LS, 키움 (공식 SDK 및 문서 존재).
  • 부분 확인/미확인: 토스(실시간 시세 언급은 있으나 WebSocket 상세 명세 미비), KB증권(공유 조사에서 공개 원문의 WebSocket 엔드포인트를 확인하지 못해 고빈도·실시간 전략 적용 전 재확인 필요).
  • 실무적 제약: 키움증권은 공개 안내에서 실시간 200종목 한도가 제시되어 있습니다. NH투자증권은 시장별(KRX, NXT) 피드와 통합 피드를 구분한다고 문서화되어 있어 전략에 따른 확인이 필요합니다.

7. NXT·SOR·통합시세 대응

국내 주식 복수 시장(KRX, NXT) 환경에서의 기술적 차별점입니다.

  • 한국투자증권: 주문 파라미터에서 KRX, NXT, SOR(Smart Order Routing) 선택이 명시되어 있습니다.
  • DB증권: NXT 전용 주문 엔드포인트를 별도로 운영하여 시장별 직접 제어가 가능합니다.
  • 키움증권: KRX 시세와 통합시세 중 하나를 선택해야 하며, 두 피드를 동시에 수신하는 것은 불가능하므로 설계 단계에서 고정해야 합니다.

8. 호출 한도와 확장성

  • 키움증권 (상세 수치 공개):
    • 국내 주식 주문/조회: 초당 5회.
    • 미국 주식 주문: 초당 10회 (단, 09~10시 KST에는 초당 3회로 제한).
    • 미국 주식 전체 계열 합산 한도: 초당 50회.
    • 차트 조회 한도: 초당 20회.
  • DB증권: 공식 클라이언트에서 앱 전체 약 20 TPS와 API별 한도를 함께 고려하는 구조가 확인되며, 액세스 토큰 발급은 분당 1회로 안내됩니다. 실제 운영 수치는 공식 가이드의 해당 API별 기준을 최종 확인해야 합니다.
  • 기타사: KIS, LS, NH는 계층형 제한 방식을 사용하나 세부 수치는 신청 등급에 따라 변동될 수 있습니다. 토스/KB는 이번 공유 조사에서 공식 원문으로 확정할 수 있는 상세 호출 한도표를 찾지 못했습니다.

9. 인증·보안·네트워크 제약

  • 인증 및 토큰: 대부분 OAuth2 기반이나, LS증권은 토큰이 발급 시점과 무관하게 익일 07:00에 일괄 만료되므로 오전 7시 경계에서 선제 교체하도록 설계해야 합니다.
  • 네트워크 보안: 키움증권은 최대 10개의 허용 IP를 등록해야 하므로 클라우드 환경(Serverless 등) 이용 시 고정 IP(NAT Gateway 등) 확보가 전제되어야 합니다.
  • 식별 정보: NH투자증권은 MAC 주소 정보와 법인 IP 조건을 안내합니다.

10. 모의투자 및 테스트 환경

  • 제공 현황: 한국투자, DB, LS, 키움은 실전과 구분된 모의 투자 환경을 제공합니다.
  • 주의 사항: 모의 환경은 실거래와 체결 엔진이 다르므로 **슬리피지(Slippage) 및 시장 충격(Market Impact)**이 반영되지 않을 수 있습니다. 특히 휴장일 대응이나 실시간 스트림 단절 후 복구 시나리오는 반드시 실거래 PoC 단계에서 검증해야 합니다.

11. 문서·SDK·개발자 경험 (DX)

  • 전통적 구조 (LS, DB): 데이터 구조가 증권 도메인 고유의 TR(InBlock/OutBlock) 형태를 유지합니다. 웹 개발자에게는 초기 학습 비용이 높으나, 전문 트레이더에게는 데이터 매핑의 정밀함을 제공하는 장점이 있습니다.
  • 현대적 웹 구조 (키움, KB, 토스, NH): 상대적으로 현대적인 웹 문서와 개발 도구를 지향하며, 일부는 Postman Collection이나 인터랙티브 문서를 제공해 접근 경로가 명확합니다.
  • 생태계: 한국투자증권과 키움증권은 공식 AI·MCP 자료와 실행 가능한 코드가 구체적이며, DB증권과 NH투자증권도 관련 개발 지원이 확인됩니다.

12. 수수료·데이터 비용 및 상업적 이용

비용 구조는 5개 층(API 사용료, 매매 수수료, 거래세, 실시간 시세료, 인프라 비용)으로 관리되어야 합니다.

  • 상업적 이용 경고: 개인용 API 키만으로 다계좌 관리 SaaS, 데이터 재판매, 타인 주문 대행 등이 가능하다고 가정해서는 안 되며 별도 계약·라이선스·법률 검토가 필요할 수 있습니다. 시세 데이터의 제3자 표시·재배포는 증권사 제휴와 코스콤 등 별도 시세정보 계약이 필요할 수 있으므로 사업모델별 확인이 필요합니다.

13. 운영 성숙도 분석

  • 상대적으로 확립된 서비스: KIS, DB, LS는 폭넓은 API 범주와 누적 문서·공지가 확인되며, 키움 REST API는 2025년 공개 후 기능을 확장했습니다. 이는 공개 SLA가 아닌 서비스 연혁에 따른 정성 판단입니다.
  • 신생 서비스: **NH(8/10), 토스(8/13), KB(8월 초)**는 2026년 8월에 출시된 서비스입니다. 이들은 조사 기준일 당시 운영 이력과 커뮤니티 사례가 짧으므로 자체 PoC와 회귀시험을 거쳐 보수적으로 접근해야 합니다.

14. 증권사별 상세 개별 평가

[한국투자증권 KIS Developers]
  • 강점: 전 자산군 지원, SOR 선택권, 가장 앞선 AI/LLM 개발 생태계.
  • 약점: TR ID 기반의 복잡한 응답 구조로 인한 어댑터 개발 부담.
  • 적합 사용자: 멀티에셋 퀀트, 해외상품 확장 팀 및 공식 AI 도구를 활용하려는 개발자.
[DB증권 OPEN API]
  • 강점: 야간 파생 및 장내채권 지원, 상세한 실시간 스트림 범위.
  • 약점: 토큰 발급 빈도 제한(분당 1회)으로 인한 세션 관리 난이도.
  • 적합 사용자: 전문 파생상품 트레이더 및 채권 자동매매 시스템 구축자.
[NH투자증권 Namuh PLUG]
  • 강점: 금현물 포함 넓은 상품 폭, 통합 시세 피드 선택 기능.
  • 약점: 신규 서비스로 인한 커뮤니티 및 운영 사례 부족.
  • 적합 사용자: 멀티에셋과 NXT 통합시세가 필요하고 신생 서비스의 자체 PoC 역량이 있는 팀.
[키움증권 REST API]
  • 강점: 가장 투명한 호출 정책, 강력한 조건검색 연동, 3개월 미접속 관리 등 명확한 운영 규칙.
  • 약점: 주식 외 자산군 부재, 고정 IP 등록 수 제한(10개).
  • 적합 사용자: 국내·미국 주식 퀀트와 조건검색 기반 매매 개발자.
[토스/KB증권 Open API]
  • 강점: 표준 웹 기술(OAuth2, JSON) 준수 및 단순한 인터페이스.
  • 약점: 공유 조사에서 WebSocket 세부와 상세 호출 한도를 확정하지 못해 고빈도·실시간 전략 후보로 삼기 전 추가 확인이 필요함.
  • 적합 사용자: 저빈도 주식 조회 및 주문 위주의 초기 MVP 프로젝트.

15. 목적별 최종 추천

16. 권장 2주 PoC(개념 증명) 절차

정식 도입 전 반드시 다음 체크리스트를 통과해야 합니다.

  1. 인증: 토큰 만료 전 갱신 로직 및 세션 유지 안정성 확인.
  2. 주문 상태 머신: **"주문 타임아웃은 실패가 아니다"**라는 원칙하에 중복 주문 방지를 위한 상태 전이 검증.
  3. WebSocket: 단절 시 자동 재접속 및 기존 구독 종목의 재구독 안정성 측정.
  4. 호출 한도: 버스트 요청 시 HTTP 429 응답 및 Retry-After 헤더 준수 여부 측정.
  5. 대사: API 잔고와 실제 HTS/MTS 잔고 간의 데이터 일치성 확인.

17. 권장 시스템 구조

  • 핵심 컴포넌트:
    • 유량 제한기(Rate Limiter): 증권사별 TPS 준수.
    • 주문 상태 머신(Order State Machine): 타임아웃 발생 시 재주문 대신 상태 조회를 강제하여 중복 주문 방지.

18. 최종 상대평가 요약

  • 상품 폭 & 실시간 범위: KIS, DB, NH 우세.
