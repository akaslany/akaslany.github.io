1. 개요 (Overview)

본 분석 보고서는 SemiAnalysis의 팟캐스트 "Ep. 038"에서 다룬 중국 AI 기업 Z.ai의 오픈소스 프론티어 인공지능 모델 'GLM 5.3'의 반도체 아키텍처, 추론 인프라 효율성 및 사후 학습(Post-training) 파이프라인 분석을 심층 재구성한 것이다. GLM 5.3은 사전 학습(Pre-training) 아키텍처를 동결한 상태에서 오직 사후 학습 파이프라인의 고도화와 인프라 최적화만으로 에이전트 추론 능력 및 사이버 보안 역량을 첨단(Frontier) 수준으로 끌어올린 대표적 사례로 평가받는다.

아키텍처 관점에서 GLM 5.3은 DeepSeek V3.2에서 제안된 희소 주의집중(Sparse Attention) 메커니즘인 DSA(DeepSeek Sparse Attention)와 토큰 선택 알고리즘인 Lightning Indexer를 계승한다. 희소 주의집중 메커니즘은 전체 KV 캐시의 메모리 용량(Capacity) 자체를 물리적으로 줄이지는 못하지만, 연산에 필요한 메모리 대역폭(Bandwidth) 압박을 획기적으로 완화한다. Z.ai는 HBM(High Bandwidth Memory)의 용량 한계를 극복하기 위해 KV 캐시 데이터를 상대적으로 대역폭은 낮으나 용량이 풍부한 Host DRAM으로 오프로딩(Offloading)하는 HiCache 및 HiSparse 기술을 도입함으로써, 100만 토큰 이상의 초장문맥(Long-context) 환경에서도 높은 동시성(Concurrency)을 안정적으로 확보하였다.

하드웨어 추론 효율성 벤치마크(InferenceX) 분석에 따르면, 초기에는 NVIDIA B200 등 엔비디아 가속기 생태계가 우위를 점했으나 AMD 엔지니어링 팀의 지속적 소프트웨어 스택 최적화(ATOM 엔진)를 통해 AMD MI355(FP4)가 실제 서비스 상호작용성 기준인 초당 150 토큰 구간에서 NVIDIA B200과 동등한 토큰당 TCO 비용 효율(최대 1달러당 4,500만 토큰)을 달성했음이 확인되었다. 아울러 단일 배치(Batch size = 1) 환경에서 디코딩 지연을 극소화하기 위해 메가 커널(Mega kernel) 기술을 적용한 TileRT 추론 엔진은 최대 초당 470 토큰의 디코딩 속도를 기록했으나, 대규모 배치 처리가 불가능하다는 명확한 시스템적 트레이드오프를 보여준다.

사후 학습 파이프라인 측면에서 Z.ai는 동기식 GRPO(Group Relative Policy Optimization)에서 출발하여, 긴 시퀀스 환경의 보상 신호 희석 및 정책 시차(Policy staleness) 문제를 극복하기 위해 PPO 스타일의 Actor-Critic 동시 학습 구조인 SAO(Single Rollout Asynchronous Optimization) 알고리즘을 정립하였다. 나아가 자체 구축한 사후 학습 프레임워크 Slime과 모델 기반 인프라 자가 개선 루프(Self-improvement loop)를 통해 국산 GPU 커널 검증 및 시스템 자동화를 달성했다. 이를 바탕으로 화웨이 어센드(Huawei Ascend)를 포함한 중국 국산 7개 칩 플랫폼 풀스택 최적화 지원(GLM 5.3 Flash/Aux Alpha 사례)을 실증하였으며, Anthropic 평가 기준 'Fable' 클래스에 육박하는 사이버 보안 및 에이전트 추론 역량을 확보하였다.

3. 주요 논점 (Key Issues & Arguments)

3.1. 희소 주의집중(Sparse Attention) 메커니즘과 메모리 병목 (HBM vs DRAM)
  • 논점: 희소 주의집중(Sparse Attention) 메커니즘은 KV 캐시의 메모리 용량(Capacity) 한계를 직접 축소하지 못하며, 연산 시 요구되는 메모리 대역폭(Bandwidth) 효율성을 정교하게 개선하는 기술이다.
  • 근거 및 물리적 메모리 흐름:
    • 토큰 선택 알고리즘인 Lightning Indexer가 포워드 패스(Forward Pass) 동안 최적의 토큰을 동적으로 선택하기 위해서는, 전체 문맥(Context)에 대한 관련성을 수시로 평가해야 하므로 전체 컨텍스트 데이터가 시스템 메모리 상에 보존되어야 한다.
    • 따라서 전체 컨텍스트에 대한 메모리 점유 공간(Footprint) 자체는 줄어들지 않으며, 실질 연산에 인가되는 순간 토큰 데이터만 HBM(High Bandwidth Memory)으로 선택적 덤프/로딩(Dump/Load)되는 구조를 갖는다.
    • 결과적으로 100만 토큰 이상의 초장문맥 환경에서도 KV 캐시의 물리적 총 용량 요구량은 감소하지 않는다.
  • 사례 및 기술 솔루션 (HiCache & HiSparse 오프로딩):
    • HiCache (Prefix Cache Reuse) 및 HiSparse 오프로딩: HBM과 Host DRAM 간의 계층적 캐시 구조(Cache Hierarchy)를 형성한다. 전체 KV 캐시는 용량이 크고 단가가 저렴한 Host DRAM에 오프로딩하여 저장하고, 연산 실행 시점에 가장 관련성이 높은 KV 토큰 블록만을 고속 HBM으로 인프라 레이어에서 인스턴스화한다.
    • 동시성(Concurrency)과 메모리 점유의 관계: 서빙 인스턴스의 동시 사용자 수(Concurrency)가 증가할수록 HBM의 용량 압박이 극대화되므로 Host DRAM으로의 오프로딩 비율이 비례하여 증가한다. (NVIDIA B200 벤치마크 결과, 동시성 8과 16 설정 간 Host DRAM 점유율에서 현격한 격차가 발생함).
  • 사실(Fact) 및 주장/해석(Claim) 구별:
    • 확인된 사실(Fact): GLM 5 및 GLM 5.3은 DeepSeek V3.2에서 정립된 DSA(DeepSeek Sparse Attention)와 Lightning Indexer 기반의 Multi-head Latent Attention(MLA) 변형 구조를 채택했다.
    • 연구진의 주장/해석(Claim): 희소 주의집중이 메모리 용량 문제를 완벽히 해결한다는 통념은 용어상의 오해(Misnomer)이며, 하드웨어 메모리 계층(HBM-DRAM Hierarchy) 간의 대역폭과 용량 트레이드오프를 알고리즘 레이어에서 능동적으로 제어할 때 비로소 오프로딩의 효율이 완성된다.
3.2. 추론 성능 및 비용 분석 (InferenceX Benchmarks & TileRT)
  • 서비스 유즈케이스별 하드웨어/소프트웨어 트레이드오프 프레임워크:
[서비스 유즈케이스별 서빙 엔진 트레이드오프]

1. 고동시성 / 대량 타이핑 서빙 (ATOM Engine on AMD MI355)
   - 목표: 토큰당 서빙 TCO 극소화 & 높은 동시 사용자 수 처리
   - 특성: 초당 150 tokens/s 구간에서 NVIDIA B200과 동등한 $1당 4,500만 토큰 달성
   - 매커니즘: 소프트웨어 스택 반복 최적화(Iterative Optimization)를 통한 대역폭 효율 극대화

2. 극단적 저지연 에이전트 서빙 (TileRT Engine)
   - 목표: 단일 요청에 대한 극단적 응답 속도 (Memory-Bound Decoding 최적화)
   - 특성: 단일 배치(Batch Size = 1) 환경에서 최대 470 tokens/s 디코딩 실현
   - 매커니즘: 메가 커널(Mega Kernel)로 커널 호출 오버헤드 제거 (배치 확장 불가능 및 서빙 단가 상승)
  • 고동시성/대량 타이핑용 고효율 서빙 (AMD ATOM vs NVIDIA B200):
    • 모델 출시 초기(8월)에는 NVIDIA B200 생태계가 성능을 독점했으나, AMD 엔지니어링 팀이 자체 추론 엔진인 ATOM의 소프트웨어 스택에 대한 지속적 반복 최적화(Iterative Optimization)를 단행함.
    • 결과적으로 실제 대화형 서비스 환경의 핵심 지표인 초당 150 토큰(150 tokens/s) 출력 구간에서 AMD MI355(FP4)가 NVIDIA B200과 동등한 수준의 토큰당 TCO 비용 효율(피크 기준 1달러당 4,500만 토큰)을 확보함.
  • 극단적 저지연 에이전트용 특수 서빙 (TileRT 추론 엔진):
    • 메모리 바운드 디코딩(Memory-Bound Decoding) 한계를 극복하기 위해 메가 커널(Mega kernel) 기술을 적용, 커널 호출 오버헤드(Launch overhead)를 제거함.
    • 단일 배치(Batch size = 1) 조건에서 최대 초당 470 토큰(470 tokens/s)이라는 압도적 디코딩 속도를 기록함.
    • 그러나 배치 크기 확장이 불가능하여 단위 토큰당 서빙 비용이 매우 높게 형성되며, 극단적 저지연을 요구하는 전문 에이전트 작업(Jane Street 등 금융/코딩 에이전트)에 특화된 트레이드오프를 가짐.
  • 제반스 패러독스 (Jevons Paradox) 현상:
    • 추론 엔진 최적화로 토큰 서빙 비용이 감소함에 따라 시장 전체의 메모리 수요가 감소하는 것이 아니라, 동시성 요청 폭증, 문맥 길이 확장(100만 토큰 이상), 전체 처리 토큰 총량 증가로 연결되어 HBM 및 Host DRAM에 대한 전체 시스템 메모리 수요는 가파르게 증가함.
3.3. 사후 학습(Post-Training) 파이프라인 및 에이전트/사이버 보안 역량
  • 사후 학습 파이프라인 3단계 고도화:
    1. 1단계 (동기식 GRPO): 초기 학습 수렴의 안정성 확보를 위한 동기식 GRPO(Group Relative Policy Optimization) 적용.
    2. 2단계 (변형 강화학습 도입): 에이전트 작업 특성상 시퀀스가 장대해짐에 따라 RLVR(Reinforcement Learning with Verifiable Rewards)의 보상 신호가 희석되는 문제를 극복하기 위해, 시스템 오차 및 정책 시차(Policy Staleness)를 정교하게 허용하는 변형 RL 도입.
    3. 3단계 (SAO 적용): PPO 스타일의 학습 포맷으로 회귀하여 액터(Actor) 모델과 크리틱(Critic) 모델을 동시 학습시키는 Actor-Critic Co-training 기법인 SAO(Single Rollout Asynchronous Optimization) 알고리즘 정립.
  • Slime 프레임워크 및 자가 개선 인프라 루프 (Self-Improvement Loop):
    • Z.ai는 분산 사후 학습 프레임워크인 Slime을 오픈소스로 구축하여 분산 시스템 환경에서의 학습 효율을 극대화함.
    • 특히 "자사 AI 모델을 활용해 미지의 국산 하드웨어 GPU 커널을 자동 검증하고 시스템 모니터링 작업을 자동화하여 인프라 효율성을 스스로 극대화하는 자가 개선 루프(Self-improvement loop)"를 운용하여 시스템 엔지니어링 오버헤드를 획기적으로 낮춤.
  • 역량 변화 (Pre-training 동결 기준):
    • 사전 학습 weights를 동결한 상태에서 사후 학습만으로 벤치마크상 에이전트 추론 능력을 2% 이상 향상시킴.
    • 사이버 보안 역량이 급격히 상승하여 Anthropic의 레드팀 평가 기준 Fable 수준(Near-Fable level)의 프론티어급 공격/방어 역량 확보.
  • 데이터 및 인간의 개입 (Human Effort):
    • Z.ai는 학술 컨퍼런스 발표를 통해 사후 학습 데이터 구축 과정에 대규모 정제 작업과 데이터 라벨링 등의 인적 노력(Human effort)이 투입되었음을 밝혔으나, 세부 데이터셋 라벨링 방법론은 비공개함.
3.4. 중국 자체 하드웨어 생태계(Chinese GPU Ecosystem)와의 연계
  • 중국 국산 7개 칩 플랫폼 풀스택 최적화:
    • GLM 5 개발 시점부터 하위 커널 레이어부터 상위 추론 프레임워크까지 중국 국산 7개 메이저 가속기 플랫폼에 대한 풀스택 최적화를 완료함.
    • 지원 7개 플랫폼: 화웨이 어센드(Huawei Ascend), 무어 스레드(Moore Threads), 하이곤(Hygon), 캄브리콘(Cambricon), 쿤룬신(Kunlunxin), 메타엑스(MetaX), 엔플레임(Enflame).
  • GLM 5.3 Flash (Aux Alpha) 서빙 사례 및 하이브리드 아키텍처:
    • OpenRouter에서 스텔스 서비스 'Aux Alpha'로 공개된 GLM 5.3 Flash 모델은 완전히 중국 자체 국산 하드웨어만으로 서빙되었음이 실증됨.
    • GLM 5.3 Flash의 주의집중 메커니즘은 DeepSeek의 DSA(DeepSeek Sparse Attention)와 Kimi의 KDA(Kimi Delta Attention)를 접목한 하이브리드 아키텍처(일명 프랑켄슈타인 아키텍처)로 구성되어 고성능과 극단적 서빙 효율을 동시 달성함.
  • 연산 강도(Arithmetic Intensity)와 하드웨어 Co-design 해석:
    • GLM 5 및 5.X 시리즈의 연산 강도 계산값은 약 120 수준임.
    • NVIDIA B200/H200 등 최신 엔비디아 GPU가 요구하는 높은 Compute-to-Bandwidth 비율과 달리, 연산 강도 120 수준은 디코딩 단계에서 대역폭 제약이 상대적으로 높은 무어 스레드(Moore Threads) 등 중국 국산 GPU 사양의 Arithmetic Intensity 특성과 정밀하게 일치함.
    • 이는 단순한 소프트웨어 최적화를 넘어 비-엔비디아 하드웨어 제약을 고려한 하드웨어-소프트웨어 공동 설계(Co-design)의 기술적 근거로 해석됨.

4. 주요 수치 및 시점 정리 (Key Metrics & Timeline)

4.1. 연대기별 시점 정리 (Chronological Timeline)
  • 약 1년 전 (팟캐스트 녹음 기준): GLM 5 최초 논문 공개 및 중국 국산 7개 칩 플랫폼 풀스택 최적화 발표.
  • 6월: TR Taxes의 질의에 대한 Elon Musk의 답변("중국의 Mythos급 모델 상용화는 2025년 1분기 예상")과 Jie Tang(Z.ai CEO)의 반박("그렇게 오래 걸리지 않을 것") 트윗 타임라인 논쟁 발생.
  • 8월 초: GLM 5.3 정식 모델 공개 (사전 학습 동결, 사후 학습 기반).
  • 8월 20일: OpenRouter 상에 GLM 5.3 Flash 모델이 'Aux Alpha'라는 스텔스 명칭으로 등록되어 중국 국산 하드웨어 기반의 대규모 무료 서빙 진행.
  • 8월 말: GLM 5.3 Flash 모델 공식 발표 및 아키텍처(DSA+KDA) 공개.
  • 10월 초: SemiAnalysis 에피소드 038 녹음 및 분석 아티클 출판 (GLM 5.3 출시 후 약 2개월 경과 시점).
4.2. 주요 수치 데이터 (Key Metrics)
  • 타겟 상호작용 출력 속도: 사용자당 초당 150 토큰 (150 tokens/s) (100 tokens/s 구간 포함).
  • 피크 TCO 비용 효율: 1달러당 최대 4,500만 토큰 (45M tokens / $1 TCO) 처리 (NVIDIA B200 및 AMD MI355 FP4 기준).
  • TileRT 엔진 디코딩 속도: 단일 배치(Batch size = 1) 디코딩 시 최대 초당 470 토큰 (470 tokens/s).
  • 단일 세션 문맥 연산 지원: 100만 토큰 (1M tokens) 이상 연산 지원.
  • 중국 국산 최적화 지원 가속기 수: 7개 플랫폼 (Huawei Ascend, Moore Threads, Hygon, Cambricon, Kunlunxin, MetaX, Enflame).
  • 사후 학습 기반 에이전트 성능 향상 폭: 사전 학습 재가동 없이 벤치마크상 2% 이상 향상.
  • GLM 5 / 5.X 연산 강도(Arithmetic Intensity): 약 120 (디코딩 페이즈 기준).
  • NVIDIA Rubin Ultra GPU 메모리 De-spec 수치: GPU당 메모리 용량이 기존 계획인 1TB에서 192GB로 감소 (R200 수준으로 축소, 메모리 대역폭은 유지). 이는 반도체 설계에서 메모리 용량(Capacity)보다 대역폭(Bandwidth)을 우위에 두는 하드웨어 트렌드를 입증함.

5. 한계와 불확실성 (Limitations & Uncertainties)

  • Z.ai 사후 학습 투입 데이터 및 인력 규모의 비공개성: Z.ai 측은 사후 학습 시 막대한 규모의 인적 노력(Human effort) 및 정교한 데이터 라벨링을 투입했다고 언급했으나, 고성능 에이전트 및 사이버 보안 성능을 이끌어낸 구체적인 라벨링 기법, 데이터 파이프라인 구성, 투입 인력 수치는 완전히 비공개 상태임.
  • AMD TileRT 메가 커널 개발 및 학습 비용의 불확실성: AMD MI355 환경에서 극단적 저지연을 구현한 TileRT 메가 커널을 개발하고 합성/최적화하는 과정에서 투입된 정확한 토큰 수, R&D 기간, 실제 엔지니어링 비용 수치는 소스상에 밝혀지지 않음.
  • 중국 국산 칩 맞춤형 연산 강도(~120) 아키텍처 설계의 검증 부재: GLM 5/5.3의 연산 강도 수치(약 120)가 무어 스레드(Moore Threads) 등 중국 국산 GPU 사양에 완벽히 맞춤 설계되었다는 분석은 산술적 계산에 기초한 분석진의 유력한 가설(Conspiracy Theory)이며, Z.ai 공식 입장으로 검증되지는 않음.
  • 차기 모델(GLM 5.4, MiniMax 3.1 등)의 타임라인 및 아키텍처 확장성 미정: GLM 5.3 Flash에서 검증된 DSA와 KDA의 하이브리드 결합 구조가 차기 대형 모델(GLM 5.4 등)로 스케일업되어 적용될지 여부, 그리고 MiniMax 3.1 등 경쟁 모델과의 구체적인 출시 타임라인은 추측 영역으로 남아 있음.
