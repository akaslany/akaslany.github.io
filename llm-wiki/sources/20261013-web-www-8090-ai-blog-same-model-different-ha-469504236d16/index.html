[보고서] 동일 모델, 다른 하네스(Same Model, Different Harness) 실험 결과 분석

1. 개요 (Overview)

본 보고서는 인공지능 기반 코딩 에이전트(Coding Agent)의 성능 평가에 있어 핵심적 요소인 인공지능 모델과 '하네스(Harness)' 프로그램 간의 결합 효과를 다각도로 분석한 리서치 결과를 다룹니다. 기존의 소프트웨어 개발 벤치마크 리더보드는 대부분 인공지능 모델 단독의 성능을 측정하여 순위를 매기는 방식을 취해왔습니다. 그러나 실제 현장에서 작동하는 코딩 에이전트는 프롬프트 작성, 도구 제공, 파일 편집, 오작동 시 복구 결정 등을 담당하는 하네스 프로그램과 모델이 결합된 하나의 시스템 형태로만 동작합니다. 따라서 하네스를 배제한 채 모델만을 독립적으로 평가하는 기존 방식은 실제 개발 환경에서의 수행 능력을 정확하게 반영하지 못합니다.

이러한 한계를 검증하기 위해 8090 랩스(8090 Labs) 연구팀은 데이터커브(Datacurve)의 DeepSWE v1.1 벤치마크를 활용하여 7개 주요 인공지능 모델과 5개 주요 하네스 조합에 대한 종합적인 실험을 수행했습니다. 본 실험은 오픈소스 소프트웨어 프로젝트에서 추출한 총 113개의 실제 개발 과제(버그 수정 및 기능 구현)를 대상으로 진행되었으며, 동일한 모델과 추론(Reasoning) 설정을 유지한 상태에서 하네스 교체에 따른 성능 변화, 모델 개발사 자체 제작 하네스의 실제 효과, 결과의 반복 재현성, 그리고 실행당 비용 대비 성공당 비용(Cost per success)의 경제성을 정밀 측정했습니다.

실험 결과, 동일한 모델을 사용하더라도 구동되는 하네스 종류에 따라 작업 성공률이 최대 35포인트까지 변동하는 것으로 나타났습니다. 이는 테스트 대상 최상위 모델과 하위 모델 간의 최고 성공률 격차(16포인트)보다 단일 모델 내부에서 하네스 변경으로 인해 발생하는 성능 격차가 2배 이상 더 클 수 있음을 증명합니다. 본 보고서는 이러한 기술적 실증 데이터를 바탕으로 인공지능 에이전트를 도입하고 평가하려는 소프트웨어 리더십 및 연구진에게 실질적이고 전략적인 제언을 제공합니다.

2. 주요 논점 (Key Arguments & Evidence)

2.1. 하네스 교체에 따른 성능 변동폭 (최대 35포인트 격차)

동일한 인공지능 모델과 동일한 추론 설정을 고정한 상태에서 하네스 프로그램만 교체했을 때, 작업 성공률은 극단적인 변동폭을 보였습니다.

  • 주요 데이터 및 사례:
    • 지엘엠 5.3 플래시(GLM 5.3 Flash): 코덱스(Codex) 하네스 환경에서는 24%의 성공률에 그쳤으나, 딥시크(DeepSeek) 하네스 환경에서는 59%의 성공률을 기록하여 단일 모델 내 하네스 교체만으로 35포인트라는 가장 큰 성능 격차를 나타냈습니다.
    • 지피티-5.6 솔(GPT-5.6 Sol): 하네스 변경에 따른 성능 변화가 6포인트 수준(69%~75%)에 머물러 테스트 대상 중 가장 안정적인 하네스 독립성을 보여주었습니다.
    • 기타 모델 성능 격차: 클로드 페이블 5.1(Claude Fable 5.1)은 20포인트, 딥시크 V4 플래시 0731(DeepSeek V4 Flash 0731)은 17포인트, 지피티-5.6 루나(GPT-5.6 Luna)는 11포인트, 지피티-5.6 테라(GPT-5.6 Terra)는 9포인트, 그록 4.6(Grok 4.6)은 5포인트의 변동폭을 기록했습니다.
모델명 최저 성공률 하네스 및 비율 최고 성공률 하네스 및 비율 하네스 간 격차
지엘엠 5.3 플래시 코덱스 (24%) 딥시크 하네스 (59%) 35포인트
클로드 페이블 5.1 클로드 코드 (41%) 코덱스 (61%) 20포인트
딥시크 V4 플래시 0731 오픈코드 (21%) 코덱스 / 딥시크 (39%) 17포인트
지피티-5.6 루나 오픈코드 (53%) 파이 (64%) 11포인트
지피티-5.6 테라 오픈코드 (60%) 딥시크 하네스 (69%) 9포인트
지피티-5.6 솔 클로드 코드 / 오픈코드 (69%) 파이 (75%) 6포인트
그록 4.6 파이 (64%) 클로드 코드 (69%) 5포인트
  • 시사점: 실험에 참여한 가장 강력한 모델인 지피티-5.6 솔의 최고 성공률(75%)과 지엘엠 5.3 플래시의 최고 성공률(59%) 간 격차는 16포인트였습니다. 그러나 지엘엠 5.3 플래시 단일 모델 내에서 하네스 교체로 발생한 격차는 35포인트로 모델 간 격차의 두 배를 넘었습니다. 이는 모델의 구체적인 성능이 하네스와의 결합 방식에 의해 크게 좌우된다는 점을 명확히 보여줍니다.
2.2. 모델 개발사 자체 하네스와의 부합 여부

인공지능 모델 개발사가 직접 자체 제작한 하네스(오픈에이아이의 Codex, 앤트로픽의 Claude Code, 딥시크의 DeepSeek harness)가 해당 개발사의 모델과 결합되었을 때 반드시 최선의 성능을 내지는 않았습니다.

  • 주요 데이터 및 사례:
    • 클로드 페이블 5.1: 앤트로픽(Anthropic)이 자체 개발한 클로드 코드(Claude Code) 하네스 환경에서는 41%의 성공률에 그쳤으나, 타사 하네스인 오픈에이아이(OpenAI)의 코덱스(Codex) 하네스 환경에서는 61%의 성공률을 기록하여 20포인트 더 높은 성과를 냈습니다.
    • 도구 호출 및 실행 특성 차이: 클로드 페이블 5.1은 클로드 코드 하네스에서 실행 시 도구 호출(Tool calls) 횟수의 중앙값이 28회로 비교적 짧게 작업을 종료한 반면, 코덱스 하네스에서는 도구 호출 횟수 중앙값이 66회로 훨씬 더 깊이 있게 문제 해결을 시도하는 양상을 보였습니다.
    • 기타 모델군: 지피티-5.6 모델군(Sol 3포인트, Terra 3포인트, Luna 7포인트 격차) 및 딥시크 V4 플래시 0731(2포인트 격차)의 경우 자체 개발사 하네스 수치와 타사 최적 하네스 수치 간 격차가 노이즈 오차 범위(9포인트 이하) 내에 위치했습니다.
2.3. 반복 실행을 통한 재현성과 신뢰성 검증

단순 평균 성공률 지표는 identical한 과제를 반복 부여했을 때 모델이 일관성 있게 작업을 완수할 수 있는지를 나타내지 못합니다. 본 연구팀은 113개 과제에 대해 모델/하네스 조합별로 각 2회씩 독립 실행하여 결과를 '2회 모두 성공(Both)', '1회만 성공(One)', '모두 실패(Neither)'로 세분화했습니다.

  • 주요 데이터 (지엘엠 5.3 플래시 기준 5개 하네스별 재현성 수치):

    • 딥시크 하네스: 113개 과제 중 51개 과제 2회 모두 성공, 31개 과제 1회 성공, 31개 과제 모두 실패.
    • 파이 하네스: 113개 과제 중 50개 과제 2회 모두 성공, 32개 과제 1회 성공, 31개 과제 모두 실패.
    • 코덱스 하네스: 113개 과제 중 16개 과제 2회 모두 성공, 22개 과제 1회 성공, 75개 과제 모두 실패.
    • 클로드 코드 하네스: 113개 과제 중 14개 과제 2회 모두 성공, 31개 과제 1회 성공, 67개 과제 모두 실패.
    • 오픈코드 하네스: 113개 과제 중 16개 과제 2회 모두 성공, 25개 과제 1회 성공, 62개 과제 모두 실패.

  • 시사점: 최적의 하네스 선택은 단순히 일회성 성공 확률을 높이는 데 그치지 않고, 동일한 프로그래밍 과제를 지속적으로 완수해 내는 운영상의 재현성(Repeatability)과 신뢰성을 비약적으로 상승시킵니다.

2.4. 실행당 비용과 성공당 비용(Cost per Success)의 차이

단순 API 토큰 단가나 1회 실행당 소요 비용(Cost per run)이 저렴하다고 해서 실제 개발 과제를 완수하는 데 드는 비용이 저렴한 것은 아닙니다. 실패한 실행에서도 API 토큰 비용은 동일하게 청구되기 때문입니다.

  • 성공당 비용 산정 메커니즘: 각 모델 개발사의 공식 리스트 요금(Official list rates)을 기준으로 실행 시 기록된 토큰 수량을 곱하여 총 API 지출액을 산출한 후, 이를 최종 성공한 실행 횟수로 나누어 '성공당 비용(Cost per success)'을 도출했습니다.

  • 지엘엠 5.3 플래시(GLM 5.3 Flash) 하네스별 비용 정밀 비교:

하네스 종류 실행당 비용 (Cost per run) 작업 성공률 성공당 비용 (Cost per success)
코덱스 (Codex) $0.22 24% $0.93
파이 (Pi) $0.25 58% $0.43
딥시크 하네스 (DeepSeek) $0.37 59% $0.64
클로드 코드 (Claude Code) $0.58 26% $2.20
오픈코드 (OpenCode) $0.88 27% $3.28
  • 분석 결과: 지엘엠 5.3 플래시를 코덱스 하네스에서 구동할 경우 1회 실행 비용은 $0.22로 가장 저렴하지만, 저조한 성공률(24%)로 인해 실제로 성공적인 결과를 얻기 위해 지출되는 성공당 비용은 $0.93로 늘어납니다. 반면 파이(Pi) 하네스는 1회 실행 비용이 $0.25로 약간 더 비싸지만, 높은 성공률(58%)에 힘입어 성공당 비용이 $0.43로 절반 이하로 감소합니다. 실행 단가가 가장 저렴한 하네스가 실제 작업당 비용 관점에서는 2배 이상 비싼 결과를 초래할 수 있습니다.
2.5. 프로그래밍 언어별 최적 하네스의 변동성

대상 프로그래밍 언어(Go, Python, TypeScript)의 종류에 따라서도 모델과 하네스 조합의 성과가 상이하게 변동했습니다.

  • 주요 데이터 및 사례 (클로드 페이블 5.1 기준):
    • 오픈코드(OpenCode) 하네스 적용 시: Go 언어 과제에서는 최고 성과 하네스와 단 3포인트 차이(63% 성공률)로 뛰어난 성능을 보였으나, TypeScript 언어 과제에서는 최고 하네스 대비 성공률이 20포인트 하락(36% 성공률)했습니다.
    • 클로드 페이블 5.1의 하네스별 언어 성과 추이:
      • 코덱스 하네스: Go 65%, Python 56%, TypeScript 57%
      • 파이 하네스: Go 66%, Python 55%, TypeScript 56%
      • 딥시크 하네스: Go 51%, Python 49%, TypeScript 43%
      • 클로드 코드 하네스: Go 48%, Python 38%, TypeScript 38%
      • 오픈코드 하네스: Go 63%, Python 48%, TypeScript 36%
    • 언어별 과제 분포: 전체 113개 과제 중 Go, Python, TypeScript 3개 언어가 103개를 차지하며, 각 언어당 약 34개 과제가 배정되어 테스트되었습니다.
2.6. 에이전트 도입 기획 및 선택을 위한 핵심 제언

본 실험 데이터는 소프트웨어 에이전트 인프라를 구축하려는 조직에게 다음의 3가지 핵심 전략 방향을 제시합니다.

  1. 모델과 하네스의 일체형 평가(Test the model and harness together): 특정 하네스에서 낮은 성과를 보이는 모델이라도 다른 하네스와 결합 시 뛰어난 성과를 낼 수 있습니다. 벤치마크 평가 시 모델 단독이 아닌 하네스와의 결합 시스템 전체를 평가해야 합니다.
  2. 평균 성공률 뒤의 재현성 검증(Check pass repeatability): 프로덕션 환경에서는 단순 평균 성과보다 동일 과제에 대한 반복 성공률이 중요합니다. 에이전트 채택 시 다회 반복 실행을 통한 재현성 지표 확인이 필수적입니다.
  3. 성공당 비용 기준의 예산 수립(Price work by cost per success): 단순 토큰 단가나 1회 실행 비용에 기반한 예산 산정은 오판을 불러일으킵니다. 실패 비용이 반영된 성공당 비용을 바탕으로 실질적인 ROI를 계산해야 합니다.

5. 한계와 불확실성 (Limitations & Uncertainties)

  • 제외된 주요 모델: 오퍼스(Opus), 소넷(Sonnet), 아스트라(Astra), 키미 K3(Kimi K3) 등 시장에서 널리 쓰이는 일부 인기/상용 모델은 본 실험 평가 대상에서 제외되었습니다.
  • 샘플 크기의 한계: 과제당 2회 실행은 통계적으로 표본의 크기가 작으므로 제시된 재현성 수치는 절대적 지표가 아닌 상한선(Upper bound)으로 해석해야 합니다.
  • 특정 언어 데이터 부족: 러스트(Rust)와 자바스크립트(JavaScript)는 과제 수가 각각 5개에 불과하여 통계적 유의성이 부족하므로 언어별 독립 차트 생성에서 제외되었으며 전체 통계 수치에만 포함되었습니다.
  • 하네스 세부 메커니즘 데이터 미제공: 하네스 내부의 프롬프트 엔지니어링 구조, 컨텍스트 윈도우 관리 방식, 요약 알고리즘 등 세부적인 소프트웨어 구조적 차이에 따른 구체적 영향은 소스에서 다루지 않음/확인 불가.
  • 기타 외부 요인: 소스에서 다루지 않은 외부 환경 변수 및 기타 모델 성능 데이터는 소스에서 다루지 않음/확인 불가.
