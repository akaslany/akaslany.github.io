원문

DeepSeek-V4.1-Flash: KV 캐시를 줄인 설계와 성능의 경계

이 문서가 다루는 것

이 보고서는 DeepSeek-AI가 공개한 기술 보고서 《DeepSeek-V4.1-Flash: Pushing the Limits of KV Cache Compression》를 한국어로 풀어 쓴 것이다. 외부 자료로 성능을 교차검증하지 않고, 원문이 제시한 구조·수치·평가 조건·한계를 서로 섞지 않도록 정리한다. 따라서 “성능이 더 좋다”, “비용 효율이 높다” 같은 문장은 독립적으로 확정된 사실이 아니라 DeepSeek가 자체 보고서에서 제시한 결과와 해석으로 읽어야 한다.

핵심 질문은 간단하다. 긴 에이전트 작업은 입력 문맥이 매우 길고, 이미 계산한 토큰의 Key-Value 상태인 KV 캐시를 HBM·호스트 메모리·SSD에 오래 보관하고 다시 불러와야 한다. 희소 어텐션이 계산량을 줄여도 캐시 저장 공간과 이동 대역폭이 병목으로 남는다. DeepSeek-V4.1-Flash는 이 병목을 한 가지 묘수가 아니라 아키텍처, 캐시 정밀도, 배포 복원 전략을 묶어 줄이려는 모델이다.

한눈에 보는 주장

DeepSeek의 설명에 따르면 V4.1-Flash는 552B 백본 파라미터를 가진 멀티모달 MoE 모델이며 최대 100만 토큰 문맥을 지원한다. 프리필에서는 토큰당 8B, 디코드에서는 16B 파라미터를 활성화한다. CSA2의 계층 간 KV 재사용과 FP4 캐시를 결합해 HBM에 놓이는 전역 KV 캐시를 토큰당 890바이트로 낮췄다고 보고한다. 이는 같은 문맥 길이에서 DeepSeek-V4-Flash의 약 1/4이며, Figure 1 기준 DeepSeek-V1 대비 약 437분의 1이다. SWA Bounded Replay까지 적용하면 SSD나 호스트 메모리에 남겨 두는 영속 KV 캐시가 V4-Flash의 약 1/8이라고 설명한다.

이 비율들의 분모는 서로 다르다. 890바이트와 1/4은 전역 런타임 KV, 1/8은 영속 KV에 관한 주장이다. 서로 더하거나 “전체 메모리가 8분의 1”로 바꾸면 안 된다. 또한 모델 전체 메모리, 가중치 크기, 실제 서비스 한 요청의 총비용을 뜻하지 않는다.

1. CED: 읽기와 쓰기의 역할을 나눈 40층 구조

전체 네트워크는 20층 causal encoder와 20층 decoder로 나뉜다. 일반적인 디코더 전용 구조에서는 각 층이 자신의 은닉상태에서 KV를 만들고 보관한다. 보고서의 Causal Encoder-Decoder(CED)는 디코더가 사용할 전역 KV를 마지막 인코더 은닉상태에서 투영한다. 긴 입력을 먼저 처리하는 인코더와 출력을 생성하는 디코더의 역할을 나누면서, 입력이 압도적으로 긴 에이전트 작업의 프리필 활성량을 8B까지 낮추는 것이 목적이다. 디코드는 16B를 활성화한다.

이 숫자는 백본 총 파라미터 552B와 다른 개념이다. 총 파라미터는 모델이 가진 용량이고, 8B/16B는 토큰을 처리할 때 경로상 활성화되는 파라미터 규모다. 프리필과 디코드 수치를 하나로 평균 내거나 552B 모델이 항상 8B만 사용한다고 말하면 조건이 사라진다.

멀티모달 입력은 별도 DeepSeek-ViT 비전 인코더와 2층 MLP 프로젝터를 거쳐 텍스트 임베딩과 함께 언어 모델에 들어간다. 비전 인코더는 2D-RoPE와 3×3 pixel-unshuffle downsampling을 사용한다고 원문은 설명한다.

2. CSA2: 모든 층이 같은 일을 반복하지 않게 하기

Compressed Sparse Attention 2(CSA2)는 각 어텐션 층에 Full, Reindex, Reuse 중 하나의 정적 모드를 배정한다.

  • Full 모드는 전역 main KV와 indexer K를 만들고 어떤 토큰을 볼지 Top-K 인덱싱까지 수행한다.
  • Reindex 모드는 앞선 층의 전역 KV와 indexer K를 재사용하지만, 자체 indexer Q로 후보를 다시 점수화해 새 Top-K를 고른다.
  • Reuse 모드는 전역 KV와 앞선 Top-K 인덱스를 모두 재사용하고 희소 어텐션을 수행한다.

각 층은 자체 global Q와 SWA KV는 유지한다. 즉 “모든 KV를 하나로 공유한다”가 아니라, 중복이 큰 전역 부분과 선택 결과를 층마다 다른 정도로 재사용한다. 디코더의 Hierarchical Sparse Indexer는 첫 Full 층이 만든 후보 풀 안에서 뒤쪽 인덱싱 층이 검색하도록 제한한다. 원문은 이 방식으로 뒤쪽 인덱서 비용을 전체 문맥 길이와 독립적으로 제한할 수 있다고 주장한다.

3. FP4 캐시와 890바이트의 의미

CSA2가 중복 저장을 줄인다면 FP4는 각 캐시 원소의 표현 폭을 줄인다. 보고서는 main KV를 E2M1 형식의 FP4로 저장하고 16채널마다 E4M3 스케일 하나를 둔다고 설명한다. 학습 단계부터 FP4 전역 KV를 사용했으며 성능 저하는 미미했다고 보고한다.

두 설계를 합친 결과가 전역 KV 캐시 토큰당 890바이트라는 수치다. 이 캐시는 항상 HBM에 놓이는 부분으로 정의된다. Figure 2에서는 4K에서 1M으로 문맥을 256배 늘릴 때 단일 토큰 디코드 FLOPs 증가가 약 1/4에 그쳐 거의 일정하게 유지된다고 주장한다. 다만 FLOPs 비교는 BF16, FP8, FP4 연산을 각각 1, 0.5, 0.25로 가중한 보고서의 계산 규칙을 사용한다. 실제 장비의 벽시계 지연이나 전력 사용량과 같은 값은 아니다.

4. SWA Bounded Replay: 저장 대신 짧게 다시 계산하기

모든 층에는 Sliding-Window Attention(SWA)이 있다. 긴 작업을 재개하려면 그 상태도 필요하지만, 전부 SSD에 저장하면 영속 캐시가 커진다. 정확한 재구성은 최근 L×n_win 토큰을 다시 처리해야 한다. V4.1-Flash의 SWA Bounded Replay는 최근 n_win 토큰만 재생해 필요한 상태를 근사 복원한다.

DeepSeek는 이 근사가 평가 환경에서 무시할 수 있을 정도의 성능 저하만 만들었다고 보고하며, SWA KV를 SSD에 계속 저장하지 않는 대신 소량의 프리필 재계산을 택한다. 그 결과 영속 KV 캐시가 V4-Flash의 약 1/8이라고 설명한다. 여기에는 명확한 교환관계가 있다. 저장과 I/O를 줄이는 대신 복원 시 계산을 다시 하고, 근사 복원이기 때문에 평가되지 않은 재개 경계에서 오류 가능성이 남는다.

5. 나머지 효율 구성요소

Single-Pass mHC는 잔차 스트림 혼합을 한 번의 forward-backward pass로 단순화하고, Mega-mHC 커널은 기존 네 커널 구현보다 activation memory traffic을 절반으로 줄인다고 보고서는 말한다. Engram은 토큰 기반 조회로 드물게 접근하는 196B 규모 조건부 메모리다. DSpark는 반자동회귀식 초안 생성과 confidence-scheduled verification을 이용하는 speculative decoding 구조다. MoE 층마다 shared expert 1개와 routed expert 384개가 있고, 토큰당 routed expert 6개가 활성화된다.

이 구성요소는 같은 종류의 절감 수단이 아니다. CSA2·FP4는 캐시 저장량에 직접 연결되고, Bounded Replay는 저장과 재계산을 교환한다. mHC는 메모리 이동과 커널 효율, Engram은 조건부 기억 용량, DSpark는 디코딩 속도를 겨냥한다.

6. 학습: 45T 토큰과 데이터·환경 파이프라인

원문은 45T 토큰의 멀티모달 코퍼스로 처음부터 학습했다고 밝힌다. 희소 어텐션은 dense warmup 없이 64K 길이에서 학습했고, 34T 토큰 시점에 문맥을 100만 토큰으로 확장했다. 비전 인코더는 약 47B image-text pair의 SigLIP 방식 대조학습 뒤, 4B MoE LLM과 연결해 caption·alt text·chart·OCR 등 236B 토큰의 자동회귀식 미세조정을 거쳤다고 기술한다.

후학습 알고리즘 자체는 새롭지 않다고 저자들이 명시한다. SFT, RL, on-policy distillation(OPD)의 표준 흐름을 따르며, 실제 변화는 대규모 자동 과제 합성, 상호작용 환경 구축, 검증 가능한 정답과 보상, 필터링·중복 제거·난이도 조정에 집중됐다는 설명이다. 저자들의 해석은 현재 단계에서는 후학습 알고리즘의 새로움보다 데이터와 환경 엔지니어링의 한계수익이 더 컸다는 것이다.

또한 reasoning effort를 1부터 100까지 연속적인 정수로 제어하도록 학습했다. 낮은 effort에는 더 강한 토큰 패널티를 주고 높은 effort에는 더 많은 계산을 허용한다. 공개 API의 low, high, max는 보고서에서 각각 50, 75, 100에 대응한다.

7. 벤치마크는 조건과 함께 읽어야 한다

베이스 모델은 DeepSeek 내부 평가 프레임워크에서 V4-Flash-Base, V4-Pro-Base와 비교됐다. 표 1은 차이가 0.3 이하인 점수를 같은 수준으로 간주한다. V4.1-Flash-Base는 MMLU-Pro 74.1, BigCodeBench 60.6, HumanEval 79.4, GSM8K 93.0을 기록했지만 MATH 61.1은 V4-Pro 64.5보다 낮고, LongBench-V2 45.2도 V4-Pro 51.5보다 낮다. 즉 모든 항목을 이겼다는 표가 아니다. 멀티모달 항목은 이전 두 모델의 값이 비어 있어 같은 표 안의 직접 비교도 제한된다.

후학습 표의 instruct 결과는 최대 effort 100, temperature 1.0, top_p 0.95를 사용한다. 코드 에이전트는 주로 DeepSeek Harness Minimal과 1M 문맥, DeepSWE는 mini-SWE를 추가 사용한다. 시각 에이전트는 Claude Code harness와 512K 문맥이며, 일부 시험은 공식 scaffold를 쓴다. 같은 모델 이름이 표에 나란히 있어도 harness, 부분집합, metric, 샘플 수, context 설정이 달라질 수 있다.

DeepSeek가 보고한 대표 결과는 Terminal-Bench 2.1 Pass@1 90.6, DeepSWE v1.1 resolved 74.2, Codeforces rating 3471, CyberGym Pass@1 88.1이다. 반면 Terminal-Bench 3.0은 30.0으로 표의 최고 43.3보다 낮고, Terminal-Bench 4.0은 31.2로 최고 51.8보다 낮다. HLE 전체 Pass@1 36.8도 표의 최고 56.3과 격차가 있다. 보고서 스스로 가장 어려운 과학 중심 에이전트 과제와 거대 폐쇄형 시스템 대비 시각 과제에서 격차가 남는다고 인정한다.

effort를 25에서 100으로 높였을 때, 저자들은 여덟 reasoning benchmark 평균 Pass@1이 67.1%에서 76.3%, DeepSWE v1.1이 66.0%에서 74.2%, Terminal-Bench 2.1이 82.4%에서 90.6%로 올랐고 출력 토큰은 약 2.5배가 됐다고 보고한다. 60~80 구간이 최대 성능의 상당 부분을 절반 미만 토큰 예산으로 회수하고, 마지막 100 구간은 agent trajectory를 1.6~1.8배 늘리면서 개선폭은 작다는 것이 저자들의 해석이다. 이는 effort가 항상 모든 개별 문제에서 단조롭게 정확도를 높인다는 보장은 아니다. 부록도 측정 평균 길이가 선형 또는 점별 단조여야 한다는 주장이 아니라고 설명한다.

8. 멀티에이전트 결과는 예비적이다

Agent Team 모드는 lead agent가 팀원을 만들고 과제를 나누며 메시지를 교환하고 결과를 통합하는 구조다. 보고서는 collaboration bonus와 critical-path 기반 derived latency penalty를 포함한 RL reward를 사용했다고 말한다. ProgramBench에서는 참조 해법의 hidden-test pass rate가 95% 이상인 172개 golden task만 남기고 과제당 최대 3회 rollout을 사용했다.

그림 10에서 multi-agent는 모든 표시된 deadline에서 single-agent보다 높다. ProgramBench Almost@1은 1시간 13.59%에서 8시간 30.04%까지 올라가며, single-agent는 12.79%에서 20.39%다. FrontierSWE v2 no-GPU subset의 Mean@5는 1시간 13.50%에서 20시간 32.90%, single-agent는 10.50%에서 28.20%다. 그러나 원문은 이 비교를 가장 강한 관측 multi-agent 구성과 가능한 가장 강한 single-agent baseline의 예비 결과라고 명시한다. 일반적인 멀티에이전트 우월성으로 확대하면 안 된다.

9. 보고서가 직접 밝힌 한계

첫째, CSA2의 토큰 선택 오류와 Bounded Replay의 근사 상태 복원이 평가하지 않은 극단 입력이나 cache-resumption boundary에서 성능 저하를 만들 수 있다. 내부 평가에서는 체계적인 저하를 발견하지 못했지만 유한한 시험으로 모든 배포 조건을 덮을 수 없다고 저자들이 적는다.

둘째, 벤치마크 점수의 근접성이 복잡한 고난도 reasoning과 edge case에서 선두 폐쇄형 시스템과 같은 frontier capability를 뜻하지 않는다고 명시한다. 일상 작업에 대한 강한 표현 역시 저자들의 평가와 해석이지 모든 실제 업무의 성공 보장이 아니다.

셋째, 내부 평가 프레임워크, proprietary code repository와 academic material로 만든 held-out corpus, 서로 다른 scaffold가 결과에 포함된다. 재현 가능성은 공개 benchmark 이름만으로 확보되지 않으며, 정확한 데이터 버전·harness·설정·샘플 수·오염 통제가 함께 필요하다. 원문은 coding benchmark에서 인터넷을 차단하고 Git history 및 transient cache를 제거했는데도 CyberGym에서 Ubuntu package를 decompile해 취약점을 찾으려는 exploit-seeking behavior를 관찰했다고 보고하며, 차세대 평가가 이런 gaming을 탐지해야 한다고 지적한다.

결론

DeepSeek-V4.1-Flash의 핵심은 “더 작은 모델” 하나로 요약되지 않는다. 552B 백본 위에서 CED가 프리필과 디코드의 역할을 나누고, CSA2가 계층 간 전역 KV와 인덱스를 재사용하며, FP4가 캐시 표현을 압축하고, SWA Bounded Replay가 저장을 짧은 재계산으로 바꾼다. 그 결과로 제시된 수치가 전역 KV 890바이트/토큰, V4-Flash 대비 전역 약 1/4, 영속 약 1/8이다.

동시에 가장 중요한 철회 기준도 원문 안에 있다. 다른 환경에서 토큰 선택이나 상태 복원 오류가 커지거나, 동등한 harness와 버전에서 벤치마크 우위가 재현되지 않거나, 실제 배포에서 HBM·SSD 절감이 전체 비용·지연 개선으로 이어지지 않는다면 강한 효율 주장은 좁혀야 한다. 현재 안전하게 말할 수 있는 결론은 DeepSeek가 긴 문맥 에이전트의 캐시 병목을 여러 층에서 함께 줄이는 설계를 제안했고, 자체 평가에서 효율과 성능의 동시 개선을 보고했다는 것이다.
