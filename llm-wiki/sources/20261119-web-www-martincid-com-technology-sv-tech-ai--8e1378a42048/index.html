1. 개요 (Overview)

[사실] xAI(현재 SpaceX의 일부)의 대형 언어 모델인 Grok 4.8의 출시 일정이 지연되었습니다. 이번 지연의 근본 원인은 xAI가 기존 모델 학습 및 서빙에 사용하던 오픈소스 도구인 JAX와 SGLang을 전면 폐기하고, C/C++ 언어를 바탕으로 자체 강화학습(RL) 및 추론(Inference) 스택을 바닥부터 재작성했기 때문입니다.

[소스 주장/발언] xAI를 이끄는 일론 머스크(Elon Musk)는 Grok 4.8의 성능에 대해 "아직 놀라울 정도는 아니다(not yet incredible)"라고 솔직하게 평가하면서도, 시스템의 기반을 올바르게 구축했다는 점을 강조했습니다. 그는 경쟁사인 앤스로픽(Anthropic)의 Opus 5.5를 "걸작(masterpiece)"이라고 높게 평가하며 Grok 4.8이 이에 미치지 못함을 인정했으나, 새로 작성된 스택을 기반으로 약 2~3개월 후 출시될 Grok 5가 Opus 5.5를 능가할 것이라고 공언했습니다.

[사실] 본 보고서는 Martin Cid Magazine의 에이드리언 케슬러(Adrian Kessler) 기자가 작성한 분석 기사(2026년 11월 10일 자)를 바탕으로 정리되었습니다. 본문은 정보의 정확성과 객관성을 확보하기 위해 [사실], [소스 주장/발언], [작성자/기자 해석] 범주를 엄격히 구별하여 기술합니다.

2. 주요 논점 (Key Arguments & Deep Dive)

2.1. 오픈소스 프레임워크 폐기 및 인하우스 C/C++ 스택 전환
  • [사실] 폐기된 도구: xAI는 모델 사전 학습에 사용하던 파이썬(Python) 기반 수치 계산 라이브러리 JAX와 대형 언어 모델 서빙 프레임워크인 SGLang을 전면 폐기했습니다.
  • [사실] 신규 스택 및 아키텍처적 의미: xAI는 강화학습(RL) 및 추론 스택 전체를 C/C++ 언어로 직접 바닥부터 재작성했습니다.
  • [소스 주장/발언] 머스크의 언어 설명 및 성능 주장: 머스크는 새로 작성된 코드가 "약간의 C++이 포함되어 있지만 대부분 C 언어로 구성되어 있다"고 설명했습니다. 외부 고수준 추상화 라이브러리를 제거함으로써 엔비디아(Nvidia) GB300 칩 220,000개 클러스터 하드웨어에 소프트웨어를 1:1 직접 매핑(exact-maps)할 수 있게 되었으며, 이를 통해 대규모 학습 실행 시(for large training runs) 기존 JAX 대비 10배 이상(over an order of magnitude)의 속도 향상이 가능하다고 주장했습니다.
  • [소스 주장/발언] 기술적 배경 및 코드 작성 주체: 머스크에 따르면 해당 소프트웨어 스택은 SpaceX의 Starlink 엔지니어 팀이 작성한 시스템 유산에 기반합니다. Starlink 팀은 "자체 헤더를 작성하고 자체 시간을 계산하는" 개발 방식을 취합니다. 머스크는 사전 학습 코드가 Starlink 팀에 의해 직접 인공 작성(Not written by AI)되었으며, "고성능 소프트웨어 분야에서 AI는 아직 충분히 뛰어나지 못하다"는 이유를 제시했습니다.
2.2. 개발 일정 경과 및 지연의 구체적 원인
  • [사실] 단계별 추진 경과: Grok 4.8의 개발 및 지연 과정은 아래의 구체적인 순서에 따라 진행되었습니다.
    1. 사전 학습(Pre-training) 완료 및 지도 미세조정(SFT) 데이터 세트에 대한 대대적인 정제(Cleanup) 작업 수행.
    2. 사전 학습 코드는 신규 작성되었으나, 모델의 행동을 다듬는 RL 영역이 기존에 여러 서드파티 소프트웨어 시스템이 얽혀 있는 "레거시 더미(legacy pile)" 상태임을 확인.
    3. 모델의 행동을 학습시키는 RL 스택과 사용자 응답을 처리하는 추론 스택 전체를 C/C++로 바닥부터 전면 재작성 결정.
    4. 재작성 완료 후 RL 단계에 진입하여 평가 수치(evals) 상승 확인.
  • [사실] 지연 기간: 머스크가 6월 말에 "약 3개월 후 학습 및 추론 스택 전체 재작성을 통해 대부분의 소프트웨어 레이어를 삭제하고 대대적인 성과를 내겠다"고 발표했으나, 실제 완료는 예정보다 약 6주(6 weeks) 지연되었습니다.
2.3. Grok 4.8 및 Grok 4.7 성능 평가와 경쟁 모델 비교
  • [소스 주장/발언] Grok 4.7 평가: 머스크는 2026년 9월 21일 출시했던 기존 모델 Grok 4.7에 대해 "Grok 4.8은 4.7과 전혀 닮지 않을 것(다행히도)"이라며 내부 모델에 대해 비판적으로 평가했습니다.
  • [소스 주장/발언] Grok 4.8 성능 인정: 머스크는 Grok 4.8이 "아직 놀라운 수준은 아니다"라고 인정했습니다. 특히 앤스로픽(Anthropic)의 Opus 5.5와 비교하는 질문에 "Opus 5.5는 걸작(masterpiece)이며, Grok 4.8은 그 정도로 좋지는 않다"고 공개적으로 솔직한 평가를 내놓았습니다.
  • [소스 주장/발언] Grok 5 목표: 머스크는 이번 C/C++ 자체 스택 전환을 통해 올바른 기반을 구축했으므로, 약 2개월 또는 3개월 후 출시될 Grok 5가 Opus 5.5를 능가할 것이라고 공언했습니다.
2.4. 스택 자체 소유화의 이점과 위험 요소 (기자/작성자 해석 분석)
  • [작성자/기자 해석] 인하우스 스택의 이점: xAI가 JAX와 SGLang을 abandonment함으로써 타사의 소프트웨어 추상화 레이어나 외부의 출시 일정 의존성에서 완벽히 탈피했습니다. 22만 개의 엔비디아 GB300 칩셋이라는 특정 하드웨어에 소프트웨어를 직접 1:1 매핑하여 속도 최적화를 이룰 수 있습니다.
  • [작성자/기자 해석] 인하우스 스택의 위험 요소: 외부 커뮤니티가 사용하거나 검증하지 않은 독자적인 코드베이스를 사용하기 때문에, 학습 루프와 서빙 경로에서 발생하는 모든 소프트웨어 버그를 타사의 탓으로 돌릴 수 없으며 전적으로 xAI 내부 인력이 자체 책임져야 하는 리스크가 있습니다.
  • [작성자/기자 해석] 결론적 진단: 이번 소프트 롤아웃(Soft rollout)은 모델 자체의 성능 평가보다 C/C++ 파이프라인 전체(plumbing)를 시험하는 무대입니다. 실제 Grok Bot 트래픽을 모델이 성공적으로 견뎌낸다면 이번 재작성 스택은 Grok 5를 학습시키는 핵심 플랫폼이 되겠지만, 시스템이 흔들릴 경우 더 이상 탓할 상류 오픈소스 프레임워크(upstream framework)가 전혀 남지 않게 됩니다.

5. 한계와 불확실성 (Limitations and Uncertainties)

  • [사실] 공식 기술 문서 및 공시 부재: xAI의 공식 뉴스 페이지 및 개발자 문서에는 Grok 4.8 관련 항목이 등록되어 있지 않습니다. 모델 카드(Model Card), 벤치마크 평가 점수, 가격 정책, API 리스팅 정보가 일체 존재하지 않습니다.
  • [작성자/기자 해석] 외부 검증 부재: 2.5조 개에 달하는 파라미터 규모, 대규모 학습 시 10배 이상의 속도 향상, 그리고 RL 평가 수치 상승 주장은 전적으로 머스크 개인의 발표일 뿐 xAI 외부에서 객관적으로 검증된 바 없습니다.
  • [사실] 소프트 롤아웃 및 구동 방식 세부사항 미비: 기사 작성 주간에 Grok Bot 사용자들을 대상으로 진행된다는 소프트 롤아웃의 정확한 요일이나 시간표는 공개되지 않았습니다. 또한 머스크가 10월에 언급한 "초고속 버전의 Grok 4.8(a lightning-fast version of Grok 4.8)"이 구체적으로 어떤 구조로 구동되는지에 대한 기술적 정보가 부재합니다.
  • [작성자/기자 해석] 외부 프레임워크 상실에 따른 불안정성: 자체 C/C++ 스택 전환으로 외부 커뮤니티의 검증을 거친 코드가 없기 때문에, 소프트 롤아웃 과정에서 기술적 오류가 발생할 경우 책임이나 원인을 돌릴 외부 상류 프레임워크(Upstream framework)가 존재하지 않는 구조적 위험이 존재합니다.
  • [사실] 소스 미다룸 영역 (확인 불가): 소스 텍스트에는 xAI의 세부 재무 상태, SpaceX와의 지분 결합 구조, 재작성된 C/C++ 소스 코드의 상세 아키텍처 정보가 포함되어 있지 않아 해당 내용은 확인이 불가합니다.
