Gemini Decisions API 기술 해설 보고서

본 보고서는 제공된 소스 문서를 바탕으로 구글의 Gemini Decisions API 및 이를 구동하는 Gemini Decision 1 모델의 기술적 특성, 구조, 성과 및 생태계 적용 현황을 객관적으로 분석하여 정리한 기술 해설서입니다.

1. 개요 (Overview)

구글은 빠른 폐쇄형(closed-set) 확률적 의사결정을 지원하기 위해 Gemini Decision 1(gemini-decision-1) 모델 기반의 Gemini Decisions API를 공식 발표했습니다. 본 API는 구글 AI 스튜디오(Google AI Studio) 및 Gemini API를 통해 제공되며, 텍스트, 이미지, 오디오, 비디오, PDF 등 최대 256K 토큰 분량의 다중 모달(Multimodal) 입력을 바탕으로 도구 선택, 정책 점검, 모델 라우팅, 컨텍스트 채점 등의 제한된 선택(bounded choices) 문제를 신속하게 계산하도록 설계되었습니다. (소스 아티클 도입부 및 1~2문단 기준)

Gemini Decisions API의 핵심적 동작 원리는 기존의 생성형 LLM 방식처럼 텍스트를 토큰 단위로 순차 디코딩(token-by-token decoding)하지 않는다는 점에 있습니다. 단일 포워드 패스(single forward pass) 연산 메커니즘을 적용하여 주어진 후보 선택지들의 확률과 신뢰도 점수(0~1 사이 값)를 직접 산출합니다. 이를 통해 엔드투엔드(End-to-End) 지연 시간을 150~250ms 수준으로 대폭 단축했습니다.

소스 문서의 작성자 및 구글 측의 주장에 따르면, 이 API는 다중 모달 데이터 분석의 속도와 정확도를 보장하면서 연산 비용을 대폭 절감할 수 있는 최적화된 제어 평면(control plane) 솔루션입니다. 본 보고서에서는 발표된 사실 데이터와 소스의 기술적 주장을 명확히 구분하여 하위 세부 기술 항목을 작성하였습니다.

2. 주요 논점 (Key Points and Evidence)
2.1 논점 1: Gemini Decision 1 모델의 성능, 지연 시간 및 처리 메커니즘
  • 주장 및 논점: 토큰 단위 디코딩 과정 없이 단일 패스(single pass) 연산만으로 단일 요청당 최대 1,000개의 독립적인 예/아니오, 다중 선택, 루브릭 채점 질문을 고속으로 평가할 수 있습니다.
  • 근거:
    • 지연 시간: 모델 연산 시간(model compute)은 중앙값 기준 50~100ms이며, 엔드투엔드 지연 시간은 150~250ms를 유지합니다.
    • 컨텍스트 및 평탄 구간: 최대 256K 토큰의 입력 컨텍스트를 지원하며, 최대 16K 토큰 컨텍스트 범위 내에서는 1개부터 100개 질문까지 지연 시간이 거의 일정(flat latency)하게 유지됩니다.
  • 비교 서술:
    • 에이전트 라우팅, 추론, 랭킹, 다중 모달 이해를 포함하는 공통 벤치마크 제품군에서 가장 낮은 캘리브레이션 오차(calibration error)를 기록했습니다.
    • 동일한 벤치마크 테스트에서 Interactions API 기반의 Gemini 3.5 Flash-Lite 대비 약 5배 더 저렴한 비용 효율성을 제공합니다.
2.2 논점 2: 3가지 단일 패스 결정 유형 및 코드 구현 구조

Gemini Decisions API는 Gemini의 네이티브 다중 모달 아키텍처를 기반으로 구축되어, 단일 공유 입력(shared input)에 대해 3가지 형태의 결정 유형(noul, choice, score)을 단일 포워드 패스 내에서 자유롭게 조합하여 동시 평가할 수 있습니다. 개발자는 이미지 및 비디오 입력의 해상도를 직접 조절함으로써 시각적 세부 표현 수준과 토큰 비용 사이의 균형을 유연하게 제어할 수 있습니다.

  • 지원되는 3가지 결정 유형:

    • noul (Yes/No): 참/거짓 조건의 성립 확률을 추정하며, 선택적으로 참/거짓 세부 설명 기준(description criteria)을 포함할 수 있습니다.
    • choice (Multiple Choice): 2개부터 255개 사이의 선택지 중 최적의 항목을 선택하고, 모든 후보에 대해 정규화된 확률(normalized probabilities)을 반환합니다.
    • score (Ordered Rubric): 0부터 시작하는 순서형 루브릭에 따라 입력을 평가하여 단계별 확률 및 연속 가중 점수(continuous weighted score)를 산출합니다.

  • 코드 구현 구조 (Python 예시 기준): 소스 문서에 명시된 google-genai SDK 구현 코드 방식에 따라, 휴게실 카운터 사진(spill.jpg)과 텍스트 노트(Breakroom counter check...)를 하나의 입력 데이터 묶음으로 구성하여 3가지 질문 유형을 단일 요청 내에서 동시에 평가하는 구조는 다음과 같습니다.

    from google import genai

client = genai.Client(http_options={"api_version": "v1beta"})

result = client.decisions.create(
    model="gemini-decision-1",
    input=[
        {
            "type": "image",
            "uri": "https://storage.googleapis.com/generativeai-downloads/images/spill.jpg",
            "mime_type": "image/jpeg",
        },
        {
            "type": "text",
            "text": "Breakroom counter check before the 9 AM client meeting.",
        },
    ],
    questions={
        "has_spill": {
            "type": "noul",
            "instructions": "Is there an uncleaned liquid spill on the counter?",
        },
        "next_action": {
            "type": "choice",
            "instructions": "Which cleanup action fits the scene?",
            "criteria": {
                "wipe_with_cloth": "Small counter spill with a cloth or towel already nearby.",
                "dispatch_janitorial": "Large floor hazard, broken glass, or active leak.",
                "ready_for_meeting": "Counter is clean and ready.",
            },
        },
        "severity": {
            "type": "score",
            "instructions": "Rate the severity of the counter mess.",
            "criteria": [
                "Clean and ready.",
                "Minor localized spill.",
                "Major spill or safety hazard.",
            ],
        },
    },
)
2.3 논점 3: 구글 내부 팀 및 실제 프로덕션 적용 사례

구글 내부의 여러 프로덕션 팀은 Decisions API를 저지연 제어 평면(control plane)으로 도입하여 서비스를 개선하고 있습니다.

적용 서비스/팀 적용 목적 및 주요 효과
Gemini Notebook 실시간 동적 모델 라우팅 체계 구축. 쿼리 의도를 밀리초 단위로 분류하여 일상 쿼리의 지연 시간을 최대 40% 감소시키고 복잡한 작업에만 고성능 추론 모델을 할당
Stitch (Stitch Rapid) 신속한 캔버스 실험 기능 제공. 몇 초 만에 실행 가능한 와이어프레임을 생성하고 음성/터치 편집을 지연 없이 즉시 반영
CC (Google Labs) 200개 이상의 이모지 팔레트 항목 중 최적의 반응 이모지를 1초 미만(fraction of a second)에 선택하여 지연 없는 사용자 반응 제공
Google Search MCP(Model Context Protocol) 툴을 위해 적대적 평가(adversarial evals) 기준에 따라 적대적 동작 및 콘텐츠를 빠른 지연 시간 내에 감지하는 안전 레이어로 활용
2.4 논점 4: 가격 체계 및 생태계 연동
  • 가격 체계:
    • 입력 토큰: 100만 토큰(1M input tokens)당 $0.10
    • 출력 토큰: $0 (출력 토큰 청구 비용 없음)
    • 별도의 가변 사고 토큰(thinking token) 청구 없음.
    • 별도의 오디오 전사(audio transcription) 및 OCR 비용 없음.
    • 요청에 포함된 공유 입력(shared input) 페이로드는 평가하는 질문 수와 관계없이 요청당 1회(1x)만 청구되며, 질문이 추가될 경우 해당 질문의 지침(instructions) 및 기준(criteria)에 해당하는 토큰만 추가로 계산됩니다. 구글 AI 스튜디오 내 무료 티어(no-cost tier) 제공.
  • 데모 애플리케이션:
    • Doorstep Parcels
    • Speed Sketch
    • Find the Zoo Keeper
  • 생태계 및 개발 도구 연동:
    • google-genai SDK 지원.
    • 연동 개발 플랫폼/프레임워크: OpenRouter, LangChain, Vercel, LiteLLM, Pydantic AI, Pipecat, LiveKit, OpenCode.
    • 구글 클라우드 Gemini (Google Cloud Gemini) 지원 예정(coming soon).

5. 한계와 불확실성 (Limitations and Uncertainties)

소스 텍스트 내에 명시되지 않았거나 구체적 정보를 확인할 수 없는 한계 항목은 다음과 같습니다.

  • 구체적 벤치마크 수치 미기재: 에이전트 라우팅, 추론, 랭킹 및 다중 모달 벤치마크에서 우수한 성과 및 최저 캘리브레이션 오차를 보였다고 언급되었으나, 각 벤치마크의 세부적 수치 점수 데이터는 소스에 서술되어 있지 않음 (확인 불가).
  • Google Cloud 출시 일정의 불확실성: Google Cloud Gemini 연동에 대해 "coming soon"으로만 표기되어 있어 구체적인 출시 일자는 서술되어 있지 않음 (확인 불가).
  • 생성형 AI 요약 기능의 한계: 오디오 플레이어 상단 및 개요 요약문은 Google AI에 의해 자동 생성된 실험적(experimental) 기능임이 명시되어 있음.
  • 기타 미기재 사항: 훈련 데이터셋의 구체적인 크기, 모델의 구체적인 파라미터 개수 및 구조적 세부 사항 등 소스에서 명시적으로 언급하지 않은 정보는 본 보고서에 포함하지 않음 (내용 없음 / 확인 불가).
