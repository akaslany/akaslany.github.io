원문

Cadence AuraStack, 회로 설계는 어떻게 바뀌나 — 쉬운 풀이

한 문장 결론

회로 설계 AI의 핵심은 사람이 하던 모든 판단을 언어모델이 대신하는 것이 아니라, AI agent가 기존 설계·검증·물리해석 도구를 연결해 반복 작업을 수행하고, solver의 증거와 인간 승인으로 통제하는 것이다.

1. AuraStack은 무엇인가

Cadence AuraStack은 PCB와 첨단패키지 설계를 위한 agent형 플랫폼이다. 사용자가 자연어로 목표와 제약을 주면, 시스템은 Allegro AI Studio 안에서 다음 작업을 연결한다.

  • 시스템과 보드 구조 계획
  • 설계 제약 관리
  • 부품 배치와 배선
  • 기판·RDL·interposer 구현
  • 신호·전원 무결성 분석
  • 열과 기계응력 분석
  • 제조 가능성 점검
  • 실패한 결과를 반영한 재실행

여기서 중요한 점은 언어모델이 전기장이나 열을 머릿속으로 정확히 계산하는 것이 아니라는 사실이다. LLM은 작업을 나누고 도구를 선택하는 조정자에 가깝고, 실제 물리 판단은 Sigrity, Clarity, Celsius, MSC 계열과 같은 기존 solver가 맡는다.

쉽게 말하면 AuraStack은 모든 답을 혼자 아는 천재라기보다, 전문 프로그램과 엔지니어를 계속 호출하면서 프로젝트를 진척시키는 가상 수석 엔지니어에 가깝다.

2. 왜 지금 이런 방식이 필요한가

오늘날 고성능 시스템은 칩 하나만 잘 만든다고 끝나지 않는다. HBM, chiplet, interposer, 기판, PCB, 전력 공급, 냉각과 기계응력이 서로 영향을 준다. 뒤늦게 열이나 전원 문제가 발견되면 칩 범프, 패키지 배선, 보드와 냉각구조까지 다시 설계해야 할 수 있다.

그래서 설계 흐름은 다음과 같이 바뀌려 한다.

기존 방식:

칩 → 패키지 → PCB → 전기검증 → 열검증 → 제조검토 → 재설계

agent형 방식:

시스템 목표 ↔ 칩 ↔ 패키지 ↔ PCB ↔ 전력·냉각 ↔ 제조·수율

한 단계가 끝난 뒤 다음 단계로 넘기는 대신, 여러 solver와 설계 도구가 초기부터 반복해서 피드백을 주는 방식이다.

3. 화려한 숫자는 어떻게 읽어야 하나

Cadence는 최대 2배 빠른 출시, 15배 생산성, 최대 20배 멀티피직스 성능을 제시했다. TSMC 관계자는 특정 기판 자동배선 작업에서 100배 생산성을, FORVIA HELLA는 300개 부품 배치가 최대 4일에서 4분으로 줄었다고 설명했다. Reuters는 특정 5G 스마트폰 PCB 데모에서 28% 원가를 줄였다고 보도했다.

이 수치들은 agent형 EDA가 반복적이고 경계가 분명한 작업에서 큰 가치를 낼 수 있음을 보여준다. 그러나 다음과 같이 확대 해석하면 안 된다.

  • 15배 생산성이 인력과 전체 비용이 15분의 1이라는 뜻은 아니다.
  • 20배 멀티피직스가 전체 개발 기간이 20분의 1이라는 뜻은 아니다.
  • 4일에서 4분은 선택된 부품 배치 작업이지 전체 PCB 개발이 아니다.
  • 100배는 특정 substrate autorouting 워크플로이지 모든 패키지 설계가 아니다.
  • 28% 절감은 특정 BOM과 부품 대체 조건의 데모이지 평균 원가 절감률이 아니다.

현재 공개 근거에서 부족한 것은 여러 독립 고객의 전체 프로젝트를 같은 기준으로 비교한 자료다. 전체 리드타임, 인간 검토시간, 결함 유출, 재스핀, 제조수율, 총 계산·라이선스 비용과 고객 갱신률이 공개돼야 실제 경제성을 판단할 수 있다.

4. Cadence만의 독점적 방향인가

아니다. Cadence는 AuraStack을 세계 최초·유일이라고 표현하지만, 이 말은 회사가 정의한 제품 범위와 통합 수준에 따른 마케팅 주장이다.

Siemens는 2026년 3월 Fuse EDA AI Agent를 발표했다. 이 시스템도 반도체, 3D IC, PCB, 검증과 제조 사인오프에 걸쳐 여러 도구와 agent를 조정한다. MCP 연결, 제3자 도구, 자동 복구, 에어갭, 역할기반 권한, 감사로그와 인간 체크포인트를 강조한다.

Synopsys도 2026년 7월 장시간 실행되는 자율 검증과 열해석 흐름을 공개했다. 최대 50배 빠른 검증 RTL 도달과 추가 20% coverage를 주장하지만, 이 역시 회사 데모 수치이며 독립 검증 결과는 아니다.

따라서 경쟁의 본질은 어느 회사가 가장 말 잘하는 챗봇을 갖고 있는지가 아니다. 다음 능력이 더 중요하다.

  • 설계 의도와 제약을 정확히 구조화하는 능력
  • 여러 EDA·물리 도구를 안정적으로 호출하는 능력
  • 실패 후 상태를 보존하고 복구하는 능력
  • PDK와 제조 규칙에 접근하는 능력
  • 변경 이유와 검증 증거를 감사 가능한 형태로 남기는 능력
  • 고객의 IP와 설계 데이터를 안전하게 격리하는 능력

5. 연구는 무엇을 말하나

현재 arXiv:2607.17528v3은 PicoRV32를 상용 55nm 흐름에서 구현하면서 agent 구조를 비교했다. 이 연구의 중요한 결론은 domain skill 몇 개를 추가하는 것만으로 긴 RTL-to-GDS 작업을 안정적으로 끝낼 수 없다는 점이다.

실패의 큰 원인은 모델의 지식만이 아니었다. Tcl 명령이 도구 버전이나 실행모드에 맞지 않거나, 현재 어떤 설계 상태가 로드됐는지를 잃어버리는 낮은 수준의 인터페이스 문제가 중요했다. 비슷한 설계 진척을 낸 agent 사이에서도 현재 v3 초록 기준 Token ROI가 최대 141배 차이 났다.

공유 ChatGPT 답변에는 86.27%·105.92배라는 수치도 나온다. 86.27%는 v1 표의 97.94−11.67을 상대비율로 잘못 부른 것으로, 최신 v3는 이를 86.27점(points) 차이라고 교정했다. 105.92배는 v1의 동점 실행 ROI 12.71÷0.12에서 나온 값이지만, 현재 v3는 비교 구성이 바뀌어 최대 약 141배라고 보고한다. 이 영상에서는 버전이 확인되는 현재 v3의 86.27점과 최대 141배를 사용한다. 둘 다 PicoRV32·상용 55nm·선택 도구·구성당 1회 실행의 저자 실험이며 산업 전반의 보편 성능비나 경제적 투자수익률이 아니다.

연구가 주는 쉬운 교훈은 다음과 같다.

더 큰 LLM 하나보다, 구조화된 도구 인터페이스·지속적 설계 상태·실패 복구·과정 평가가 더 중요할 수 있다.

6. 어떤 업무부터 자동화될까

가장 먼저 변할 가능성이 큰 업무는 되돌리기 쉽고 자동 검증이 가능한 작업이다.

  • 요구사항과 제약 추출
  • 반복형 부품 배치와 배선
  • BOM 대안 탐색
  • 테스트·assertion 초안
  • 회귀시험 선택
  • 실패 로그 분류
  • 해석 모델 설정과 반복 실행
  • 기존 제품의 파생 설계와 migration

반대로 다음 업무는 더 오래 사람의 판단이 필요하다.

  • 모호한 요구사항의 우선순위 결정
  • 새로운 시스템 architecture
  • 신규 RF·analog topology
  • 물리 모델이 현실을 제대로 반영하는지 판단
  • 안전·항공·의료·자동차의 최종 승인
  • 제조수율과 field failure의 인과관계 해석
  • 책임과 예외 승인

회로 개발자의 역할은 모든 선과 스크립트를 직접 만드는 사람에서, 목표를 형식화하고 agent의 결과를 검증하며 위험을 승인하는 사람으로 이동할 가능성이 크다.

7. 2032년 시나리오는 사실이 아니라 가설이다

공유 답변은 2032년 운영모델을 다음처럼 배정했다.

  • 57%: solver 증거와 인간 승인을 갖춘 관리형 자율화
  • 20%: 보안·검증 장벽으로 제한적 보조도구에 머묾
  • 15%: 대기업 중심의 폐쇄형 풀스택 고자율 설계
  • 8%: 개방형·휴대형 agent 생태계가 주도

이 숫자는 조사기관의 통계나 관측 빈도가 아니다. 작성자가 제품 출시, 벤치마크, 인력 부족, PDK 접근, 보안과 인증을 종합해 붙인 조건부 확률이다. 따라서 2032년에 57% 확률로 반드시 이렇게 된다고 말할 수 없다.

가장 중요한 것은 확률 자체보다 확률을 바꿀 관측지표다.

관리형 자율화 전망이 강해지는 신호:

  • 여러 독립 고객에서 전체 개발기간 단축이 재현됨
  • 인간 검토시간까지 포함해 순절감이 확인됨
  • 결함 유출과 재스핀이 증가하지 않음
  • 설계 의도와 감사기록이 표준 기능이 됨
  • 온프레미스·에어갭과 모델 선택권이 보편화됨

전망을 낮춰야 하는 신호:

  • 중요한 AI 유발 설계오류나 IP 유출
  • 검토 부담이 절약시간을 상쇄
  • GPU·solver·사용량 과금이 과도함
  • PDK와 제조데이터를 연결하지 못함
  • 공급사 최고사례가 일반 프로젝트에서 재현되지 않음
  • 인증기관과 고객이 agent의 증거를 인정하지 않음

8. 한국 산업에 주는 의미

한국은 HBM, 메모리, 파운드리, 패키징, 기판·PCB와 완제품을 함께 보유한다. 기회는 범용 LLM 하나를 새로 만드는 데만 있지 않다. 더 중요한 자산은 다음과 같다.

  • HBM·logic·package·기판 사이의 검증된 제약 모델
  • SI·PI·열·응력 실패 사례
  • 실제 조립·검사·수율과 연결된 피드백
  • PDK·ADK·DFM 규칙의 기계판독 표현
  • 한국어 사양과 변경 요청을 설계 제약으로 바꾸는 내부 지식층
  • 서로 다른 공급사 도구를 안전하게 연결하는 orchestration

반대로 설계 의도, 실행 기록과 수율 데이터가 해외 EDA 공급사의 비공개 형식에 고착되면 파일 포맷보다 강한 새로운 종속이 생길 수 있다.

9. 기업이 지금 할 일

첫째, 되돌릴 수 있는 작업부터 작은 pilot을 시작한다. 둘째, 생성량이 아니라 승인된 결과를 측정한다. 셋째, 설계 의도와 변경 이유를 공급사 중립적인 데이터로 남긴다. 넷째, 생성 agent와 검증기를 분리한다. 다섯째, 계약에서 고객 데이터 학습 여부, 실행기록 export, 온프레미스·에어갭, 비용 상한, 책임과 삭제 조건을 확인한다.

필수 KPI는 다음과 같다.

  • 전체 리드타임
  • 결과의 1차 승인율
  • 인간 검토시간
  • 재작업과 rollback
  • escape defect와 respin
  • solver·GPU·token·license 총비용
  • 제조수율과 field failure

최종 판단

AuraStack은 회로 설계자가 곧 사라진다는 신호가 아니다. 더 정확히는 반복 실행과 직접 그리기에 있던 병목이 무엇을 만들지, 어떤 제약이 중요한지, 어떤 증거가 충분한지, 누가 책임질지로 이동한다는 신호다.

가까운 미래의 가장 현실적인 구조는 다음과 같다.

사람은 목적·책임·허용위험을 정한다. Agent는 설계·해석·검증 도구를 반복 실행한다. Solver와 형식검증기는 증거를 만든다. 고위험 결정은 사람이 승인한다. 제조와 수율 데이터는 다음 설계를 개선한다.

따라서 경쟁우위는 가장 유창한 모델보다 정확한 설계 의도, 풍부한 실패·수율 데이터, 강한 검증 폐루프와 안전한 실행 통제를 가진 조직에서 나올 가능성이 크다.
