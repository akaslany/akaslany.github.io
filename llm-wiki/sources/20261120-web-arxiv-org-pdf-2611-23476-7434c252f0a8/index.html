GUARD: Stabilizing Recursive Self-Improvement with Regret Guidance

논문 · 2026-11-20

요약

GUARD는 모델 가중치를 동결한 채 자가 검토와 회귀 검증으로 에이전트 하네스를 개선한다.

주제 색인 · 논문 · 2026년 11월 · 출처 · 보고서 영상

원문

GUARD 프레임워크 기반 자율 에이전트 하네스 재귀적 자기 개선(RSI) 기술 해설 보고서

1. 개요 (Overview)

[사실] 자율 인공지능 에이전트 시스템은 가중치가 동결된 백본 언어 모델(Frozen Base Model, 예: 제미나이 4)과 시스템 프롬프트, 재사용 가능한 스킬(SKILL.md), 메모리(MEMORY.md), 도구 인터페이스 스키마 및 제어 로직으로 구성된 수정 가능한 '하네스(Harness)'를 결합하여 구동됩니다. [소스 주장] 구글 클라우드(Google Cloud) 연구진은 에이전트 성능 향상의 상당 부분이 하네스 엔지니어링에서 기인하지만, 사람이 수동으로 하네스를 튜닝하는 방식은 확장성이 떨어지고 도구, 스키마, 사용자 워크플로 변경 시 쉽게 무력화된다고 지적합니다. 이에 따라 에이전트의 과거 실행 경험을 지속적인 텍스트 하네스 수정으로 전환하는 재귀적 자기 개선(Recursive Self-Improvement, RSI)이 핵심 대안으로 등장하였습니다.

[사실] 외부 평가자(Grader)나 정답(Ground-truth)이 제공되지 않는 환경에서 에이전트 하네스를 재귀적으로 지속 업데이트할 때, 기존의 자유 형식 반추(Reflection) 및 단일 스칼라 점수 방식은 3가지 핵심 실패 모드를 야기합니다. 첫째, 최근 실패를 해결하기 위해 작성된 광범위한 규칙이 기존에 성공하던 작업을 깨뜨리는 국소 오버피팅(Local Overfitting/Over-triggering), 둘째, 워크플로나 도메인이 전환될 때 이전 스킬을 덮어써 버리는 재앙적 망각(Catastrophic Forgetting), 셋째, 검증되지 않은 규칙이 누적되어 프롬프트를 비대하게 만드는 **메모리 오염(Memory Pollution)**입니다. [작성자 해석] 이러한 실패 모드는 기존 스칼라 평가 방식이 '최근 수정으로 인해 새롭게 깨진 동작(What an edit newly broke)'과 '여전히 미해결 상태인 기능 갭(What remains unsolved)'을 구별하지 못하고 단일 점수로 혼재시켜 피드백을 제공하기 때문에 발생합니다.

[소스 주장] 이러한 한계를 극복하기 위해 구글 클라우드 연구진은 GUARD(Grader-free UED with Adaptive Rule Distillation) 프레임워크를 제안합니다. GUARD는 비지도 환경 설계(UED)의 향수 및 후회(Regret) 개념과 집단 상대적 정책 최적화(GRPO)의 비평가 없는(Critic-free) 집단 점수 산정 방식을 텍스트 하네스 최적화에 이식한 폐루프 시스템입니다. [사실] GUARD는 작업을 실행하기 전 원자적 이분형 체크리스트를 도출하는 자가 검토 메커니즘, 이전 하네스 간의 이행도 차이를 추적하는 방향성 후회(Directional Regret) 분석, 비평가 없는 GRPO 기반 집단 상대적 후보 풀링, 그리고 유발된 후회보다 이득이 클 때만 수정을 승인하는 Soft-HURT 게이트로 구성됩니다.

[작성자 해석] GUARD 프레임워크는 백본 모델의 가중치를 직접 업데이트하지 않는 비파라미터적(Non-parametric) 정책 최적화 구조를 취함으로써, 흑색상자(Black-box) API 환경에서도 안전하고 검증 가능한 재귀적 자기 개선을 실현합니다. 적응(Adaptation) 단계에서는 동적 자가 검토와 풀링을 수행하지만, 배포(Test-time) 시에는 단일 동결 하네스($W_T$)만을 사용하여 $O(1)$ 컨텍스트 비용과 $pass@1$ 1회 실행을 달성함으로써 실무 토큰 절감과 안정성을 동시에 확보하는 구조적 기틀을 제공합니다.

2. 주요 논점 (Key Points & Detailed Arguments)

2.1. 논점 1: 실행 전 체크리스트 기반 자가 검토 및 비대칭 검증 (Reference-Free Self-Review)
  • [사실] 외부 정답이나 외부 평가자 없이 에이전트 스스로 복잡한 다중 턴 도구 워크플로의 수행 여부를 검증하기 위해, GUARD는 에이전트가 첫 번째 행동을 실행하기 전(Turn-0) 오직 작업 프롬프트와 도구 스키마만을 읽고 원자적 이분형 조건(Atomic Binary Predicates)으로 구성된 체크리스트 $C(q)$를 도출하여 캐싱합니다. [소스 근거: Section 4.1]
  • [소스 주장] 이는 생성 과정에서 $N$개의 제약조건을 동시에 유지해야 하는 에이전트의 생성 부담과 달리, 완료된 궤적(Trace)에서 단일 조건을 검증하는 평가가 구조적으로 훨씬 용이하다는 **생성-검증 비대칭성(Generation-Verification Asymmetry)**에 기초합니다. [소스 근거: Section 4.1]
  • [사실] 검증 체계는 샌드박스 상태 및 의미론적 추적을 분리하여 평가하는 2계층 구조로 구동되며, 궤적 $\tau$의 연속 점수 $S(\tau)$ 및 엄격 점수 $S_{strict}(\tau)$는 아래 수식에 따라 산출됩니다. [소스 근거: Section 4.1, Eq. 2]

$$S(\tau) = 100 \cdot \frac{1}{|C_{gr}(\tau)|} \sum_{c \in C_{gr}(\tau)} r(\tau, c)$$

$$S_{strict}(\tau) = \begin{cases} 0 & \text{(차단성 샌드박스 오류 발생 시)} \ 100 & \text{(모든 검증 항목 통과 시)} \ S(\tau)/2 & \text{(기타의 경우)} \end{cases}$$

  • [작성자 해석] 결정론적 샌드박스 오류를 1계층에서 먼저 즉시 차단하고, 2계층에서 의미론적 조건을 세부 감점 방식으로 평가하는 비대칭 체계는 환각으로 인한 생성 오버헤드를 줄이면서도 평가의 객관성을 극대화하는 안전장치로 작동합니다.
검증 계층 주요 검증 대상 수행 방식 불합격 처리 규칙
1계층 (Layer 1) 샌드박스 실행 상태, 도구 호출 오류, 인자 유효성, 상태 변경 상태 결정론적(Deterministic) 샌드박스 복사본 검사 차단성 오류 발생 시 $S_{strict}(\tau) = 0$ 즉시 부여
2계층 (Layer 2) 프롬프트 의미론적 제약, 서식, 안전 수칙 이행 여부 언어 모델 기반 궤적 및 최종 출력 평가 ($r(\tau, c) \in {0, 1}$) 불합격 항목 수에 비례하여 $S(\tau)$ 차등 감점
2.2. 논점 2: 방향성 후회 기반 분석 및 순위 지정 (Analyze Stage & Paired Regret Ranking)
  • [사실] 최근 두 임컴번트 하네스($W_{t-2}, W_{t-1}$)의 조건 이행도(Obedience) 차이를 통해 복구 후회 $\Delta_{hurt,t}(c) = \max(0, obey(c; W_{t-2}) - obey(c; W_{t-1}))$ 및 미해결 갭 $\Delta_{gap,t}(c) = 1 - obey(c; W_{t-1})$를 계산합니다. 최종 우선순위는 식 (4)와 같이 합산됩니다. [소스 근거: Section 4.2]

$$Priority_t(c) = \Delta_{hurt,t}(c) + \Delta_{gap,t}(c) \in [0, 2]$$

  • [작성자 해석] 이는 과거 성공 동작의 회복과 미해결 갭을 하나의 스칼라 점수로 혼재시키지 않고 분리함으로써, 수치적 환각이나 국소 오버피팅을 구조적으로 방지하는 핵심 메커니즘입니다.
  • [소스 주장] 진단 목록 분할에 따라 하네스 수정 지침이 명확히 구별됩니다: [소스 근거: Section 4.2]
    • Regressed ($\Delta_{hurt,t} > 0$): 최근 수정으로 인해 새롭게 깨진 동작입니다. 우선순위가 가장 높으며, 기존 규칙을 삭제하는 대신 반드시 [iff <trigger>] 조건절로 예외 범위를 제한(Scope-guarding)하도록 지시합니다.
    • Unsolved Gap ($\Delta_{hurt,t} = 0, \Delta_{gap,t} > 0$): 미해결 기능 갭입니다. 새로운 해결 메커니즘이나 스킬을 하네스에 추가하도록 지시합니다.
    • Mastered ($Priority_t = 0$): 검증된 규칙입니다. 규칙 핀 고정(Rule Pinning)을 통해 덮어쓰거나 훼손되지 않도록 방지합니다.
  • [사실] Theorem 2 (표적 수리 vs. 수동적 발견): 수동적 발견(Passive discovery) 방식이 미소 제약 조건 $J$개를 발견하는 데 $\mathbb{E}[T_{passive}] \ge \frac{H_J}{-\log(1-\epsilon)} \ge \frac{1-\epsilon}{\epsilon} H_J = \Omega\left(\frac{\log J}{\epsilon}\right)$의 시간 복잡도 벌금을 받는 반면, 조밀 체크리스트 평가 기반의 표적 수리(Targeted repair)는 기대 라운드 수 상한을 $\mathbb{E}[T_{target}] \le \frac{J}{\rho b_{min}} + 1 + \frac{H_{b_{min}}-1}{\rho}$로 제한하여 $1/\epsilon$ 의존성을 완전히 제거함을 이론적으로 증명합니다. [소스 근거: Section 4.5, Appendix A.2]
  • [사실] Proposition 1 (엄격한 회귀 우위성): 단일 실행 이분 평가($K_{gr}=1$) 환경에서 신규 회귀 조건(우선순위 2)은 어떠한 미회귀 조건(우선순위 최대 1)보다 항상 높은 우선순위를 가지며, $Priority_t(c) = 0$은 $obey(c; W_{t-1})=1$ 및 $\Delta_{hurt,t}(c)=0$일 때만 성립하여 마스터된 수칙을 정확히 핀 고정합니다. [소스 근거: Section 4.5, Appendix A.3]
2.3. 논점 3: 비평가 없는 집단 상대적 후보 풀링 및 대조적 진화 (Propose Stage)
  • [사실] 강화학습의 GRPO 메커니즘에서 영감을 받아, 백본 모델의 가중치 업데이트나 별도의 가치 비평가(Value Critic) 없이 동일한 작업 배치에서 $M \ge 2$개의 마크다운 하네스 후보군을 병렬로 평가합니다. [소스 근거: Section 4.3, Algorithm 1]
  • [사실] 후보 하네스 $\tilde{W}_t^{(m)}$의 적합도 $R_m$ 및 집단 표준화 적합도 $\hat{A}_m$은 다음 식 (8)로 산출됩니다: [소스 근거: Section 4.3, Appendix B]

$$Perf_m = \bar{S}_{strict}(\tilde{W}_t^{(m)}) + \frac{1}{4}\bar{S}(\tilde{W}_t^{(m)})$$

$$R_m = Perf_m - \beta |Q_m^-| + \gamma |Q_m^+| \quad (\text{단, } \beta = 3.5, \gamma = 1.5)$$

$$\hat{A}m = \frac{R_m - \mu_R}{\sigma_R} \quad \left(\mu_R = \frac{1}{M}\sum{m=1}^M R_m, \quad \sigma_R = \sqrt{\frac{1}{M}\sum_{m=1}^M (R_m - \mu_R)^2 + 10^{-6}}\right)$$

  • [소스 주장] 최고 적합도 후보($m^+ = \arg\max_m R_m$)와 최하위 후보($m^- = \arg\min_{m \ne m^+} R_m$)의 실무 궤적을 대조 분석(ContrastEvolve)합니다. 대조 판정 시 대비 문턱값 $\delta_{con} = 10$점을 적용하며, 작업 식별자(Task ID)를 <TASK_ID>로 마스킹하여 전략 프롬프트 집합 $P_{t+1,g} = {s_{t+1}^+}{\lfloor M/2 \rfloor} \cup {s{t+1}^-}_{M-\lfloor M/2 \rfloor}$를 진화시킵니다. [소스 근거: Section 4.3, Eq. 9-10]
  • [작성자 해석] 동일 배치 내 상호 적합도 표준화($\hat{A}_m$)를 통해 별도의 비평가 네트워크 없이도 후보 간 상대적 우위를 정확히 식별함으로써, 게이트 거부율을 64% 감소시키고 효율적인 프롬프트 진화를 달성합니다.
2.4. 논점 4: Soft-HURT 승인 게이트 및 거부 대장 (Gate Stage & Rejection Ledger)
  • [사실] 승인 게이트는 후보 하네스 $\tilde{W}_t$의 순 이득이 유발된 후회 패널티 $Hurt(\tilde{W}t, W{t-1})$를 초과할 때만 승인하며, 수식 조건은 식 (11)-(13)과 같습니다. [소스 근거: Section 4.4]

$$Hurt(\tilde{W}t, W{t-1}) = \frac{1}{|Q_g|} \sum_{q \in Q^-(\tilde{W}t, W{t-1})} \left( S_q(W_{t-1}) - S_q(\tilde{W}_t) \right)$$

$$\bar{S}(\tilde{W}t) - \bar{S}(W{t-1}) > \max \left( Hurt(\tilde{W}t, W{t-1}), \mu_{min} \cdot \mathbb{I}[|Q^-| > 0] \right)$$

  • [사실] 파라미터는 단일 작업 노이즈 바닥값 $\delta_{noise} = 15$점, 후회 허용 예산 $h_{max} = 1$작업, 트레이드오프 마진 $\mu_{min} = 1.5$점(전문 수트 3.0점)으로 설정됩니다. [소스 근거: Section 4.4, Appendix B]
  • [소스 주장] 승인 조건 미달 시 $1 \le |Q^-| \le h_{rep}$ 범위의 소수 하락 작업에 대해 라운드 내 1회 [iff <condition>] 조건부 수리를 시도합니다. 최종 거부된 후보는 거부 사유와 수칙 문구를 중복 제거하여 거부 대장($L_g$, 읽기 창 $L_{max} \in {12, 40}$)에 기록함으로써 차기 라운드의 중복 실패를 방지합니다. [소스 근거: Section 4.4]
  • [사실] Theorem 1 (비하락 게이팅 및 수렴성): Soft-HURT 게이트 하에서 게이트 점수는 단조 비감소($\sum_{t=1}^T \Delta_t \ge 0$)하며, 유발된 후회는 항상 성과 이득에 의해 보상되고($\sum_{q \in Q_t^-} (S_q(W_{t-1}) - S_q(W_t)) < |Q_g| \Delta_t$), sub-Gaussian 환경에서 최소 $1-\alpha$의 확률로 획득 점수가 수렴함을 보장합니다. [소스 근거: Section 4.5, Appendix A.1]

5. 한계와 불확실성 (Limitations & Uncertainties)

  • [사실] 자가 검토 체크리스트 파싱 한계: 턴-0 자가 검토 구동 시 언어 모델의 평결(Verdict) 결과가 파싱 불가능하거나 오류가 발생할 경우, 자가 검토 시스템은 해당 검증 항목을 불합격으로 처리하거나 결정론적 샌드박스 추적 검증(Deterministic Sandbox Trace Checks)으로 강제 대체되는 한계를 갖습니다. [소스 근거: Section 4.1]
  • [사실] 비파라미터적(Non-parametric) 개선의 본질적 한계: GUARD 프레임워크는 백본 언어 모델의 가중치(Weight)를 직접 수정하지 않고 텍스트 형태의 하네스(프롬프트, 스킬, 규칙, 메모리)만을 진화시킵니다. 따라서 백본 모델 자체가 근본적으로 지니고 있는 절대적 추론 능력이나 지식 한계를 넘어서는 가중치 학습은 불가능합니다. [소스 근거: Section 1, 2]
  • [작성자 해석] 본 프레임워크는 하네스 오버피팅과 재앙적 망각을 해결하지만, 백본 모델의 근본적인 추론 오류까지 교정할 수는 없으므로 모델 자체의 발전과 하네스 최적화가 병행되어야 합니다.
  • [사실] 소스 미언급 / 불확실 영역: 인간과의 실시간 상호작용 피드백 환경에서의 연속 RSI 적용 여부, 동적 환경에서의 대규모 분산 에이전트 간 하네스 동기화 메커니즘 등 소스 텍스트에서 구체적으로 다루지 않거나 실험하지 않은 항목은 "소스 미언급 / 확인 불가"로 기재합니다.
