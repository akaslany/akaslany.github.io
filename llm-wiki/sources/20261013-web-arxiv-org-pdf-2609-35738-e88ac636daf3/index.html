1. 개요

하네스 러닝(Harness Learning)은 거대언어모델(LLM) 기반 에이전트의 파라미터를 직접 업데이트하지 않고, 모델 호출, 도구 활용, 정보 흐름을 제어하는 실행 가능 파이썬(Python) 프로그램인 '하네스(Harness)'를 실행 피드백을 통해 동적으로 수정함으로써 새로운 태스크에 적응시키는 기술이다. 기존 언어모델 에이전트는 다양한 문제 구조에 맞춰 오케스트레이션 로직을 변경해야 하는 한계가 있었다. 하네스 러닝은 하네스 코드 수정을 경사하강법 기반 적응에서의 가중치 업데이트 역할로 재정의하여 프로그램 공간 상의 메타 러닝(Meta-Learning) 프레임워크로 정형화한다.

이 아키텍처의 핵심 구성요소는 고정된 솔버(Solver) 모델, 수정 가능한 실행 프로그램인 하네스(Harness), 그리고 하네스 코드를 재작성하는 제안자(Proposer) 모델이다. 솔버는 기본 언어 모델로서 문제 해결에 필요한 추론과 출력을 담당하며 학습 및 추론 과정 전체에서 파라미터가 고정(Frozen)된다. 하네스는 솔버 모델의 호출 시점, 컨텍스트 구성, 외부 도구 실행 및 루프 구조를 정의하는 실행 코드이다. 제안자 모델은 주어진 태스크 설명, 현재 하네스 코드, 실행 피드백 보고서를 입력받아 하네스의 구조화된 코드 수정안(Search/Replace 편집)을 생성한다. [SOURCE_IMAGE_1] 및 [SOURCE_IMAGE_2]에 기술적으로 시각화된 바와 같이, 제안자 모델이 실행 피드백을 바탕으로 하네스를 수정하는 동안 솔버 모델은 완전히 고정된 상태를 유지한다.

본 연구의 핵심 목표는 학습 과정에서 경험하지 못한 보지 못한(Unseen/Out-of-domain) 태스크에 대해 추론 단계(Test-time)에서 파라미터 업데이트 없이 실행 피드백만으로 일반화 가능한 적응 성능을 확보하는 것이다. 추론(Reasoning Gym) 및 다단계 질의응답(Multi-hop QA) 데이터셋 실험 결과, 하네스 러닝으로 학습된 4B 제안자 모델은 단일 단계 수정만으로 35B 교사(Teacher) 모델의 평균 성능을 뛰어넘었으며, 여러 라운드에 걸친 연속적인 피드백 기반 수정을 통해 보지 못한 태스크에서도 지속적인 성능 향상을 달성함을 검증하였다.

2. 주요 논점

논점 1: 하네스 러닝의 개념과 메타 러닝(Meta-Learning) 프레임워크
개념 정의 및 작동 기전

하네스(Harness)는 언어모델 에이전트 환경에서 모델 호출 생성, 외부 도구 인터페이스 실행, 실행 결과의 피드백 처리, 오케스트레이션 루프 제어를 담당하는 실행 가능한 파이썬 프로그램이다. 제안자(Proposer) 모델은 이전 하네스 코드($h_{t-1}$)와 개발 질문 세트($Q_{fb}$)에서 수집된 실행 결과 보고서를 검토한 후 구조화된 서치 및 리플레이스(SEARCH/REPLACE) 방식을 통해 하네스 코드를 직접 수정하는 프로그램 편집($y_t$)을 수행한다. [SOURCE_IMAGE_1]과 [SOURCE_IMAGE_2]는 이러한 하네스 수정 및 피드백 순환 구조를 명확히 보여준다.

메타 러닝 정형화

하네스 러닝은 실행 가능한 프로그램에 대한 메타 러닝으로 정형화된다.

  • 안쪽 루프 (Inner loop - 추론 시간 적응): 추론 단계에서 고정된 솔버 및 제안자 모델을 유지한다. 시드 하네스 $h_0$에서 시작하여 $t$번째 라운드마다 제안자 모델은 태스크 설명, 현재 하네스 $h_{t-1}$, 피드백 질문 세트($Q_{fb}^t$)의 실행 보고서로 구성된 컨텍스트 $x_t$를 입력받아 $G$개의 후보 수정안 ${y_i}{i=1}^G$을 샘플링한다. 각 수정안을 적용하여 $h'i = \text{Apply}(h{t-1}, y_i)$를 생성한 후, 평가 질문 세트($Q{score}^t$)에서의 점수를 기반으로 최적의 하네스 $h_t = \text{Select}(h_{t-1}, {h'i}{i=1}^G; Q_{score}^t)$를 선택하여 다음 라운드로 전달한다.
  • 바깥 루프 (Outer loop - 제안자 정책 학습): 다양한 학습 태스크 집합에서 하네스 수정 결과로 얻어지는 최종 평가 성능 보상을 바탕으로 강화학습을 통해 제안자 모델의 파라미터($\theta$)를 최적화한다. 이는 $\max_\theta \mathbb{E}[J(h_T; Q_{eval})]$의 메타 목표를 지향한다.
사실, 소스 주장, 작성자 해석의 명확한 구별
  • 명시적 사실 (Facts): 구현된 프레임워크는 고정된 솔버와 실행 보고서를 활용하여 파이썬 하네스 코드를 편집하는 구조이다.
  • 소스의 주장 (Source Claims): 하네스 러닝을 통해 모델 파라미터 수정 없이 실행 피드백만으로 보지 못한 태스크에 높은 일반화 성능을 보이는 테스트 시간 적응이 가능하다.
  • 작성자의 구조적 해석 (Analyst Interpretation): 에이전트의 제어 로직(하네스)과 인지 능력(솔버)을 완전히 분리함으로써, 가중치 오염(Weight corruption) 위험 없이 에이전트의 실행 아키텍처를 안전하고 모듈화된 방식으로 지속 개선할 수 있는 정보 아키텍처적 기반을 제공한다.

논점 2: 제안자(Proposer) 모델의 학습 방법론 (SFT 및 RL/GRPO)
지도 미세조정 (SFT)

강화학습에 앞서 제안자 모델의 초기화를 위해 교사 모델(Qwen3.6-35B-A3B)이 수행한 성공적인 하네스 수정 이력을 수집하여 지도 미세조정을 진행한다. 초기 시드 하네스의 성능을 개선하고 품질 필터를 통과한 432개의 검증된 수정 사례를 구축하여 제안자 모델이 기본적인 코드 편집 및 실행 구조를 학습하도록 한다.

그룹 상대 정책 최적화 (GRPO) 및 수학적 보상 정형화

초기화된 제안자 모델은 그룹 상대 정책 최적화(GRPO, Group Relative Policy Optimization) 알고리즘을 통해 학습된다. 토큰 수준 중요도 비율 $\omega_{i,k}(\theta) = \frac{\pi_\theta(y_{i,k}|x, y_{i,<k})}{\pi_{\theta_{old}}(y_{i,k}|x, y_{i,<k})}$와 그룹 정규화된 어드밴티지 $\hat{A}_i = \frac{r_i - \text{mean}(r)}{\text{std}(r) + \delta}$를 사용할 때, 클리핑된 대리 목적 함수(Clipped Surrogate Objective)는 다음과 같다:

$$J(\theta) = \mathbb{E}{x \sim \mathcal{D}, {y_i} \sim \pi{\theta_{old}}(\cdot|x)} \left[ \frac{1}{\sum_{j=1}^G |y_j|} \sum_{i=1}^G \sum_{k=1}^{|y_i|} \min \left( \omega_{i,k}(\theta) \hat{A}i, \text{clip}(\omega{i,k}(\theta), 1-\epsilon, 1+\epsilon) \hat{A}_i \right) \right]$$

동일한 입력 컨텍스트 $x$에 대해 제안자 모델로부터 $G$개의 후보 수정안 ${y_i}_{i=1}^G$을 샘플링하고, 각 후보 하네스 $h'i$를 독립된 평가 질문 세트($Q{score}$)에서 실행하여 보상을 산출한다.

1. Reasoning Gym 보상 함수 정형화: $$r_i = J(h'i; Q{score}) + v_i$$ 여기서 유효성 보조 보상(Auxiliary Validity Reward) $v_i$는 다음과 같이 구체적으로 정의된다: $$v_i = 0.05 \cdot \mathbf{1}[y_i \text{ 구문 파싱 성공}] + 0.10 \cdot \mathbf{1}[h'i \neq \bot] + 0.15 \cdot \rho{run}(h'i)$$ $\rho{run}$은 평가 질문 중 오류 없이 완료된 실행 시도의 비율이다.

2. Multi-hop QA 보상 함수 정형화: $$r_i = \begin{cases} J(h'i; Q{score}) + 0.1 \cdot \mathbf{1}[h'_i \neq \bot], & \text{실행 가능한 하네스인 경우} \ 0, & \text{실행 불가능한 경우} \end{cases}$$

단일 단계(Single-step) vs 다단계(Multistep) RL
  • 단일 단계 RL (Single-step RL): 각 학습 단계에서 독립적인 시드 하네스 또는 고정된 부모 하네스 컨텍스트만을 입력으로 제공하여 단일 수정의 즉각적인 보상을 기반으로 학습한다.
  • 다단계 RL (Multistep RL): 이전 수정 단계에서 선택된 하네스와 새로 갱신된 실행 피드백 보고서를 순차적 입력으로 구성하여 학습을 진행한다. (Reasoning Gym에서는 오프라인 상태 갱신 방식, QA 환경에서는 온라인 동적 생성 방식 적용)

교사 모델과의 비교 및 일반화 검증

Reasoning Gym의 보지 못한 21개 태스크 평가에서 4B 파라미터 기반의 단일 단계 RL 제안자 모델은 평균 0.62의 점수를 기록하여, 동일한 평가 프로토콜 하에서 35B 교사 모델이 기록한 평균 점수 0.56을 능가하였다. 또한 Multi-hop QA 실험에서는 HotpotQA에서만 학습된 RL 제안자가 학습에 전혀 사용되지 않은 MuSiQue 및 2WikiMultihopQA 환경에서도 10 라운드 연속 수정을 통해 각각 점수를 크게 향상시켜 강한 교차 벤치마크 일반화 전이 능력을 입증하였다.

단일 단계 vs 다단계 RL의 이론적 의의

실험 결과, 다단계 RL이 단일 단계 RL보다 일관되게 우수한 성능을 보이지는 않았다. 이는 이론적으로 매우 중요한 시사점을 제공한다. 단일 단계 수정 환경에서의 학습만으로도 추론 시간 동안 반복적 하네스 개정 능력이 유기적으로 발현(Emergent capability)될 수 있음을 의미한다. 즉, 학습 과정에서 복잡한 다단계 신용 할당(Multi-step credit assignment)을 수행하지 않더라도, 단일 단계에서 습득된 코드 편집 및 피드백 반영 능력이 추론 시 중간 실행 컨텍스트에 자연스럽게 일반화된다.

논점 4: 반복적 수정(Repeated Revision)과 하네스 구조적 변화 분석
반복적 테스트 시간 적응의 우수성

단일 수정이나 독립적인 무작위 제안(Independent proposals) 대비, 여러 라운드에 걸쳐 이전 라운드의 최선의 하네스를 지속적으로 개정하는 연속 수정(Successive revision) 방식이 훨씬 뛰어난 성과를 보인다. QA 데이터셋(MuSiQue)의 경우 독립 제안의 평균 정확도는 0.15에 불과했으나, 10 라운드 연속 수정을 거친 후 0.27까지 상승하여 독립적 80개 후보 중 최선의 오라클 점수(Best of 80)마저 상회하였다.

연속적 수정 파이프라인 흐름:

  • 초기 단계: 시드 하네스($h_0$) 평가 및 initial 실행 보고서 생성
  • 1차 적응: 1차 피드백 반영 제안자 코드 수정 $\rightarrow$ 개선된 하네스 $h_1$ 선발
  • N차 적응: $N$차 피드백 반영 지속적 수정 $\rightarrow$ 최적화된 하네스 $h_T$ 완성
생성된 하네스 구조 분류 및 결합 실패 메커니즘 분석

제안자 모델 학습 후 생성된 하네스 코드는 태스크 특성에 맞게 고유한 정보 처리 아키텍처로 진화한다:

  1. 인터프리터 루프 (Interpreter loop): Reasoning Gym에서 주로 나타나며(SFT 데이터의 48% 차지), 솔버가 계산 과정을 파이썬 코드로 작성하면 이를 런타임 환경에서 직접 실행하여 답을 도출하는 방식이다.
  2. 도구 재구성 루프 (Tool loops): 검증 알고리즘이나 헬퍼 도구를 솔버의 도구 호출 루프 내로 통합하는 구조이다.
  3. 검증 분기 (Verification branch): QA 환경에서 솔버의 초안 답안이 검색된 문서 내에 존재하는지 검증하고, 없을 경우 해당 초안을 새로운 검색 쿼리로 재검색하는 분기 로직이다 ([SOURCE_IMAGE_9]의 d 참조).
  4. 증거 재연결 (Evidence rewiring): 기존 시드 하네스의 '요약본 기반 답변' 구조를 변경하여, 검색된 1차/2차 원문 단락(Passages)을 답변 생성 모델 호출에 직접 연결하는 구조이다 ([SOURCE_IMAGE_9]의 b 참조).

구조적 결합(Structural Composition)과 기능적 결합(Functional Composition)의 차이 및 실패 원인:

  • 구조적 결합: 헬퍼 도구를 솔버의 도구 호출 루프 내에 코드 상으로 통합하는 것.
  • 기능적 결합: 통합된 헬퍼 도구가 실제로 정답 도출에 유의미하게 기여하는 것.
  • 기능적 결합의 실패 메커니즘: 지침 프롬프트 하에서 제안자 모델은 높은 구조적 결합률(예: Single-step RL에서 12/32)을 달성하지만, 실제 기능적 결합률(3/32)은 매우 낮다. 표 20과 Section 6.2에 명시된 바와 같이, 올바른 알고리즘 코드가 삽입되었더라도 인터페이스/파싱 불일치(질문 파서가 목표 매개변수를 추출하지 못함), 도구 통신 오류(잘못된 형식의 메시지 전달), 답변 추출 실패(헬퍼 도구의 실행 결과가 최종 출력 포맷으로 변환되지 못함)로 인해 실제 과제 점수로 연결되지 못하고 기능적으로 실패하게 된다.
동시대 유사 프레임워크와의 구조적 비교 분석

소스 문서 Appendix A 및 Table 2에 기재된 동시대 유사 연구들과의 아키텍처적 차이는 다음과 같다:

  • 하네스-R1 (Harness-R1): 고정된 대상 에이전트에 대해 오류 궤적 패치(Single patch edit)를 생성하도록 학습된다. 반면 하네스 러닝은 독립된 피드백 세트($Q_{fb}$)와 평가 세트($Q_{score}$)를 분리하고, 동일 하네스에 대한 다라운드 연속 수정(Successive refinement) 체계를 평가한다는 점에서 차별화된다.
  • JIT-에이전트 (JIT-Agent): 인스턴스 수준에서 하네스 아카이브를 확장하며 동적으로 하네스를 생성/수리한다. 반면 하네스 러닝은 태스크 패밀리 수준에서 프로그램 상의 메타 러닝을 수행하여, 보지 못한 전체 패밀리 및 벤치마크로의 제로샷 전이 성능을 확보한다.
  • 오르니스 (Ornith / Ornith-1.0, 1.5): 스캐폴딩(하네스) 생성 정책과 과제 해결 솔버 정책을 공동 학습(Joint RL)시킨다. 반면 하네스 러닝은 솔버의 파라미터를 완전히 고정(Frozen solver)시킴으로써, 가중치 변경에 따른 혼선 없이 순수한 하네스 프로그램의 적응 능력만을 모듈화하여 평가한다.

5. 한계와 불확실성

연구의 한계점 (Source Explicits)
  1. 단일 교사 모델 의존성: Reasoning Gym의 지도 미세조정(SFT) 코퍼스는 단일 35B 교사 모델의 1라운드 수정 데이터에만 의존하여 생성되어 전략 다양성이 제한된다.
  2. 고정된 솔버 사용: 솔버 모델의 파라미터가 고정되어 있어, 하네스 생성 능력과 솔버의 하네스 활용 능력이 함께 발전하는 공동 최적화(Joint optimization) 효과를 검증하지 못했다.
  3. 규정된 프롬프트 의존성: 제안자 모델이 스스로 코드를 검사하거나 실행 도구를 선택하는 자율적 탐색 없이, 외부에서 지정한 프롬프트 및 실행 보고서 양식에 의존하여 수정을 수행한다.
  4. 긴 도구 사용 궤적 제한: 매우 긴 도구 사용 궤적이나 복잡한 환경에서의 다단계 의사결정에 대한 평가 범위가 한계로 남아있다.
소스 미다룸 및 불확실한 영역
  • 동시 연구와의 동일 조건 정량적 성능 직접 비교: Harness-R1, JIT-Agent, Ornith 등 동시기에 진행된 유사 연구들과 동일한 실험 환경에서 직접 비교한 정량적 성능 수치는 소스에서 다루지 않는다 (소스에서 다루지 않음).
  • 솔버와 제안자의 공동 최적화 성능: 고정된 솔버 대신 솔버와 제안자를 동시에 학습시킬 경우의 일반화 전이 성능 변화 수치는 확인 불가.
  • 연구진의 세부 소속 및 세부 실험 일자: 문서상 명시되지 않은 개별 저자의 세부 기관 소속 및 구체적 실험 수행 일자는 확인 불가.
