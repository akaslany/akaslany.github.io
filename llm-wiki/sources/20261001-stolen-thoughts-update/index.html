1. 연구 배경 및 저자들의 핵심 주장

1.1 초기 취약점 공개 및 대형 AI 사업자 대응

프론티어 AI 모델 제공자들은 지식재산권(IP) 보호 및 역증류(distillation) 방지를 목적으로 체인 오브 소트(Chain-of-Thought) 추론 과정을 외부로 노출하지 않고, 암호화된 불투명한 블록(encrypted reasoning blob / signed thinking block) 형태로 클라이언트에 반환하는 방어 아키텍처를 채택해 왔다. 그러나 J Schaeffer, A Panfilov 외 연구진은 선행 연구를 통해 해당 메커니즘의 근본적인 클라이언트 측 포터블리티 결함을 최초로 공개하고 추론 트레이스 추출 가능성을 실증하였다.

연구진의 최초 취약점 공개 직후 OpenAI, Anthropic, Google 등 주요 프론티어 AI 개발사들은 긴급 방어 조치에 착수하였다. 특히 Anthropic은 연구진의 논문을 공식 인용하며 Messages API의 추론 블록 구조를 전면 재구성하여 기존의 보존된 생각 블록(preserved thinking block) 정책을 폐지하였음을 명시하였다. Anthropic은 이후 정밀 조사를 통해 중국의 Moonshot AI가 연구진이 제시한 기술적 메커니즘과 정밀하게 일치하는 방식으로 Claude 모델의 추론 능력을 무단 추출(distillation)했음을 확인하고 이를 공식 위협 보고서로 문서화하였다.

1.2 위협 수준의 격상

추론 정보 유출은 개별 API 수준의 기술적 허점을 넘어 국가 안보 차원의 역동적 위협으로 격상되었다. 미국 국립사이버안보청(CISA)은 연구진의 위협 인텔리전스 분석 및 주요 AI 사업자들의 침해 사례를 바탕으로 보안 권고(Advisory AA26-251A)를 공식 발표하였다. CISA는 해당 권고문에서 중국 정부와 연계된 주체들이 미국 주요 AI 개발 기업의 프론티어 모델을 타깃으로 삼아 국가적 차원의 대규모 능력 증류 캠페인을 전개하고 있음을 공식적으로 밝혔다.

1.3 보고서의 핵심 목적

최초 대응 조치가 도입된 지 2개월이 지난 2026년 9월 13일 기준, 연구진은 1차 공급자의 직접 엔드포인트(OpenAI direct, Anthropic direct)와 2차 하류 클라우드 집계자(AWS Bedrock, Microsoft Azure, Google Vertex, OpenRouter) 간의 보안 방어 수준을 종합 감사(audit)하였다.

연구진의 분석에 따르면, 프론티어 AI 개발사들이 적용한 패치는 매우 표면적이고 파편화되어 있으며 API 수준의 취약한 템플릿 매칭에 의존하고 있다. 더욱이 1차 공급자의 패치가 2차 클라우드로 전파되는 과정에서 수일 이상의 시차(propagation lag)가 발생하고, 하류 클라우드의 구조적 허점을 악용한 '다운스트림 보안 아비트라지(Downstream Security Arbitrage)' 현상이 지속되고 있다. 본 보고서의 핵심 목적은 공격자가 1차 경계 가드레일을 직접 우회할 필요 없이 하류 클라우드로 요청을 재라우팅함으로써 신규 모델인 GPT-6 Astra를 비롯한 최신 프론티어 모델의 추론 과정을 여전히 원본 그대로 추출할 수 있음을 입증하는 데 있다.

2. 추론 정보 추출 공격 방식의 개념적 차이 및 비교 분석

보안 아키텍처 관점에서 추론 정보 추출 공격은 암호화 아티팩트의 세션/모델 간 포터블리티 결함을 이용하는 방식과 모델의 도구 호출(Tool Calling) 인터페이스 및 오케스트레이션을 악용하는 방식으로 구별된다.

비교 항목 추론 재플레이 공격 (Reasoning Replay Attack) 스크래치패드 공격 (Scratchpad Attack)
공격 메커니즘 클라이언트에 반환된 암호화 추론 아티팩트를 동일 가문의 하위 모델 세션에 전달하여 복호화 유도 프롬프트를 통해 모델에게 생각 도구(think tool)를 제공하고 도구 인자(argument)에 추론 과정 출력을 강제
제2의 디코더 모델 필요 여부 필요함 (동일 제공자 가문의 하위/저비용 모델을 암호 해독 오라클로 악용) 불필요함 (단일 타깃 모델의 도구 호출 메커니즘을 직접 활용)
복호화 과정 필수 (전역 공유 키 결함을 악용하여 암호화 아티팩트 복호화) 없음 (도구 인자로 반환된 텍스트를 그대로 수집)
취약점의 근본 원인 교차 모델 및 세션 간 암호화 아티팩트 포터블리티(Portability) 결함 모델의 시스템 프롬프트 가드레일 부재 및 미흡한 도구 오케스트레이션 통제
2.1 추론 재플레이 공격 (Reasoning Replay Attack)
  • 포터블리티 결함: 제공자들은 추론 블록을 암호화할 때 전역 공유 키(shared global keys)를 사용한다. 이로 인해 암호화된 추론 블록이 동일 제공자 생태계 내에서 서로 다른 사용자, 세션, 심지어 서로 다른 모델 간에 아무런 바인딩 제약 없이 교환(portable)되는 구조적 아키텍처 결함이 발생한다.
  • 복호화 오라클 메커니즘: 공격자는 고성능 타깃 모델로부터 수신한 암호화 블록(OpenAI의 encrypted reasoning item, Anthropic의 signed thinking block)을 동일 가문의 정렬(alignment)이 약하고 비용이 저렴한 하위(weaker/cheaper) 모델에 전달한 뒤 "자신의 생각"으로 오인하게 만든다. 하위 모델은 이를 암호 해독 오라클(decryption oracle)처럼 작동하여 타깃 모델의 숨겨진 추론 과정을 평문(plaintext) 텍스트 그대로 복원하여 출력한다.
2.2 스크래치패드 공격 (Scratchpad Attack)
  • 도구 호출 악용 및 실전 에이전트 사례: Can Bölük에 의해 공개된 이 공격 방식은 모델에게 공개되지 않는 생각 도구(private scratchpad)를 제공하고 해당 도구의 인자(argument)에 추론 과정을 작성하도록 지시한다. 이는 단순한 이론적 프롬프트 우회를 넘어 현업 개발 현장에서 실제 운영되는 에이전트를 통해 악용되고 있다. 일례로 OpenRouter 환경에서 활용되는 코딩 에이전트 omp (oh-my-pi)는 external_thinking 설정을 제공하여 기본 추론(native reasoning)을 비활성화하는 대신 스크래치패드 도구를 강제한다. omp는 "private scratchpad; not shown to user. MUST use for planning; other tools become callable when it completes"라는 지시문을 시스템 프롬프트에 주입하고, 모델이 스크래치패드 도구를 호출하여 추론 트레이스를 반환할 때까지 다른 모든 도구의 사용을 차단하는 방식으로 유출을 자동화한다.
  • 구조적 차이점: 재플레이 공격과 달리 제2의 디코더 모델이나 복호화 과정이 전혀 필요하지 않다. 단일 타깃 모델에 도구 정의와 지시문만 주입하면 동작하며, 모델의 기본 추론 기능이 'None'으로 설정되거나 비활성화된 상태에서도 도구 인자를 통해 추론 트레이스가 원본 그대로 노출되는 구조적 차이를 보인다.
2.3 추출된 추론 트레이스의 유사성 및 정량적 비교 (실증 분석)

연구진은 GPT-6 Astra(낮은 추론 노력/low effort 조건, 152개 HLE 문항)를 대상으로 두 공격 방식을 통해 추출된 추론 트레이스의 품질과 실질적 동등성을 정량 분석하였다.

  • 수량 및 길이에 대한 정량적 수치: 두 방식으로 추출된 추론 트레이스의 문제당 중앙값(median) 토큰 길이는 128토큰으로 완전히 동일하였으며, 문제당 길이 비율은 1.07로 집계되었다. 문제별 토큰 길이에 대한 Spearman 상관계수는 0.89를 기록하여 두 방식 간 높은 정량적 연관성을 입증하였다. 두 표본 간 Kolmogorov-Smirnov(KS) 통계량은 0.13으로 나타나 전체적인 분포 차이가 매우 미미함을 확인하였다.
  • 스타일 및 텍스트 유사성 분석: 토큰 길이에 영향을 받지 않는 **'길이 비의존적 문자 3–5-gram 분류기(length-blind character 3–5-gram classifier, problem-grouped 5-fold cross-validation)'**를 적용하여 분석한 결과, 스크래치패드 트레이스와 복호화 트레이스를 구분하는 분류기의 AUC 수치는 0.64에 불과하였다.
  • 대조군과의 통계적 비교:
    • 동일 모델 내 추론 노력 수준 차이(low effort vs medium effort)를 구분하는 기회 통제군(positive control)의 AUC 수치는 0.80으로 명확히 구별되었다.
    • 동일한 스크래치패드 공격을 1차와 2차에 걸쳐 독립적으로 수행한 무작위 기회 수준(null control / random chance)의 AUC 수치는 0.50으로 집계되었다.
    • 즉, AUC 0.64는 두 공격 방식으로 추출된 추론 트레이스가 통계적으로 거의 분리되지 않음을 입증한다.
  • 어휘적 분포 차이의 실체: 연구진은 AUC 0.64 수준의 미세한 차이가 추론 로직 자체의 구조적 차이가 아니라, 스크래치패드 추출 시스템 프롬프트 표면의 단어 선택(wording)에 따른 분포 이동(distributional shift)에 불과하다고 분석한다.
    • 재플레이 복호화 트레이스 측 어휘: time, remaining 등 토큰 예산 관리 관련 어휘와 need reason, need compute, hence 등 추론 접속어가 독자적으로 관찰되었다.
    • 스크래치패드 트레이스 측 어휘: explicit, answer, needed, check 등 응답 프로토콜과 관련된 어휘가 주로 관찰되었다.
    • 두 트레이스 모두 문제의 본질적 내용에 관한 어휘적 차이는 존재하지 않았으며, 능력 증류(distillation) 목적으로 활용될 때 정량적·실질적으로 완전히 동일한 유용성을 제공함이 입증되었다.

3. 공급자와 중개 클라우드 간 방어 전파 문제 및 다운스트림 보안 아비트라지

1차 공급자(직접 엔드포인트)와 2차 집계자(중개 클라우드) 사이에 방어 가드레일의 파편화가 발생하면서 하류 생태계 전체가 유출 경로로 악용되고 있다.

3.1 패치 전파 시차(Propagation Lag) 및 정책 이탈(Policy Drift)
  • 방어책의 파편화: OpenAI direct, Anthropic direct 등 1차 엔드포인트에는 서명된 생각 블록(signed thinking block) 강제 적용, API 수준의 모더레이션 필터링, 프롬프트 플래깅 등 다양한 완화 조치가 도입되었다.
  • 하류 클라우드로의 전파 지연: 1차 공급자에 적용된 방어 패치가 2차 클라우드로 전파되는 과정에서 심각한 시차와 격차가 발생한다. Anthropic이 패치를 적용한 후 AWS Bedrock에 반영되기까지 수시간 이상의 지연이 관찰되었으며, Microsoft Azure 및 OpenRouter 같은 하류 호스트에는 수주일이 지난 시점까지도 방어 패치 조치가 적용되지 않거나 차단 조치가 재현되지 않는 정책 이탈 현상이 확인되었다.
3.2 다운스트림 보안 아비트라지 (Downstream Security Arbitrage)
  • 기능과 취약점의 혼동: 2차 클라우드 호스트 및 프록시 사업자들은 암호화 아티팩트 패스스루(pass-through) 및 유연한 도구 오케스트레이션(tool orchestration) 기능을 결함이 아닌 정상적인 제공 기능(feature)으로 취급하고 있다.
  • 보안 아비트라지 우회 메커니즘: 공격자는 1차 공급자의 직접 API 경계에 구축된 엄격한 가드레일(프롬프트 플래깅, 암호화 아티팩트 검증 등)을 직접 우회하려 시도할 필요가 없다. 대신 보안 통제가 미비한 하류 호스트로 요청 경로를 우회(Routing)하는 전략을 취한다.
    • 교차 모델 키 범위 제한(cross-model key scoping) 누락: Microsoft Azure 등에서는 암호화된 추론 아티팩트가 모델 간 경계를 넘어 동일 가문의 다른 하위 디코더 모델로 제약 없이 전달되어 통과된다.
    • 스크래치패드 남용 통제 미비: 하류 호스트가 생각 도구의 인자 반환 과정을 모니터링하거나 도구 오케스트레이션 남용을 통제하지 못함에 따라, 공격자는 하류 호스트를 우회 경로로 활용하여 1차 공급자의 방어책을 완전 무력화한다.

4. 실험 결과, 한계점 및 방어적 시사점

4.1 주요 모델 및 제공자 경로별 유효성 현황 (2026년 9월 13일 감사 기준)

연구진이 2026년 9월 13일 진행한 감사 결과, 공급자 및 경로별 방어 유효성은 아래와 같이 심각하게 불균형한 상태임이 확인되었다.

1) 추론 재플레이 공격 (Reasoning Replay Attack) 유효성 현황
  • OpenAI Direct API: GPT-6 Astra, GPT-5.6 Sol, GPT-5.6 Terra, GPT-5.5 등 모든 모델에서 하위 디코더 모델이 복호화를 거부(✗)하도록 조치되어 완전 차단되었다.
  • Microsoft Azure: GPT-6 Astra를 포함한 모든 OpenAI 모델 및 Anthropic Sonnet 5 이하 모델에 대해 재플레이 공격이 여전히 작동함(✓). 단 한 번의 디코딩 요청으로 공급자 보고 수치와 수 토큰 이내로 일치하는 전체 추론 트레이스가 그대로 복원된다.
  • AWS Bedrock / Google Vertex / Claude on AWS: Anthropic Opus 4.8 모델에 대해 여전히 재플레이 공격이 유효함(✓).
2) 스크래치패드 공격 (Scratchpad Attack) 유효성 현황

본 실증 실험의 모든 경로 접근은 OpenRouter API 및 BYOK(Bring Your Own Key) 환경을 경유하여 수행되었다.

  • OpenAI 계열 (Direct 및 Azure/Bedrock 전체): GPT-6 Astra, GPT-5.6 Sol, GPT-5.6 Terra, GPT-5.5 등 모든 프론티어 모델에서 스크래치패드를 통한 추론 트레이스 추출이 지속적으로 성공함(✓).
  • Anthropic 계열: Opus 4.8 및 Sonnet 5 모델은 주요 호스트 경로에서 스크래치패드를 통한 추론 노출이 여전히 유효함(✓).
  • (✗) 상태의 정밀 정의 및 차단 한계: 표 및 감사 결과에서 Opus 5 모델 등에 표시된 (✗) 상태는 완전한 차단을 의미하지 않는다. 이는 **"스크래치패드 추론 과정의 일부 또는 전체가 클라이언트로 출력된 후, 별도의 최종 답변 없이 거부(refusal) 메시지로 이어지는 불완전한 방어 상태"**를 뜻한다. 즉, 거부 반응이 발생하더라도 추론 트레이스는 이미 탈취되는 한계가 존재한다.
  • 차단 일자(Timeline) 및 유효 모델: 2026년 9월 13일 기준, 스크래치패드 공격으로부터 추론 과정이 완벽히 보호되는 모델은 Fable 5, Fable 5.1 등 일부에 불과하다. Anthropic은 8월 16일 엔드포인트에서 Fable 5의 스크래치패드 공격 경로를 차단하였으며, Azure, Vertex, Claude on AWS 경로에서는 9월 12일에 이르러서야 해당 공격 벡터의 차단이 확인되었다.
4.2 보안 아키텍처 및 방어 시사점
다중 클라우드 동기화 의무화 (Standardized Multi-Cloud Synchronization Mandates)
  • 저자들은 모델 개발사가 제3자 클라우드 제공자(Azure, Bedrock, Vertex 등)를 단순한 수동적 유통 채널로 취급하는 아키텍처적 관습을 즉시 중단해야 한다고 강조한다.
  • 추론 트레이스 기밀성 유지, 교차 모델 키 범위 제한, 도구 범주 가드레일 적용 등 다중 클라우드 환경 전체의 보안 수준 동기화가 실증적으로 검증(practically verified)될 때까지, 방어 능력이 미달하는 하류 호스트에게 추론 가능 모델 가중치(weights)의 라이선스 부여 및 제공을 엄격히 제한해야 한다.
수출 통제 및 국가 안보 정책과의 불일치
  • CISA 보안 권고 및 연구소 지도부는 미국 프론티어 AI 모델의 핵심 지식재산인 추론 능력을 해외 적대 세력의 대규모 역증류 캠페인으로부터 보호하는 것이 국가 안보의 핵심 과제임을 명시하고 있다.
  • 그러나 1차 API 경계에서 적용된 기술적 완화 조치가 패치되지 않은 2차 클라우드 호스트의 보안 아비트라지에 의해 무력화되고 있다. 이는 결과적으로 API 경계에 구축된 국가 차원의 기술 수출 통제 정책 효과를 실질적으로 상쇄 및 무효화시키는 심각한 안보적 허점을 야기하므로, 집계자 생태계 전체를 아우르는 동기화된 보안 표준 수립이 시급하다.
