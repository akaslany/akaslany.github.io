2. Discoverative AI와 Heavy-Duty Solver(HDS)의 개념적 재정의

저자들은 기존 AI 모델의 역할을 '정적 응답기'에서 '능동적 발견 주체'로 격상시키며, 이를 Discoverative AI라 명명했다. 이는 실행 가능한 환경에서 도구를 사용하여 스스로 가설을 세우고 수정하며 발견을 수행하는 존재를 의미한다.

Heavy-Duty Solver(HDS)의 구성 요소 및 시스템적 한계

[정의/직접 확인] 성능 평가의 단위인 Heavy-Duty Solver(HDS)는 단일 파운데이션 모델(Foundation Model)이 아니다. 이는 다음의 5대 핵심 요소가 결합된 '시스템'이다.

  1. Foundation Model: 추론과 텍스트 생성을 담당하는 연산 엔진.
  2. Harness: 모델을 실제 파일 시스템, 도구, 실행 환경과 연결하는 물리적 인터페이스.
  3. Tools: 검색, 코드 실행기, 전문 과학 소프트웨어, 검증기(Verifier) 등의 외부 도구 집합.
  4. Memory: 장기 임무 수행 중 발생하는 상태 변화, 관측값, 가설, 결정 사항을 유지하는 저장소.
  5. Control Policy: 다음 행동 결정, 도구 선택, 실패 시 재시도 전략 등을 결정하는 운영 정책.

[정의/직접 확인] 보고서에 명시된 성능 수치는 파운데이션 모델 단독의 지능 지수가 아니라, 위 5개 요소가 상호작용하는 'HDS 시스템 전체'의 결과물이다. 따라서 특정 solver 점수를 모델의 순수 추론 능력으로 환원하면 안 된다. 균형 잡힌 matched subset과 충분한 반복·통제가 있을 때에만 model, harness, 제어 정책의 기여를 제한적으로 분리할 수 있다.

3. 정적 벤치마크 대 실행 기반 환경 (TRACES 아키텍처)

TRACES 벤치마크는 기존의 정적 QA 방식(MMLU, GPQA 등)이 AI의 '실험적 발견 능력'을 측정하지 못한다는 문제의식에서 출발한다.

비교 분석: 정적 QA vs. TRACES (Executable Reality)
구분 정적 QA (MMLU 등) TRACES (Reality-based Environment)
상호작용성 단회성 (Single-pass) 연속적/상태 유지형 (Stateful)
정보 획득 모델 내장 지식 (Closed-book) 실시간 도구 출력, 시뮬레이션, 외부 문서
평가 지표 최종 정답 일치도 (Accuracy) 실행 궤적(Trajectory) 및 과정 점수
복원력 실패 시 즉시 오답 검증 피드백을 통한 자체 수정(Repair) 가능
추상화 구조 분석
  • Problem Manifest: 질문, 성공 기준, 자산 예산(Time/Compute), 태스크 분해 방식을 정의하는 '정적 계약'이다. 이는 문제의 명세를 명확히 하지만, 저자들이 선택한 프록시(Proxy) 지표의 객관성까지 보장하지는 않는다.
  • Environment-Task-Episode: 실행 기반의 상호작용 구조다. 에피소드(Episode)는 특정 HDS가 환경(Environment) 내에서 특정 태스크(Task)를 수행한 전체 기록을 의미한다.

[열린 문제] 저자들이 명명한 'Reality-based'라는 표현은 실제 임상적 유효성(Real-world clinical validity)과 동의어가 아니다. 이는 시뮬레이션이나 사후 데이터 기반의 '실행 환경' 내에서의 현실성임을 유념해야 한다.

4. 3단계 검증 채널 및 권한 체계의 투명성 감사

TRACES는 결과와 과정을 두 개의 보완적 verifier로 평가하고, 무결성 위반을 별도 gate로 검사하는 구조를 제안한다. 교육적으로 세 통로로 설명할 수 있지만, 세 통로가 완전히 독립이라고 단정하면 안 된다.

  1. Outcome Verifier (결과 검증기): 최종 산출물 및 중간 단계의 핵심 산출물(Load-bearing artifacts)을 숨겨진 진실(Hidden truth)과 대조한다. 0~1 사이의 정규화된 점수를 산출한다.
  2. Process Verifier (과정 검증기 / HDS6): 모델의 신원이나 사적 사고 체인(CoT)을 배제한 채 외부로 드러난 실행 궤적(Trajectory)만을 평가하는 'Blind Judge' 역할을 수행한다.
  3. Integrity Gate (무결성 게이트): 도구 호출 조작(Fabrication), 결과 위조, 데이터 누출(Leakage) 등 치명적 위반 시 즉시 'Hard-fail' 처리한다.

[저자 측 설계 설명] 일반 process judge는 outcome을 보지 않는다고 보고되지만, integrity gate는 fabrication 탐지를 위해 outcome을 제한적으로 조회한다. 또한 verifier 소스·versioned container hash·세부 gate specification·원 trajectory 점수가 공개되지 않아, 외부인은 정확성·강건성·편향을 충분히 검사하거나 독립 재현하기 어렵다.

5. HDS6/TRACES의 6대 핵심 역량 지표 (Process Metrics)

HDS6는 task별 저자가 설계한 0–4 ordinal rubric으로 외부 trajectory의 과정 품질을 평가하는 운영자 지표다. 연구자의 성실성·내부 사고·결론의 진실을 직접 측정하는 점수는 아니다.

  • T (Tools): 도구 선택의 적절성 및 출력값 해석의 정확성.
  • R (Repair): 실패 후 원인을 파악하고 피드백을 반영하여 수정하는 능력.
  • A (Alternatives): 경쟁 가설을 비교하고 증거에 따라 가설을 갱신하는 태도.
  • C (Coherence): 수백 단계의 과정 중 초기 목표와 논리적 일관성을 유지하는 능력.
  • E (Evidence): 모든 주장이 데이터, 도구 출력, 문헌에 접지(Grounding)되었는지 여부.
  • S (Scope): 결론의 적용 한계와 불확실성을 명시하는 능력.

[정의/직접 확인] 저자들은 과정 점수(Process score)가 높다고 해서 결과가 반드시 과학적 참(Truth)인 것은 아님을 명시하고 있다. 이는 '그럴듯한 과정을 밟았는가'와 '실제 발견을 했는가'를 분리하는 중요한 경계선이다.

6. 벤치마크 구성 범위 및 선택 편향(Selection Bias) 감사

  • 규모 분석: 16개 섹션 561개 산업 조사를 통해 423개의 내부 레지스트리(Registry) 문제를 확보했으나, 초기 릴리스에는 20개, 최종 보고서(Table 1) 수치 도출에는 17개 환경 및 218개 에피소드만이 활용되었다.
  • [열린 문제] 423개 문제 전체 목록, reviewer agreement, 점수 분포와 탈락 사유는 공개되지 않았다. 따라서 selection bias나 cherry-picking의 존재 여부와 크기를 외부에서 판단할 수 없다. 이는 부정행위의 증거가 아니라 감사 가능성의 결손이다. 또한 Claude Opus 모델이 생물학적 안전(Biosafety) 이유로 design task 수행을 거부한 결측은 비임의적이므로, 단순 평균이나 순위에서 일반적인 실패와 같은 방식으로 처리하면 capability와 safety-policy 차이를 혼동할 수 있다.

7. 주요 사례 연구 (Case Studies) 및 통계적 수치 분석

AAV(Adeno-associated virus) 캡시드 설계

저자들은 기존 SOTA 대비 평균 7%의 성능 향상을 주장한다. 그러나 본 감사관이 수치를 분해한 결과는 다음과 같다.

Task (AAV) Apodex-1.1 Published SOTA Relative Improvement
Viability (예측) 0.904 0.878 3.0%
Tropism (예측) 0.635 0.622 2.1%
Structure (예측) 0.649 0.605 7.3%
Design (생성) 0.180 0.116 55.2%

[기술적 비판] '약 7%'는 네 이질 점수의 단순 macro-average인 0.59200과 0.55525의 상대 차이 6.62%를 반올림한 것으로 해석된다. 이는 네 과제별 상대 개선율 3.0%, 2.1%, 7.3%, 55.2%를 평균한 값도 아니고, 각 과제에서 7 percentage points 개선됐다는 뜻도 아니다. 서로 다른 metric을 동일 가중해 요약하는 선택의 정당화와 반복 불확실성이 제시되지 않았으므로 개별 task 수치와 조건을 함께 봐야 한다.

신약 재창출(DRR) 및 임상 분석

GPT-5.5/5.6-sol 모델에 생의학 환경을 추가했을 때 각각 +2.5, +7.6 points의 점수 향상이 보고되었다. [정의/직접 확인] 이 수치는 실제 치료 효과의 개선이 아니라, random anchor=0과 perfect=100 사이로 재척도화된 정규화 예측 점수의 포인트 차이다. Public-100 개발셋에서 각 3회 실행한 retrospective temporal forecast의 기술통계이며, raw-score 증가는 각각 +0.00330과 +0.00994다. Hidden-200 결과나 prospective clinical validation으로 해석하지 않는다.

8. 통계적 해석 및 인과관계 감사 (Technical Audit)

상관관계의 불확실성

409개 궤적 분석에서 과정 점수(HDS6)와 결과 점수(Outcome) 사이의 Spearman $\rho = +0.51$, Pearson r = +0.56이 보고되었다.

  • 주의사항: 상관관계는 인과관계를 입증하지 않는다. 특히 AAV 분야의 Spearman ρ는 +0.24로 약하다. 이 차이는 task 난이도·점수 분포·trajectory 구성·judge가 관찰할 수 있는 성공 신호 등 여러 요인의 영향을 받을 수 있으며, 과정이 결과를 인과적으로 만들었다거나 HDS6가 진실을 측정한다고 해석할 수 없다.
Repair 실험의 인과 해석 한계

저자들은 HDS6<3인 434개 실행에 대해 수정 노트를 제공하여 +0.155의 개선을 달성했다고 주장한다. [열린 문제] 이 실험에는 수정 노트 없이 단순 재실행한 matched no-note rerun control이 없다. LLM은 확률적이고 HDS6<3인 deficient run만 선택했으므로 run-to-run variation과 regression to the mean이 개입할 수 있다. 따라서 +0.155는 repair-note 재실행에서 관찰된 before/after 연관으로는 말할 수 있지만, repair note의 순수 인과효과로 확정할 수 없다.

9. 발견 챌린지의 성격: Retrospective vs. Prospective

저자들은 이미 정답이 알려진 과거 데이터를 맞히는 '사후 분석(Retrospective)'과 정답이 존재하지 않는 '미래 지향적(Prospective)' 도전을 구분한다.

  • 파킨슨병 Prospective Challenge: 현재 '진행 계획(Plan)' 단계이며 실질적인 발견 결과는 존재하지 않는다.
  • [정의/직접 확인] 이는 주장을 미리 봉인(Seal)하고 미래의 실험 결과로 검증하겠다는 방법론적 엄격함의 제안일 뿐, 현재 AI가 새로운 치료제를 실제로 '발견했다'는 성공 발표가 아님을 명확히 한다.

10. 보고서의 한계 및 최종 감사 결론

구조적 비판: Same-organization Conflict

Apodex라는 단일 조직이 벤치마크 설계, 환경 운영, verifier 제작, baseline reproduction과 자사 solver 평가를 함께 수행한다. 이는 보고된 수치가 틀렸다는 증거는 아니지만, task 선택·scorer·rerun·공개 범위가 같은 조직의 판단에 의존하는 이해상충이다. Live site가 자사 entry를 표시하고 이 문제를 공개한 점은 투명성에 도움이 되지만 독립 검증을 대신하지 않는다. 외부 재현, versioned scorer/container, 원자료 또는 독립 escrow 감사가 필요하다.

초보자용 비유를 통한 요약

"기존 AI 평가가 정답만 적어 내는 '단답형 시험'이었다면, TRACES는 학생을 실험실(Environment)에 넣고 도구를 쥐여준 뒤, 교수님이 옆에서 오답 노트(Repair)를 주며 실험 전체 과정(Trajectory)을 지켜보는 '종합 연구 프로젝트 아키텍처'와 같습니다."

최종 감사 결론

Apodex Discovery 보고서는 '실제 일반 과학 발견 능력'의 입증이 아니라, 이를 측정하기 위한 '평가 아키텍처(TRACES)의 제안서'로서의 가치를 지닌다. 보고된 7% 혹은 +0.155와 같은 수치는 고도로 통제되고 폐쇄적인 Apodex 자체 환경에서의 초기 지표일 뿐이다. 본 감사관은 이 보고서가 제안하는 'HDS 시스템 중심의 평가'라는 방향성은 긍정적으로 평가하나, 수치적 주장에 대해서는 독립적 검증이 이루어질 때까지 '유보적(Qualified)' 입장을 유지할 것을 권고한다.
