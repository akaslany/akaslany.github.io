Full-bandwidth transformer

AI가 ‘말로 쓰지 않은 생각’을 다음 토큰으로 넘기는 방법 — 쉬운 풀이

Xi Wang 외 7인, arXiv:2608.08888v1, 2026년 8월 9일 제출. 이 글은 논문의 저자 보고치와 독립적으로 확인 가능한 사실을 구분한 해설이다. 아직 동료평가·독립 재현이 확인되지 않은 preprint다.

먼저 결론

기존 autoregressive transformer는 다음 단어를 만들 때, 직전 단계가 고른 토큰 하나를 다시 입력으로 사용한다. 과거 전체 문맥의 KV cache는 남지만, 직전 token을 처리한 최상위 hidden state 전체가 다음 token의 첫 layer로 되돌아가지는 않는다.

《Full-bandwidth transformer》는 이 통로를 넓힌다. 이전 단계의 top-layer hidden state와 현재 token embedding을 작은 gate로 합쳐 다음 입력으로 넣는다. 저자들은 이를 latent feedback이라고 부른다.

생활 비유로 바꾸면 이렇다.

  • 기존 방식: 한 부서가 복잡한 검토를 끝내도 다음 부서에는 최종 한 문장만 전달한다.
  • latent feedback: 최종 한 문장과 함께 내부 작업 메모의 압축된 상태도 전달한다.

이 설계는 1B 규모 실험에서 validation loss, 여러 language-model benchmark, 수학·코딩 생성, synthetic state tracking을 개선했다. 특히 같은 model weights에서 일반 decoding을 latent-feedback decoding으로 바꾸었을 때 성능이 오른 결과는 흥미롭다.

그러나 headline은 좁게 읽어야 한다. 저자들이 negligible이라고 표현한 미측정 serving overhead, 1.5배·2배·5배 더 많은 token을 학습한 model에 근접, 더 짧은 reasoning은 모두 특정 1B model, 특정 data mixture, 특정 evaluation과 비용 정의에서 나온 저자 해석이다. 더 큰 model과 실제 serving에서의 독립 검증은 아직 없다.

1. 무엇이 좁았다는 것인가

Transformer의 계산에는 두 방향이 있다.

  1. 가로 방향: 과거 token 위치를 attention으로 읽는다.
  2. 세로 방향: 한 token이 여러 transformer layer를 통과하며 표현을 깊게 만든다.

가로 방향에서는 KV cache 덕분에 과거를 넓게 볼 수 있다. 하지만 새 token의 낮은 layer는 과거 위치의 더 깊은 layer 상태를 곧바로 읽지 못한다. 이전 위치의 state는 같은 layer 이상의 계산에서 접근되고, 직전 위치의 top-layer output 자체는 KV cache에 저장되지 않는다.

저자들은 이 현상을 depth-frozen, 즉 “깊이에서 얼어 있다”고 표현한다. 정보가 완전히 사라진다는 뜻은 아니다. 이미 생성된 token과 KV cache로부터 이론상 다시 계산할 수 있다. 다만 새 token의 얕은 layer가 이미 깊게 처리된 직전 상태를 바로 이어받지 못한다는 뜻이다.

그래서 논문은 이득의 성격을 정확히 제한한다.

latent feedback은 새로운 정보를 만들어 내는 장치가 아니라, 이미 문맥에 의해 결정된 정보를 다음 계산에서 더 쉽게 접근하게 하는 장치다.

즉 정보량의 혁신이 아니라 계산 경로와 접근성의 변화다.

2. latent feedback은 어떻게 동작하나

논문의 핵심 식은 간단하다.

  • 이전 token의 top-layer state를 value로 사용한다.
  • 현재 token embedding은 sigmoid gate를 만든다.
  • 두 결과를 element-wise로 곱해 다음 token의 입력을 만든다.

직관적으로는 현재 token이 “이전 hidden state의 어떤 부분을 통과시킬지” 정하는 gate가 된다. 추가 학습 파라미터는 hidden dimension이 D일 때 D×D projection 두 개다.

저자들이 단순 덧셈 대신 비대칭 gate를 선택한 이유도 중요하다. 입력 embedding에 hidden state를 그냥 더하면 model이 hidden path를 무시하고 익숙한 token-only path로 돌아갈 수 있다. 반면 논문의 gate는 state path를 버리면 입력 자체를 제대로 구성하기 어렵게 만들어, model이 latent state를 사용하도록 압력을 준다.

이 구조는 transformer block, attention, KV-cache layout 자체를 크게 뜯어고치지 않는다. 논문 부록은 request별 최신 trunk hidden state를 별도 buffer에 보존해 다음 decode step에 주입하는 vLLM 구현 구상을 제시한다.

다만 “vLLM-compatible”은 shape와 설계 패턴 수준의 호환성이다. 실제로는 전용으로 학습된 checkpoint와 fusion weights, request별 hidden-state buffer, patched GPUModelRunner, decoding loop 수정이 필요하다. 논문은 실제 production 규모에서 동시 요청 throughput, p95 latency, prefix-cache 공유, speculative decoding, quantization과의 상호작용을 benchmark하지 않는다. 조사 시점에 저자 공식 실행 코드나 checkpoint도 확인되지 않았다.

3. 세 가지 decoding 방식

논문은 같은 full-bandwidth model을 세 방식으로 비교한다.

STANDARD
  • prompt를 한 번 prefill한다.
  • 생성할 때 일반 token embedding만 사용한다.
  • latent-feedback training 자체가 일반 transformer 동작을 얼마나 해치는지 보는 기준이다.
SOFT
  • prompt prefill은 일반 방식이다.
  • 생성 token부터 이전 top-layer state를 되먹인다.
  • 추가 per-token 연산은 D×D matrix multiplication 두 번이다.
FUSED
  • prompt 전체를 latent-feedback 방식으로 한 번 더 처리한다.
  • 그다음 SOFT처럼 생성한다.
  • 생성 overhead는 SOFT와 같지만 prompt prefill은 사실상 두 번 실행된다.

따라서 SOFT는 거의 공짜라는 표현과 FUSED는 prefill compute를 추가한다는 사실을 분리해야 한다. 긴 prompt를 다루는 서비스에서는 FUSED의 prompt 재처리가 중요한 비용이 될 수 있다.

4. 순차 recurrence를 어떻게 병렬 학습했나

실제 decoding은 token 하나씩 순차적으로 진행된다. 이전 token의 hidden state를 다음 token에 넣는 recurrence를 그대로 학습하면, transformer pretraining의 장점인 parallel teacher forcing을 잃는다.

저자들의 해결책은 multi-pass temporal parallelism이다.

  1. 첫 pass는 일반 token embedding으로 전체 sequence를 병렬 처리한다.
  2. 첫 pass의 hidden state를 한 위치 오른쪽으로 옮긴다.
  3. 각 위치의 token embedding과 합쳐 두 번째 pass를 전체 위치에서 다시 병렬 계산한다.
  4. 필요하면 같은 일을 세 번째 pass까지 반복한다.

각 pass 내부에서는 모든 token 위치가 병렬이지만 pass와 pass 사이는 순차다. k-pass batch는 대략 k배의 forward compute가 든다. later-pass loss는 이전 pass까지 backpropagate되므로 memory footprint도 증가한다.

Progressive schedule

대부분의 학습은 값싼 1-pass로 하고, 중간 이후에 2-pass와 소량의 3-pass를 도입한다.

  • 200B·400B run: 75% one-pass, 22% two-pass, 3% three-pass
  • 200B token run의 token-equivalent compute: 256B
  • 400B token run의 token-equivalent compute: 512B
  • 10B run은 표에서 100% three-pass와 40B-equivalent를 함께 적었지만, 본문의 pass-count 정의라면 30B가 되어야 한다. 이는 명백한 표기 불일치 또는 정의 누락이다.

여기서 “400B token 학습”은 실제 data token 수고, 반복 pass까지 센 계산량은 512B token-equivalent다. 일반 400B-token standard model과 동일 training compute는 아니다.

왜 3%의 three-pass가 중요했나

1-pass와 2-pass만 섞은 model은 학습한 recurrence 깊이를 넘어 반복했을 때 validation loss가 올라가고 hidden-state update가 진동했다. 반면 3%의 3-pass batch를 추가하자 30회, 부록에서는 1000회 반복 prefill에서도 loss와 state 변화가 안정된 plateau를 보였다.

저자들은 이를 contraction-like behavior라고 해석한다. 하지만 contraction constant를 증명한 수학 정리는 아니다. 특정 1B model과 validation distribution에서 관찰된 안정성 진단이다.

5. 어떤 model을 학습했나

주요 model은 약 1B parameter다.

  • 24 transformer layers
  • hidden dimension 1,536
  • FFN dimension 6,656
  • vocabulary 100,352
  • 16 query heads, 8 KV heads
  • context 8,192
  • 대부분 2,048 sliding-window attention, 매 6번째 layer full attention
  • Phi-4와 같은 data mixture라고 설명

학습 token은 10B, 100B, 200B, 400B 규모다. Standard baseline은 최대 1T token까지 포함한다. 200B와 400B model에는 12B token의 32K long-context extension과 6B token의 instruction tuning도 적용했다.

하지만 논문만으로 data mixture의 모든 corpus, benchmark contamination, hardware, 전체 FLOP, wall-clock을 완전히 감사할 수는 없다. 1T baseline은 global batch size 1.2M을 사용했고 다른 run은 300K를 사용했다는 차이도 있다.

6. 가장 강한 결과는 무엇인가

6-1. 같은 weights에서 decoding만 바꾼 결과

가장 흥미로운 비교는 full-bandwidth training을 끝낸 같은 model weights에서 STANDARD와 SOFT/FUSED를 바꾼 것이다. 이 비교는 architecture training 효과와 decoding path 효과를 어느 정도 분리한다.

Figure 5는 같은 full-bandwidth weights에서 STANDARD·SOFT·FUSED를 비교한다. 이 within-model 비교는 decoding path 자체의 효과를 가장 잘 격리하는 강점이 있다. 여러 수학·코딩 task에서 개선 신호가 보이지만, 현재 PDF에는 수치 보고상의 충돌이 있다.

  • 본문이 예로 든 MATH-500 200B 0.27 → 0.37은 현재 Figure 5의 200B 곡선과 맞지 않는다.
  • 현재 Figure 5에서는 400B MATH-500의 SOFT가 STANDARD보다 낮아 보인다.
  • HumanEval·MBPP의 그래프도 개선 신호를 보이지만 exact raw table과 생성 score의 신뢰구간 정의가 없다.

따라서 0.27 → 0.37 같은 본문 수치를 확정 결과로 재인용하지 않고, 동일 weights 비교에서 여러 task의 개선 신호가 관찰됐지만 그림·본문이 완전히 일치하지 않는다고 정리하는 것이 안전하다. 수학은 SOFT가, coding은 FUSED가 대체로 유리하다는 것이 저자들의 해석이지만 예외도 있다.

Coding 평가는 문제당 10 rollout에서 Pass@3를 추정하고 method별로 temperature 0.3, 0.5, 0.7 중 최적값을 선택했다. method마다 hyperparameter를 따로 고른 만큼, 고정된 sampling policy보다 평가 유연성이 크다는 점을 기억해야 한다.

6-2. Instruction-tuned 결과

Table 1에서 200B full-bandwidth model은 다음과 같이 개선됐다.

  • GSM8K: 64.52 → SOFT 67.93
  • MATH-500: 43.80 → 45.60
  • HumanEval Pass@3: 42.54 → FUSED 45.92
  • MBPP Pass@3: 38.39 → FUSED 41.22

400B model에서는:

  • GSM8K: STANDARD 67.90 → SOFT 71.00 → FUSED 71.80
  • MATH-500: STANDARD 46.00 → SOFT 45.40 → FUSED 48.40
  • HumanEval: STANDARD 46.50 → SOFT 47.20 → FUSED 47.60
  • MBPP: STANDARD 40.50 → SOFT 40.60 → FUSED 41.70

비교용 1T standard baseline은 각각 70.13, 47.40, 50.01, 41.93이다. 일부 task에서는 FUSED가 1T baseline에 근접하거나 넘지만 HumanEval·MBPP에서는 뒤진다. 또한 400B MATH-500의 SOFT는 46.00에서 45.40으로 하락하므로, 본문의 “SOFT와 FUSED가 네 task 모두에서 개선”이라는 문장은 Table 1과 일치하지 않는다.

6-3. Prefill에서의 data efficiency

Figure 4에서는 fused prefill pass를 추가할수록 validation loss와 10-task 5-shot LM Eval 평균이 좋아진다. 첫 추가 pass의 이득이 가장 크다.

  • 100B full-bandwidth + feedback prefill이 200B standard 수준
  • 200B full-bandwidth가 400B standard 수준

저자들은 이를 약 2배 pretraining data efficiency로 표현한다. 다만 extra prefill compute를 사용한 결과다. “같은 training data로 더 좋은 model”이라는 의미는 있지만, “같은 end-to-end 비용에서 무조건 2배 효율”이라는 뜻은 아니다.

7. reasoning trace가 정말 짧아졌나

Figure 6은 200B base model의 MATH-500에서 SOFT가 STANDARD보다 짧은 median reasoning length와 더 높은 정확도를 보인다고 제시하고, Figure 8은 일반 decoding이 길게 나눗셈 과정을 쓰는 동안 SOFT가 핵심 계산만 짧게 적는 정성 예시를 보여준다. 다만 Figure 6의 정확도는 Figure 5의 같은 이름·규모 조건과 맞지 않고, 원 그림 파일명은 medium_level 부분집합을 암시하지만 캡션은 이를 밝히지 않는다. 따라서 전체 MATH-500 일반 결과로 확정하면 안 된다.

이는 “중간 계산 일부가 언어 token 대신 hidden state를 타고 이동할 수 있다”는 설계 예측과 맞는다.

하지만 중요한 반전이 있다.

  • instruction tuning 후 이 conciseness 효과가 사라졌다.
  • 논문은 standard token-by-token trace로 만든 off-policy tuning data가 verbosity를 재학습시켰을 수 있다고 본다.
  • 이는 그럴듯한 설명이지만 별도 대조실험으로 확정된 인과관계는 아니다.

또 짧은 trace가 곧 더 안전하거나 더 검증 가능하다는 뜻도 아니다. 사용자가 볼 수 있는 reasoning token이 줄면 오류 추적과 감독이 오히려 어려워질 수 있다. 논문은 주로 성능·효율 관점에서 이 현상을 다룬다.

8. hidden state에 정말 더 많은 상태가 들어왔나

논문은 synthetic task에서 linear probe를 사용한다.

  • completion tracking
  • delayed binary memory
  • 여러 register의 최신 값 추적

모든 example이 같은 마지막 colon token으로 끝나게 설계해, layer-0의 일반 token embedding 자체에는 label 정보가 없도록 했다.

One-step recurrent prefill 후 layer-0 probe는:

  • completion tracking 99.6%
  • delayed memory 100%

정확도를 보였다. 일반 prefill에서는 layer-0가 chance에 가깝고 여러 layer를 지나야 상태를 복구했다.

이 결과는 latent feedback이 global state를 shallow layer에서 읽기 쉽게 만든다는 메커니즘 증거다. 그러나 linear probe가 읽을 수 있다고 해서 model이 실제 next-token 결정에 그 정보를 인과적으로 사용한다는 뜻은 아니다. 논문도 이 한계를 명시하며 실제 task score를 별도 증거로 제시한다.

9. 관련 연구와 진짜 차별점

이 아이디어는 완전히 고립돼 있지 않다.

  • Feedback Transformer는 미래 위치가 과거 layer 표현의 혼합을 읽게 했다.
  • Latent Recurrent Transformer와 T²MLR는 이전 위치의 hidden representation을 다음 위치에 주입한다.
  • Coconut, Soft Thinking, PonderLM-2는 continuous latent reasoning을 탐구한다.

Full-bandwidth transformer의 실용적 차별점은 다음과 같다.

  1. token을 latent로 대체하지 않고 token embedding과 latent state를 함께 쓴다.
  2. model block 내부 변경을 최소화하고 input fusion으로 구현한다.
  3. D×D projection 두 개만 추가한다.
  4. multi-pass scheduling으로 400B-token pretraining까지 확장했다.

하지만 논문은 어떤 reinjection 위치와 구조가 같은 compute에서 가장 좋은지 자원 부족으로 비교하지 못했다고 인정한다. 즉 “최종 설계가 확정됐다”기보다 유망한 설계 지점 하나를 크게 실험한 연구다.

10. 반드시 붙여야 할 한계

  1. 1B 규모 한정: 7B, 70B, frontier model에서 같은 안정성·효율이 나올지 모른다.
  2. preprint: peer review와 독립 재현이 아직 없다.
  3. 실제 serving 측정 부족: 최종 PDF는 추가 행렬곱 비용을 negligible이라고 표현하지만 wall-clock 비율을 보고하지 않는다. 두 D×D projection의 파라미터 수는 D=1,536에서 4,718,592개, 명목상 1B의 약 0.47%지만 이는 end-to-end throughput·tail latency 비율이 아니다.
  4. FUSED prefill 비용: prompt 전체 forward pass가 하나 더 필요하다.
  5. training compute 증가: 400B data token run은 512B token-equivalent compute다.
  6. 통계 불확실성: Figure 4는 standard error를 제시하지만 모든 generation score에 seed·confidence interval이 붙지는 않는다.
  7. temperature selection: coding method별 최적 temperature를 별도 선택했다.
  8. data transparency: Phi-4-style mixture의 세부 corpus를 논문만으로 완전히 감사할 수 없다.
  9. 짧은 reasoning의 취약성: instruction tuning 후 효과가 사라졌다.
  10. probe의 한계: decodability와 causal use는 다르다.
  11. stability의 한계: repeated prefill에서의 fixed-point-like behavior가 모든 autoregressive sequence를 보장하지 않는다.
  12. 관련 방법과 iso-compute 비교 부족: 저자도 어느 hidden-state injection 방식이 최선인지 검증하지 못했다.

11. 이 연구의 유효기간과 철회 기준

이 결론의 유효기간은 다음 검증이 나오기 전까지다.

강화되는 조건
  • 독립 연구팀이 code·weights로 같은 결과를 재현한다.
  • 7B 이상 model에서 data·compute-matched baseline을 이긴다.
  • production vLLM에서 batch throughput, p95 latency, memory가 공개된다.
  • on-policy latent-feedback post-training으로 짧은 reasoning 효과가 유지된다.
약화·철회해야 할 조건
  • 더 큰 model에서 recurrence가 불안정해진다.
  • iso-FLOP 또는 iso-wall-clock 비교에서 standard training이 더 낫다.
  • benchmark gain이 data contamination이나 tuning flexibility로 설명된다.
  • 실제 serving overhead가 headline보다 훨씬 크다.
  • 독립 재현에서 generation gain이나 shorter reasoning이 사라진다.

최종 평가

《Full-bandwidth transformer》는 transformer가 “이미 계산한 것을 다음 token의 낮은 layer가 다시 쓰기 어렵다”는 문제를 명확한 통신 대역폭 관점으로 설명한다. 그리고 이전 top-layer hidden state를 token embedding과 함께 되먹이는 작은 변경으로 이를 해결하려 한다.

1B 규모 결과는 꽤 일관적이다. 같은 weights에서 decoding path만 바꿔 수학·코딩 성능이 오르고, fused prefill이 LM 평가를 개선하며, synthetic probe에서 global state가 layer 0에 거의 완벽하게 드러난다.

그러나 가장 좋은 요약은 “standard transformer를 대체할 완성품”이 아니다.

latent feedback은 기존 transformer의 계산 경로를 넓히는 유망한 방법이며, 1B pretraining에서 강한 초기 증거를 보였다. 하지만 더 큰 model, 공정한 총비용 비교, 실제 serving, 독립 재현에서 확인할 단계가 남았다.

그 경계를 지키면 이 논문은 매우 흥미롭다. 더 적은 말로 더 많은 계산을 전달하는 model이 가능한지, 그리고 다음 scaling axis가 parameter나 data만이 아니라 token 사이에 전달하는 hidden-state bandwidth가 될 수 있는지를 묻기 때문이다.
