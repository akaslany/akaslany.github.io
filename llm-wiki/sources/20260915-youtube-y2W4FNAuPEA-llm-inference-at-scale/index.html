원문

대규모 LLM 추론 최적화 및 인프라 효율화 심층 분석 보고서

본 보고서는 Harshul Jain(Audible 시니어 소프트웨어 엔지니어)과 Tanmay Sah(AI 연구원)의 기술 워크숍 내용을 바탕으로, 대규모 언어 모델(LLM) 추론의 경제적 임계점과 이를 극복하기 위한 아키텍처적 최적화 전략을 분석합니다. 수석 기술 전략가의 관점에서 하드웨어 병목 현상과 소프트웨어적 해결책을 구조적으로 정리하였습니다.

1. LLM 추론의 현황 및 경제적 페인 포인트

현재 LLM 추론 시장은 약 230억 달러 규모로 급성장 중이나, 운영 비용(Operating Cost) 측면에서 심각한 수익성 도전에 직면해 있습니다. Harshul Jain은 LLM 도입의 경제적 타당성을 다음과 같이 분석했습니다.

  • 수익성 한계와 비용 한계점: Google 검색 쿼리를 LLM으로 완전히 대체할 경우, 약 360억 달러의 이익 감소가 예상됩니다. 기존 검색 비즈니스의 수익성을 방어하기 위해서는 토큰당 비용을 0.5센트 미만으로 억제해야 하는 엄격한 비용 효율성이 요구됩니다.
  • 지속적 운영 비용의 특성: GPT-3 기준 학습 비용은 약 460만 달러의 일회성 비용(Capex)인 반면, 추론 비용은 사용자 수, 세션, 토큰 수에 비례하여 무한히 발생하는 가변적 운영 비용(Opex)입니다.
  • 인프라 다이어트의 필요성: 하드웨어 자원의 희소성과 높은 컴퓨팅 단가로 인해, 비즈니스 생존을 위해서는 토큰 사용량을 예산화(Budgeting)하고 추론 엔진을 극한으로 최적화하는 아키텍처 설계가 필수적입니다.

2. LLM 추론의 4대 핵심 지표 및 병목 현상

실시간 추론 성능과 운영 효율을 결정짓는 핵심 지표는 다음과 같습니다. 벤치마크는 주로 RTX 6000(Blackwell급 성능) 및 H100 환경에서 수행되었습니다.

  • TTFT (Time to First Token): 프롬프트 입력 후 첫 토큰이 출력될 때까지의 지연 시간입니다. 컨텍스트 크기가 커질수록 입력 토큰 전체에 대한 연산량이 증가하여 TTFT가 악화됩니다.
  • Throughput (처리량): 시스템이 초당 처리할 수 있는 총 토큰 수입니다. 순차적 처리(Sequential Processing)의 한계로 인해 동시 사용자 수가 증가할수록 병목이 심화됩니다.
  • Memory (메모리): 모델 가중치 외에도 입력 토큰 증가에 따른 KV 캐시 점유율이 변수입니다. Mistral 7B 모델(FP16 기준 약 15GB 가중치)의 경우, 컨텍스트 길이를 확장함에 따라 가용 메모리가 급격히 잠식되어 OOM(Out of Memory)을 유발합니다.
  • Inter-token Latency (TPOT): 토큰 간 생성 시간으로, 사용자가 체감하는 생성 속도를 결정하는 네 번째 핵심 지표입니다.

3. 기술적 기초: 트랜스포머 계층과 KV 캐시(KV Cache)

LLM 연산의 95% 이상을 차지하는 Attention 메커니즘은 토큰이 늘어날수록 연산 복잡도가 $O(N^2)$으로 증가합니다. 이를 $O(N)$의 선형 복잡도로 낮추기 위해 메모리와 연산을 트레이드오프하는 기법이 바로 KV 캐시입니다.

KV 캐시 점유량 산출 (Architect's Proof)

Mistral 7B 모델을 기준으로 토큰당 생성되는 KV 캐시 크기는 약 131 KB이며, 산출 근거는 다음과 같습니다.

2 (K&V 벡터) * 128 (헤드 차원) * 32 (레이어 수) * 8 (KV 헤드 수) * 2 (FP16 바이트) = 131,072 바이트

[컨텍스트 길이에 따른 메모리 요구량 추정]

컨텍스트 길이 사용자(Batch) 총 KV 캐시 메모리 인프라 영향 분석
4K (4,000 토큰) 1명 약 0.5 GB 단일 유저 처리 가능
16K (16,000 토큰) 1명 약 2.1 GB 컨텍스트 확장 시 메모리 부담 가중
4K (4,000 토큰) 80명 약 42 GB 24GB급 GPU에서 즉시 OOM 발생

GPU 메모리는 고정된 Model Weights, System Overhead, 그리고 가변적인 KV Cache 영역으로 구분됩니다. 동시 사용자 수가 많아질수록 KV 캐시가 남은 메모리를 잠식하며 시스템 안정성을 위협합니다.

4. 추론의 두 단계: Prefill과 Decode 단계 분석

추론 프로세스는 연산 특성에 따라 두 단계로 명확히 구분됩니다.

  1. Prefill 단계 (Compute-bound):
    • 입력된 프롬프트를 일괄 처리하여 KV 캐시를 최초 생성하는 단계입니다.
    • 산술 집약도(Arithmetic Intensity), 즉 전송되는 데이터 바이트당 수행되는 부동 소수점 연산 수(FLOPs/Byte)가 매우 높습니다. 따라서 GPU의 순수 연산 성능에 의해 TTFT가 결정됩니다.
  2. Decode 단계 (Memory-bound):
    • 이전 토큰을 참조하여 다음 토큰을 하나씩 생성하는 단계입니다.
    • 매 단계마다 데이터 유닛을 고대역폭 메모리(HBM)에서 연산을 위한 공유 메모리(Shared Memory)로 덩어리(Chunk) 단위로 옮겨야 합니다.
    • 산술 집약도가 낮아 GPU의 연산력보다는 메모리 대역폭(Bandwidth)에 의해 성능이 제한됩니다.

5. 모델 수준의 최적화 전략

Tanmay Sah는 모델 구조 자체를 경량화하여 추론 효율을 극대화하는 방안을 제시했습니다.

  • 양자화(Quantization): FP16에서 INT8/INT4로 정밀도를 낮춰 메모리 사용량을 절감합니다. 다만, Sah는 품질 손실을 무시하고 압축만 추구하는 태도를 '타조 알고리즘(Ostrich Algorithm)'에 비유하며, 반드시 벤치마크를 통한 품질 검증이 선행되어야 함을 경고했습니다.
  • Attention 구조 혁신:
    • GQA (Grouped Query Attention): K, V 헤드를 그룹화하여 공유함으로써 MHA의 품질과 MQA의 효율성 사이에서 최적의 균형을 찾습니다.
    • MLA (Multi-head Latent Attention): K, V 데이터를 압축된 잠재 벡터(Latent Vector)로 표현합니다. DeepSeek 등의 모델에서 채택되었으며, MHA 대비 약 14배의 메모리 절감 효과를 제공합니다.
  • Flash Attention: 메모리 계층 간의 데이터 이동을 최적화하기 위해 연산을 타일(Tile) 단위로 분할 처리하여 HBM 접근 빈도를 줄이고 속도를 높입니다.

6. 서빙 엔진 최적화 및 가용성 향상

소프트웨어 스택에서의 최적화는 GPU 자원 활용도를 극대화하는 데 초점을 맞춥니다.

  • PagedAttention: 운영체제(OS)의 가상 메모리 기법을 차용하여, KV 캐시를 불연속적인 물리 블록에 동적으로 할당합니다. 이를 통해 메모리 파편화(Fragmentation) 문제를 해결하고 가용 공간을 90% 이상 활용합니다.
  • Continuous Batching: 특정 요청의 종료를 기다리지 않고 개별 토큰 생성이 완료되는 즉시 새로운 요청을 배치에 투입하여 GPU 유휴 시간(Idle time)을 최소화합니다.
  • Prefix Caching: 반복되는 시스템 프롬프트 등을 Radix Tree 구조로 저장하여 재사용합니다. 동일한 접두사를 가진 요청들에 대해 중복 연산을 제거하여 효율을 높입니다.

7. 엔진별 성능 벤치마크 및 의사결정 가이드

워크로드의 성격에 따라 최적의 엔진 선택이 필요합니다.

  • vLLM vs SGLang: 표준적인 단발성 질의 워크로드에서는 성능 차이가 미미합니다. 그러나 동일한 프롬프트가 수백 번 반복되거나 복잡하게 분기되는 에이전트형(Agentic) 워크로드에서는 SGLang이 강점을 보입니다. 이는 SGLang의 Radix Tree 기반 캐싱이 반복적인 '테스트 타임 추론(Test-time inference)' 루프에서 압도적인 효율을 발휘하기 때문입니다.
  • TensorRT-LLM: Nvidia 하드웨어 계층에 최적화된 SDK로, 소프트웨어적 유연성보다 하드웨어의 최대 성능(Peak performance)을 끌어내야 하는 엔터프라이즈 환경에 권장됩니다.
  • Trade-off Triangle: 아키텍트는 품질(Quality), 지연시간(Latency), 처리량(Throughput) 사이의 균형을 설계해야 합니다. 프리미엄 챗봇은 품질과 지연시간을 위해 처리량을 희생하는 반면, 비동기 에이전트는 품질과 처리량 극대화에 집중합니다.

8. 핵심 요약

  • 경제성: 검색 서비스 대체 시 360억 달러 손실 위험이 있으므로 쿼리당 0.5센트 미만의 비용 달성이 필수적입니다.
  • 지표: TTFT, Throughput, Memory 외에 inter-token latency(TPOT)를 포함한 4대 지표 관리가 핵심입니다.
  • KV 캐시: Mistral 7B 기준 토큰당 131 KB가 소요되며, 이는 메모리와 연산 복잡도($O(N^2) \rightarrow O(N)$)의 트레이드오프 결과입니다.
  • 병목 분석: 산술 집약도 분석에 따라 Prefill은 Compute-bound, Decode는 Memory-bound 특성을 보입니다.
  • 구조 최적화: MLA 도입 시 MHA 대비 최대 14배의 메모리 절감이 가능합니다.
  • 서빙 전략: vLLM의 PagedAttention은 메모리 효율의 표준이며, SGLang은 Radix Tree를 통해 에이전트 워크로드에서 3~4배의 성능 우위를 가집니다.
  • 향후 과제: 하드웨어 최적화 수준을 넘어 KV Eviction(축출) 전략 및 분산 추론 환경에서의 효율화가 차세대 최적화의 핵심이 될 전망입니다.
