1. 의사결정 모델(Decision Model)과 일반 언어 모델(LLM)의 개념 및 역할 비교

클라우드플레어(Cloudflare)가 제시하는 의사결정 모델(Decision Model)과 일반 대형 언어 모델(LLM)은 시스템 아키텍처 내 목적, 추론 메커니즘, 그리고 에이전트 워크플로우에서의 역할에서 근본적인 차이를 보입니다.

  • 일반 대형 언어 모델 (LLM)의 특성
    • 비결정론적 성격 및 자유 형식 생성: 토큰 단위(Token-by-token) 자율 생성을 기반으로 자유 형식의 텍스트, 복잡한 추론 과정, 및 외부 도구 호출(Tool calling)을 유연하게 생성합니다.
    • 열린 추론 능력과 높은 컴퓨팅 비용: 광범위한 맥락 이해와 탐색적 작업에 강점을 가지지만, 추론 지연 시간(Latency)이 길고 상당한 GPU 컴퓨팅 자원을 소모합니다.
  • 의사결정 모델 (Decision Model)의 특성
    • 제한된 구조적 출력 (Bounded Structured Outputs): 임의의 텍스트를 생성하는 대신 사전 정의된 스키마에 따라 입력 상태를 수용하고, 유형화된(Typed) 확률 분포 결과만을 결정론적으로 반환합니다.
    • 저비용·고속·일관성: 중간 텍스트 생성 단계를 완전 배제하여 추론 지연 시간과 컴퓨팅 비용을 획기적으로 절감하며, 정밀하고 일관된 확률 측정치를 제공합니다.
    • 동적 분류 및 확장성: 신규 카테고리가 추가될 때마다 모델을 재학습(Retraining)할 필요 없이, 어떠한 입력 상태에 대해서도 유연하게 작동합니다.
    • 의사결정 시점 투입 및 에이전트 자동화: 입력 상태(예: 고객 지원 요청 메시지)가 진입하는 기점에 실시간으로 정형화된 확률 결과를 출력합니다. 이를 통해 사람이 모든 결정 과정에 개입(Human-in-the-loop)하지 않아도, 시스템이 프로그래밍 방식으로 티켓 라우팅, 상급 전달(Escalation), 또는 사람 전달 여부를 즉시 실행할 수 있습니다.
  • 아키텍처적 패러다임 전환: 하이브리드 오케스트레이션 ('Clef + LLM')
    • 에이전트 시스템 아키텍처에서 'Clef + LLM'의 하이브리드 패턴은 기존 LLM 단독 구조 대비 압도적인 자원 효율성을 제공합니다. 무거운 생성형 LLM을 앞단에 배치하는 대신, 비자기회귀 의사결정 모델을 초고속 '핫패스 게이팅(Hot-path gating)' 레이어로 활용하여 맥락을 사전에 분류·라우팅함으로써 불필요한 LLM 추론에 따른 GPU 자원 낭비를 원천 차단합니다.
  • '클레프(Clef)' 명칭의 유래
    • 음악 이론에서 '음자리표(Clef)'가 악보 맨 앞에 위치하여 선과 칸의 음높이 및 향후 연주될 음표(행동)의 맥락을 정의하듯, 의사결정 모델은 에이전트 워크플로우 진입점에서 맥락의 도메인을 정의하고 이후의 작업(Actions)을 결정합니다. 또한 'Clef'의 알파벳 'CF'는 클라우드플레어(Cloudflare)의 약칭을 고스란히 내포합니다.

2. 클레프(Clef) 및 클레프 플래시(Clef-flash)의 주요 구조와 제반 특성

클라우드플레어가 공개한 Clef 및 Clef-flash는 엣지 컴퓨팅 환경에서 최적의 추론 성능을 발휘하도록 설계된 고성능 의사결정 모델입니다.

항목 상세 내용
시각 입력 처리 (Vision Encoder) 텍스트 분류만 지원하던 기존 의사결정 모델(Jev 등)과 달리 시각 인코더(Vision Encoder)를 기본 탑재하여, 이미지 입력 수용 및 시각적 콘텐츠 분류가 가능함.
문맥 창 (Context Window) 기존 Jev 모델의 32k 대비 2배 확장된 64k 문맥 창을 제공하여, 고도화된 의사결정에 필요한 더 많은 입력 상태와 컨텍스트 정보를 일시에 수용.
모델 제품군 및 라이선스 정밀도와 정밀한 판단을 위한 Clef와 극도의 지연 시간 최적화를 위한 Clef-flash 2종으로 구성. 아파치 2.0(Apache 2.0) 오픈소스 라이선스로 허깅페이스(Hugging Face)에 공개되었으며, Workers AI 플랫폼에서 호스팅됨.
엣지 컴퓨팅 기반 배포 클라우드플레어 글로벌 네트워크 엣지의 GPU 인프라에 직접 배포되어 네트워크 전송 지연 시간을 극소화하고, 에이전트의 핫패스(Hot-path)에서 즉각적인 초고속 의사결정을 수행함.

3. 비자기회귀(Non-autoregressive) 추론 및 스키마 선택 점수화 메커니즘

Clef 모델 제품군은 기존 LLM의 토큰 단위 자기회귀(Autoregressive) 순차 생성 방식을 탈피하여, 내부 백본 표현을 직접 점수화하는 비자기회귀 추론 아키텍처를 구현했습니다.

  1. 사전 채우기 전용(Prefill-only) 패스 수행
    • 백본(Backbone) 모델인 큐원(Qwen)을 활용하여 전체 프롬프트와 입력 페이로드를 단일 사전 채우기(Prefill-only) 단계로 처리하고 내부 상태 표현을 추출합니다.
  2. 병렬 스키마 점수화 (비자기회귀 추론)
    • 중간 텍스트나 토큰을 순차적으로 생성하지 않고, 백본의 내부 표현 상태에서 직접 유효한 스키마 선택지들을 병렬로 점수화(Scoring)하여 추론 지연 시간을 대폭 단축합니다.
  3. 2단계 어텐션 라우팅 (Two-stage Attention Routing) 및 의미 보존
    • 선택지별 증거 라우팅 (Option-specific evidence routing): 유효한 모든 스키마 선택지가 프롬프트 내부에서 각 항목과 직접적으로 연관된 컨텍스트 증거를 추출합니다.
    • 교차 필드 어텐션 (Joint cross-field attention): 개별 필드 매개변수가 다른 필드 및 원본 페이로드와 상호 교차 어텐션을 수행하여, 필드 간의 복잡한 문맥 종속성(Contextual dependencies)을 정밀하게 파악합니다.
    • 스키마 구속 점수화 (Schema-bound scoring): 어휘적 사전 분포(Lexical prior)를 적용하여 다양한 선택지 사이에서 입력의 의미적 의도(Semantic intent)를 보존하는 동시에, 지정된 스키마 제약 조건에 맞춰 엄격하게 최종 확률을 도출합니다.

4. 모델 학습 방식 및 강화학습(RLCD) 미세조정 기법

Clef 모델은 사전 학습된 백본을 동결(Freeze)한 상태에서 라우팅 헤드를 최적화하고, 확률 보정을 위한 손실 함수와 전용 강화학습 기법을 결합하여 학습되었습니다.

기반 모델 및 파라미터 동결 (Parameter Freezing)

Clef는 Qwen3.8-27B를, Clef-flash는 Qwen3.5-9B를 기반 백본으로 채택했습니다. 백본 모델 자체의 파라미터는 완전히 동결(Freeze)한 상태에서 랭크-256(Rank-256) 저순위 적응형(LoRA) 어댑터와 라우팅 헤드(Routing head)를 함께 공동 최적화(Joint optimization)하여 학습 효율성과 표현력을 동시에 확보했습니다.

손실 함수 (Loss Functions) 및 확률 보정

유효한 스키마 구조의 출력을 정형화하기 위해 라벨 평활화 교차 엔트로피(Label-smoothed cross-entropy)를 적용하고, 모델이 출력하는 확률 수치의 정밀도를 정밀하게 보정하기 위해 브라이어 손실(Brier loss)을 조합했습니다. 두 손실 함수의 결합을 통해 스키마의 구조적 유효성 보장과 출력 확률의 예측 정밀도 보정을 동시에 달성합니다.

학습 데이터셋 구성

필드 순서, 프롬프트 형태, 스키마 구조를 무작위로 치환하고 무작위 변형을 가한 내부 합성 데이터셋(Internal synthetic datasets)을 구축하여 모델의 일반화 성능을 극대화했습니다.

RLCD (Reinforcement Learning for Calibrated Decisions)

보정된 의사결정을 도출하기 위해 RLCD 기법을 보조 최적화 목표로 도입했습니다.

  • 부분 점수 부여: 서열형(Ordinal) 선택지에 대해 인접한 정답에 가까울 경우 부분 점수(Partial credit)를 부여합니다.
  • 정확한 출력 보상: 레코드 레벨에서 완벽히 정확한 출력에 대해 보상을 제공합니다.
  • 참조 페널티 (Reference penalty): 학습 과정 중 모델의 분포 변화(Distribution shift)를 방지하는 참조 페널티를 적용하여 편향을 차단하고 안정적인 정확도를 확보했습니다.

5. 벤치마크 평가, 지연 시간 비교 및 실무 사용 사례

클라우드플레어 자체 측정 발표 기준으로 진행된 평가에서 Clef 및 Clef-flash는 다양한 의사결정 벤치마크와 워크플로우 평가에서 최상위 성능을 제시하였습니다.

위협 인텔리전스(Threat Intelligence) 도메인 분류 실무 적용 사례

클라우드플레어 내부 위협 인텔리전스 팀은 브라우저런(Browser Run) 기능과 Clef를 결합하여 웹사이트 도메인 분류 작업을 수행했습니다. 해당 시스템은 페치(Fetch), 렌더링, 분류 과정까지 단 2.2초 만에 완료하였으며, 패션(95%), 이커머스(85%), 피싱(<1%) 등의 다중 카테고리 확률을 정확히 도출했습니다. 반면 동일한 워크플로우에서 범용 LLM인 gpt-oss-120b 모델은 4.7초가 소요되고 단 2개 카테고리 분류에 그쳤습니다. 6. 강화학습(RL) 미세조정 서비스 및 클라우드플레어 플랫폼 아키텍처

클라우드플레어는 기업의 특수한 엔터프라이즈 워크플로우에 최적화된 맞춤형 의사결정 모델을 구축할 수 있도록 강화학습(RL) 미세조정 플랫폼을 함께 제공합니다.

서비스 제공 단계
  • 1단계 (현재): 클라우드플레어 FDE(Forward-Deployed Engineer) 엔지니어링 팀이 직접 파트너로 개입하여 엔터프라이즈 고객의 도메인 특화 데이터로 모델을 미세조정하는 맞춤형 파트너십 형태로 운영.
  • 2단계 (향후 계획): 고객이 클라우드플레어 플랫폼상에서 직접 데이터를 캡처하고, RL 환경에서 모델을 학습 및 재배포할 수 있는 완전한 셀프서비스(Self-serve) RL 플랫폼으로 확장.

[5. Workers AI + BYO Model] <──(가중치 재배포)─── [4. Trainer] <─── [3. Containers] (RL 샌드박스 평가)
  1. Cloudflare AI Gateway (입력 트래픽 수집): 모든 AI 트래픽이 경유하도록 설정하여 실제 엔터프라이즈 유스케이스 기반의 요청 및 응답 데이터셋을 자동으로 수집 및 생성.
  2. Cloudflare Workers AI (롤아웃 생성): 기본 Clef 모델을 실행하여 평가 대상이 되는 행동 롤아웃(Rollouts)을 생성 및 준비.
  3. Cloudflare Containers (RL 샌드박스 평가): 격리된 환경 내에서 에이전트의 행동을 점수화(Scoring)하고 실제 환경에서의 동작을 재현하는 RL 샌드박스 역할 수행.
  4. Trainer [신규 구성 요소]: 샌드박스로부터 전달된 피드백을 수용하여 미세조정된 Clef 모델의 파라미터 가중치(Weights) 업데이트를 직접 집행.
  5. Cloudflare Workers AI + BYO Model (맞춤형 재배포): Replicate 인수 기반의 Cog 기술(BYO Model)을 활용하여, 학습이 완료된 커스텀 가중치 모델을 Workers AI 글로벌 엣지 인프라에 즉시 재배포.

7. 기업용 적합성, 개인정보 보호 및 서비스 활용 안내

Clef 모델 제품군과 강화학습 미세조정 플랫폼은 엄격한 보안 요구사항과 기존 시스템과의 호환성을 고려하여 설계되었습니다.

클라우드플레어는 고객이 맞춤형 미세조정 서비스를 명시적으로 옵트인(Opt-in)하여 이용하지 않는 한, 입력된 요청 및 응답 데이터를 열람하거나 별도로 저장하지 않으며, 이를 모델 학습에 절대로 사용하지 않는 엄격한 데이터 보호 정책을 준수합니다. 기술적 호환성 측면에서는 기존 시장 표준인 Jev API와 완전한 호환성을 보장하므로, 기존 에이전트 시스템의 인터페이스 코드를 변경하지 않고도 수월하게 Clef로 전환할 수 있습니다. 현재 Clef 및 Clef-flash는 Workers AI를 통해 즉시 관리형 API 서비스로 활용 가능하며, 자체 호스팅이나 고유 연구를 진행하는 개발자는 허깅페이스(Hugging Face) 오픈소스 저장소를 통해 아파치 2.0 라이선스로 공개된 모델 가중치(Weights)를 직접 내려받아 적용할 수 있습니다.
