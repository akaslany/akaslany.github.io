1. 문제 정의: 파라미터 재사용과 계산비용은 같은 말이 아니다

Looped Transformer는 같은 물리적 레이어 블록을 여러 번 실행해 저장 파라미터를 재사용하면서 유효 깊이(effective depth)를 늘린다. 그러나 저장 파라미터 수만 맞춘 비교는 공정하지 않을 수 있다. 예를 들어 12개 물리 레이어 가운데 일부를 다시 실행해 총 24개 레이어 실행을 만들면, 가중치는 재사용하더라도 토큰당 FLOPs와 KV cache는 더 깊은 실행 경로에 맞춰 증가할 수 있다. 반대로 FLOPs만 고정하려고 폭이나 고유 레이어 수를 줄이면 총 파라미터 용량이 감소한다. 논문의 핵심 질문은 이 교란을 제거한 뒤에도 looping 자체가 이점을 보이는가이다. (PDF 1–4쪽, Section 1–2, Table 1)

저자들은 이 문제를 Sparse MoE로 다룬다. MoE는 각 토큰이 일부 전문가만 활성화하므로 총 저장 파라미터와 토큰당 활성 계산량을 어느 정도 분리할 수 있다. 그래서 반복 실행에 드는 FLOPs를 모델 폭 축소로 지불하고, 줄어든 총 파라미터는 expert 수를 늘려 회복하는 설계가 가능하다. 하지만 이것만으로 KV cache가 맞는 것은 아니므로 attention head size와 GQA 비율도 별도로 조정한다. (PDF 2, 5–6, 29–30쪽, Figure 1, Table 2, Tables 9–10)

Table 10에 따르면 스케일링 법칙 적합에 사용한 12개 sparse cell의 최대 절대 mismatch는 FLOPs 3.9%, 총 파라미터 1.0%, KV cache 3.6%다. 따라서 “same cost”라고 뭉뚱그리기보다 “논문이 정의한 세 예산을 위 오차 범위에서 근사 일치시켰다”고 말해야 한다. 이 비교는 산술 FLOPs를 맞춘 것이지 wall-clock latency, 통신량, 메모리 대역폭이나 하드웨어 효율을 맞춘 것이 아니다. (PDF 6, 30쪽, Section 3.2, Table 2, Appendix A)

200M, S≈95% 예시는 조정 과정을 구체적으로 보여준다. Baseline은 물리 깊이 12, H=1280, 레이어당 192 experts, 토큰당 학습 FLOPs 1.33×10^9, 총 non-embedding parameters 3.87×10^9다. SMELT는 가운데 6개 레이어를 두 번 방문해 총 18개 레이어를 실행한다. 추가 실행비용을 상쇄하려고 H를 1056으로 좁히고, 줄어든 총 파라미터를 회복하려고 experts를 288개로 늘린다. 그 결과 논문은 FLOPs 1.37×10^9로 Baseline 대비 +2.9%, 총 파라미터 3.89×10^9로 +0.4%, KV cache는 4% 이내라고 보고한다. (PDF 6쪽, Section 3.2; PDF 30쪽, Table 10)

여기서 S는 보통의 “활성 expert 비율” 그 자체가 아니다. 논문은 완전 활성 Baseline control의 FLOPs와 총 파라미터를 기준으로 compute-equivalent active parameters를 만든 뒤 S=1−N_act^eq/N으로 정의한다. 따라서 S=0인 looped 모델도 expert pool에서 top-8만 라우팅할 수 있다. S=0은 모든 expert가 활성이라는 뜻이 아니라 완전 활성 Baseline과 파라미터당 계산 강도가 같다는 뜻이다. (PDF 5–6쪽, Section 3.1, Eq. 1)

3. SMELT 구조: 전체 네트워크를 두 배로 돌리는 방식이 아니다

SMELT는 “Sparse MoE Transformer, middle layers Loop Twice”의 약자다. 물리 레이어 수를 L, 반복되는 연속 구간 길이를 m, 방문 횟수를 r이라고 하면 유효 깊이는 L_eff=L+(r−1)m이다. 최종 recipe는 다음과 같다. (PDF 2, 5–8, 29–30쪽, Figure 1, Sections 3.1–3.5, Tables 9–10)

  1. 전체 레이어의 가운데 절반 m=L/2만 반복한다.
  2. 그 가운데 블록을 총 두 번 방문한다. 즉 r=2이며 전체 스택을 통째로 두 배 실행하지 않는다.
  3. 추가 실행으로 늘어난 FLOPs를 지불하기 위해 hidden dimension을 줄인다.
  4. 폭 축소로 줄어든 총 non-embedding parameters를 회복하기 위해 expert 수를 늘린다. 모든 MoE 레이어는 토큰당 top-8 experts를 선택한다.
  5. KV cache를 근사 일치시키기 위해 attention head size와 GQA 비율을 조정한다.
  6. 반복 구간의 각 attention 및 MoE residual update는 1/r로 스케일한다. SMELT는 r=2이므로 해당 update에 1/2가 적용된다.

최대 grid cell은 Baseline scale label 1.6B, S≈97%다. 이 label은 Baseline의 active-parameter scale을 가리킨다. Table 9의 Baseline 총 non-embedding parameters는 53.89B, Table 10의 대응 SMELT는 53.90B다. SMELT의 한 물리 순회 active non-embedding parameter footprint는 1.103B로 적혀 있다. 따라서 “54B active parameters”라고 말하면 틀리며, “최대 약 54B total non-embedding parameters”라고 해야 한다. (PDF 29–30쪽, Tables 9–10)

4. 세 설계 ablation과 열위 설정

4.1 어느 구간을 반복할 것인가

200M, 물리 깊이 12, 두 번 방문 조건에서 반복 구간을 0–100%로 바꾼 Table 3에서 validation loss 최저점은 S≈85%와 S≈95% 모두 50% span 부근이다. 그러나 DCLM Core는 같은 순위를 주지 않는다. 특히 S≈95%에서 DCLM Core 최고값은 67% span의 31.78±0.18이고, 50% span은 29.68±0.13이다. 저자들은 수십억 token을 평균한 validation loss가 더 매끄럽다는 이유로 50%를 선택하고 DCLM 열을 consistency check로 취급한다. 각 architecture configuration은 한 번만 학습됐고, 표의 표준오차는 10개 평가 seed의 변동만 반영하므로 training-run variability는 포함하지 않는다. (PDF 6–7쪽, Section 3.3, Table 3)

4.2 깊이와 폭의 균형

50% span, 두 번 방문, 200M, S≈85% 조건에서 Table 4는 Baseline과 looped 모델의 depth sweep을 비교한다. Baseline의 validation-loss 최적 물리 깊이는 12다. Looped Transformer는 물리 깊이 12, 유효 깊이 18인 12/18 설정이 validation loss 1.9257, DCLM Core 27.57±0.13, DCLM Completion 2.2635로 자기 후보 중 세 지표 모두 최고다. 저자들은 looped 모델이 Baseline보다 큰 effective depth-to-width ratio를 선호한다고 해석하지만, shared layer가 여러 방문에서 받는 gradient가 최적화를 돕는다는 설명은 가설이다. (PDF 7–8쪽, Section 3.4, Table 4)

4.3 몇 번 방문할 것인가

Table 5에서 2×는 effective depth 18, validation loss 1.9257, DCLM Core 27.57±0.13, Completion 2.2635로 1×·3×·4×보다 모두 낫다. 3×와 4×는 같은 FLOPs cap을 맞추기 위해 더 얇아지면서 2×보다 열위다. 다만 4×가 모든 지표에서 3×보다 일관되게 더 나쁜 것은 아니므로 “반복 횟수가 늘수록 단조롭게 악화된다”고 말할 수 없다. 논문도 2×와 나머지 사이의 공통 격차만 의미 있다고 적는다. (PDF 8쪽, Section 3.5, Table 5)

이 세 ablation은 모두 200M scale, 최대 약 3.9B total non-embedding parameters 범위에서 수행됐다. 더 큰 모델에서도 최적 span과 방문 횟수가 같다는 보장은 없다. (PDF 8, 22–23쪽, Sections 4, 7)

5. 별도 스케일링 법칙과 compute-optimal frontier

저자들은 네 scale 100M/200M/600M/1.6B와 네 sparsity level S=0, 약 85%, 95%, 97%의 4×4 grid를 만든다. 각 cell의 Baseline/SMELT pair에서 여섯 cosine-decay branch를 얻어 총 96 matched pairs, 192 endpoints를 평가한다. 모든 16 cell의 마지막 training loss에서 SMELT가 Baseline보다 낮았다고 보고한다. (PDF 8–9, 30–32쪽, Section 4.1, Figures 2–3, Appendix B)

Scaling fit은 Baseline과 SMELT에 같은 하나의 식을 공유시키지 않고, 각 architecture에 별도의 여섯 계수 E,A,K,a,b,c를 적합한다. 형태는 L(F,S,D)=E+A(1−S)^b/F^a+K/D^c다. F는 평균 문서 길이에서 측정한 토큰당 학습 FLOPs, D는 학습 tokens, S는 compute-equivalent sparsity다. 총 compute C=F·D 아래에서 loss를 최소화해 F*, D*와 frontier loss L*(C,S)를 구한다. (PDF 9–10쪽, Section 4.2, Eqs. 2–4)

S=0 control은 sparse regime과 떨어져 있어 joint fit의 RMSE를 악화시키므로 fit에서 제외된다. 실제 적합은 세 sparse level의 12 cells, architecture당 72 endpoints, 총 144 endpoints를 사용한다. 지원되는 누적 학습 compute 범위는 1.3×10^19에서 2.2×10^21 FLOPs다. Huber loss δ=10^-3를 log-loss에 적용하고 L-BFGS-B로 적합했다. (PDF 10쪽, Section 4.3)

Table 6 계수로 계산한 frontier exponent는 Baseline 약 0.237, SMELT 약 0.250이며, 저자들은 SMELT 쪽이 약 5.5% 크다고 보고한다. 하지만 SMELT의 irreducible loss E=1.4493은 Baseline 1.4439보다 0.005 nats 높다. 이 차이는 양쪽 fit RMSE보다 작아 저자들은 fit noise로 해석하며, C=10^25 같은 훨씬 큰 영역은 추가 학습점 없이 예측할 수 없다고 명시한다. (PDF 10–11쪽, Table 6, Figure 4)

CE Gain은 SMELT가 어떤 loss에 도달하는 compute C_tgt와 Baseline이 같은 loss에 도달하는 C_ref를 역산해 1−C_tgt/C_ref로 정의한다. 이는 training-FLOP saving이며 벽시계 속도 향상이나 serving latency 감소가 아니다. (PDF 10쪽, Eq. 5)

Table 7의 지원 범위 안 수치는 다음과 같다.

대괄호는 12개 sparse cells를 resample해 2,000번 refit한 cell-bootstrap 95% interval이다. 논문의 “6.8–18.0%”는 이 조건부 compute-optimal-frontier estimate 범위를 요약한다. Figure 1의 14.7% [8%, 25%]는 C=10^21 FLOPs, S≈97%에서 같은 fitted loss에 도달하는 데 필요한 compute가 14.7% 적다는 뜻이다. 직접 관측된 단일 학습 run의 wall-clock 단축률이 아니다. Table 7의 10^22 행은 fit window 밖 extrapolation이며 19.6–23.5% point estimates와 매우 넓은 구간을 보이므로 이 해설의 headline 근거로 사용하지 않는다. (PDF 2, 10–12쪽, Figure 1b, Section 4.3, Table 7)

6. 다운스트림, domain, 길이와 in-context examples

저자들은 DCLM Core 22 tasks, 그중 free-form answer 9 tasks의 gold-token micro loss인 DCLM Completion, 그리고 별도의 MMLU 5-shot을 평가한다. Few-shot task는 10개 random seeds, zero-shot task는 결정적 1회 평가다. DCLM Core는 DCLM-v2 reference baseline을 0으로 놓는 centered accuracy의 22-task 비가중 평균이다. (PDF 5–6, 34–35쪽, Section 3.1, Appendix E, Eq. 11, Table 11)

Matched pair 승수는 DCLM Completion 96/96, DCLM Core 83/96이다. MMLU는 chance 25%보다 적어도 10 percentage points 높은 Baseline만 남긴 30 pairs 중 29 wins다. 모든 96 pairs를 대상으로 한 무조건적 MMLU 29/30 주장이 아니다. (PDF 12–13쪽, Figures 5–7)

Validation loss만으로 예상되는 성능을 분리하기 위해 저자들은 96 Baseline endpoints에 benchmark별 monotone sigmoid를 적합하고 SMELT residual을 계산한다. 이 calibration residual은 세 aggregate benchmark에서 scale별 평균이 양수였다고 보고된다. 이는 저자들의 모델 기반 비교이며, 모든 개별 downstream task가 향상됐다는 뜻은 아니다. Figure 9b에는 100M Commonsense처럼 음수 residual도 있고, category dominant pattern도 scale에 따라 달라진다. (PDF 13–14쪽, Eqs. 6–7, Figures 8–9)

Validation domain별 CE Gain은 aggregate fit의 exponents를 공유하고 domain별 intercept만 다시 적합한 결과다. C=10^21, S≈95%에서 Code 20.4%, Finance 16.8%, Math/STEM 16.6%, Knowledge 14.9%, Web 14.8%로 Code가 가장 크다. 이는 별도 domain scaling fit에서 얻은 frontier estimate이지 Code benchmark의 직접 accuracy 증가율이 아니다. Baseline-loss quartile 결과도 Q1 18.0%, Q2 16.3%, Q3 13.8%, Q4 15.9%로 단조롭지 않다. 저자들은 Q4 반등의 이유가 데이터로 결정되지 않는다고 밝힌다. (PDF 15쪽, Section 5.2, Figure 10)

문서 길이별로는 512–4096-token 네 긴 bucket에서의 정규화 gain 평균이 32–256-token 네 짧은 bucket의 1.52배다. Baseline-only controls는 parameters 추가가 0.98, experts 추가가 0.88로 같은 tilt를 보이지 않았다. 이는 gain shape를 평균 1로 정규화한 비교이므로 “긴 문서 정확도가 52% 높다”는 뜻이 아니다. (PDF 16쪽, Section 5.3, Figure 11a)

16개 few-shot tasks 평균에서 architecture gap은 k=0에서 0.9 percentage points, demonstrations가 있는 k=1에서 1.9 points로 넓어져 k=8까지 유지됐다. Dyck Languages의 k=32에서는 SMELT 29.8%, Baseline 26.4%다. Appendix C는 16개 중 maximum-shot gain이 positive이고 10-seed paired permutation test에서 p<0.05인 14 tasks만 그린다. 따라서 “모든 task에서 demonstration이 늘수록 계속 개선된다”는 보편 주장은 허용되지 않는다. (PDF 16, 32–33쪽, Figure 11b–c, Figure 24)

7. 두 번째 방문 내부: 관찰과 해석을 분리하기

저자들은 1M-token held-out sample에서 expert routing, residual updates와 attention을 비교한다. Sparse level이 높아질수록 두 방문의 top-8 expert overlap은 감소하지만 S≈97%에서도 2–3 experts를 재사용해 random routing보다 높았다. 동시에 일부 experts는 바뀐다. 즉 “동일 routing”도 “완전 새 routing”도 아니다. (PDF 17쪽, Section 6.1, Figure 12)

두 번째 방문의 residual update norm은 모든 16 grid cells에서 첫 방문보다 컸고, attention·MoE writes와 다음 sublayer에 들어가는 RMSNorm output의 visit-2/visit-1 norm ratio도 모두 1보다 컸다. 같은 물리 레이어의 두 방문 residual-update cosine은 1.6B 예시에서 0.42–0.65, 평균 0.56이며, nonmatching cross-visit pairs 평균 0.16보다 높다. 저자들은 이를 두 번째 방문이 첫 번째를 덮어쓰기보다 증폭하는 패턴으로 해석한다. (PDF 17–19쪽, Eqs. 8–9, Figures 13–15)

Attention에서는 Q와 K의 cross-visit cosine이 0.89–0.93으로 비교적 높고, V는 0.65–0.74, context PV는 0.56–0.69, output O는 0.49–0.64로 더 달라진다. Top-8 attended-token overlap은 같은 head 두 방문에서 56–66%, 다른 head control에서 28–34%다. 논문의 해석은 첫 방문에서 정해진 retrieval coordinates가 상당 부분 유지되는 반면 value/content가 더 크게 바뀐다는 것이다. (PDF 20–21쪽, Section 6.3, Eq. 10, Figures 16–17)

Dyck case study에서 ablation으로 고른 한 head의 k=4, 1.6B 예시는 BOS attention mass가 0.60에서 0.02로 줄고 demonstration-answer mass가 0.24에서 0.85로 늘었다. 1M-token 일반 validation sample에서도 visit 2의 segment-start mass가 대부분의 head와 layer에서 줄어드는 경향을 보고한다. 저자들은 attention sink 감소와 content-relevant tokens로의 재배분이 ICL advantage와 관련될 수 있다고 제안한다. 그러나 이 분석은 descriptive probe이며, 어떤 내부 메커니즘이 gain의 원인인지 밝히는 causal account는 미래 과제로 남긴다. (PDF 21–23, 33–34쪽, Section 6.4, Figures 18–19, 25)

8. 제약, 반증·철회 기준

  • 세 예산은 정확한 항등이 아니라 sparse fit cells에서 각각 최대 3.9%, 1.0%, 3.6% mismatch를 가진 근사 일치다.
  • 산술 FLOPs·총 non-embedding parameters·KV cache를 맞췄지만 wall-clock, 통신, sparse routing 효율, 메모리 대역폭과 latency는 맞추거나 측정한 결과가 아니다.
  • 설계 ablation은 200M scale에서 각 configuration을 한 번 학습했다. 표의 10 seeds는 주로 few-shot evaluation variability이며 training-run variability가 아니다.
  • Scaling law는 각 architecture에 별도로 적합한 estimate다. S=0은 fit에서 빠지고, fit window 밖의 10^22와 훨씬 큰 compute는 extrapolation이다.
  • 내부 corpus와 proprietary Transformer family의 전체 architecture/training stack은 공개되지 않았다고 Appendix A가 밝힌다. 이 문서는 독립 재현을 주장하지 않는다.
  • Downstream win rate, calibration residual, domain CE Gain, length-normalized gain과 ICL sweep은 서로 다른 estimand다. 이들을 하나의 “모든 task에서 같은 비율로 좋아졌다”는 수치로 합칠 수 없다.
  • Attention-sink와 residual probe는 상관적·기술적 관찰이다. sink 감소가 gain을 일으켰다는 인과가 입증된 것은 아니다.
  • 더 큰 scale에서 50% span·2×가 더 이상 최적이 아니거나, 반복이 없는 matched Baseline이 재현 실험에서 동등·우위이고, 동일 세 예산에서 gain이 사라지거나, systems measurement에서 산술 이득보다 큰 wall-clock penalty가 확인되면 이 해설의 적용 범위를 축소해야 한다.

9. 안전하게 말할 수 있는 결론과 말하면 안 되는 결론

안전하게 말할 수 있는 결론은 다음과 같다. 저자들의 MoE 실험과 별도 scaling fits에서는 토큰당 FLOPs, total non-embedding parameters, KV cache를 근사 일치시킨 조건에서도 가운데 절반을 두 번 방문하는 SMELT가 비교 Baseline보다 나은 loss와 downstream pattern을 보였고, 지원된 compute-optimal frontier에서 6.8–18.0%의 training-FLOP saving을 추정했다. 이 결과는 “looping can improve under matched budgets”를 논문이 시험한 MoE, training regime, scale, sparsity와 평가 범위에서 지지한다.

말하면 안 되는 결론은 다음과 같다. 전체 네트워크를 두 배 실행한다, 54B가 active parameters다, 계산비용이 완전히 같다, 14.7%가 직접 측정한 wall-clock 속도 향상이다, 모든 benchmark와 task에서 항상 이긴다, attention sink 감소가 성능 향상의 인과로 입증됐다, 독립 재현이나 production deployment가 완료됐다, 또는 looped Transformer가 일반적으로 비용 없는 추론을 제공한다는 주장은 논문 범위를 넘는다.
