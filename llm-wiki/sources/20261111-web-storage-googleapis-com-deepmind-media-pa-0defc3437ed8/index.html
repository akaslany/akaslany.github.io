원문

Multimodal Knowledge Agent (MKA) 벤치마크 해설 보고서

1. 개요 (Overview)

[사실 (Fact)] 본 보고서는 Google DeepMind 연구진이 2026년 11월 10일 발표한 논문 *"MKA: Evaluating Multimodal Knowledge Agents on end-to-end professional tasks"*를 바탕으로, 지식 작업(Professional Knowledge Work) 환경에서 멀티모달 AI 에이전트의 시각적 이해력과 종단간(End-to-End) 수행 능력을 평가하기 위해 개발된 Multimodal Knowledge Agent (MKA) 벤치마크를 정밀하게 분석한다. MKA 데이터셋은 10개 주요 경제 분야(Business, Construction, Education, Engineering, Finance, Healthcare, Law & government, Logistics & mapping, Science, Software & data) 및 83개 직업군에 걸친 200개의 평가 태스크로 구성되어 있다 ([SOURCE_IMAGE_1] 참조).

[사실 (Fact)] 각 태스크는 2개에서 45개(평균 7.30개)의 이종(Heterogeneous) 입력 파일(건축 도면, 회로도, 의료 영상, 지리공간 지도, 스프레드시트 등)을 복합적으로 분석하여 .xlsx, .pptx, .pdf, .docx, .html, .png 등 독립적인 실행 파일 형태의 최종 결과물(Deliverable)을 생성하도록 설계되었다. 평가 체계는 격리된 샌드박스 환경에서 구동되는 에이전트형 채점기(Agentic Autorater)를 활용하며, 도메인 전문가 3인과의 검증 연구에서 96.2%의 pairwise 이진 기준 일치도(Cohen's $\kappa = 0.911$)를 달성했다.

[소스 주장 (Source Claim)] 현실의 지식 작업은 시각적으로 조밀한 문서를 해석하고 최종 작성물의 레이아웃과 포맷을 시각적으로 검증하는 과정을 필수로 포함한다. 그러나 기존 프론티어 AI 에이전트들은 주로 코드 작성 중심의 학습 환경으로 인해 시각(Vision) 정보를 직접 관찰하기보다 텍스트, 마크다운, CSV 변환이나 OCR 엔진 및 컴퓨터 비전 스크립트에 과도하게 의존하는 '텍스트·코드 편향(Text-and-Code Bias)'을 보인다. 기존 벤치마크(GDPval, APEX-Agents, GDP.pdf, GDP.xlsx 등)는 텍스트/스프레드시트에 치중되어 있거나 단일 턴 응답만을 평가하여, 이미지 보기 도구를 제거하더라도 성능 평가 점수에 변동이 없는 등 에이전트의 시각적 인지 맹점을 포착하지 못하는 구조적 한계를 지닌다.

[작성자 해석 (Interpretation)] MKA 벤치마크는 에이전트 평가의 패러다임을 단순 텍스트 질의응답이나 단순 코드 실행에서 '시각적 인지-다단계 도구 사용-독립 실행 파일 작성 및 검증'의 완전한 종단간 워크플로우로 전환했다. 특히 시각 정보가 단순 참고 자료가 아니라 태스크 성패를 좌우하는 '필수적 시각 인식(Load-Bearing Vision)' 속성을 부여함으로써, 기존 에이전트들이 파이썬 스크립트나 OCR로 시각적 관찰을 우회하려는 편향을 정밀하게 타격하고 프론티어 AI 모델의 실질적인 지식 작업 역량을 엄격하게 검증하는 기준을 제공한다.

2. 주요 논점 (Key Discussion Points)

2.1. 기존 벤치마크의 텍스트·코드 편향 및 맹점 분석

[사실 (Fact)] 현재 프론티어 에이전트들은 작업 공간 내 파일이 주어졌을 때 문서를 플레인 텍스트, 마크다운, CSV로 변환하거나, 취약한 OCR 엔진 및 파이썬 컴퓨터 비전 스크립트에 과도하게 의존하는 경향을 보인다 (Section 1). 기존 대표 벤치마크들과 MKA의 구조적 특성을 비교한 명세는 아래 [Table 1]과 같다 (Section 1 및 Section 5).

[소스 주장 (Source Claim)] 연구진은 프론티어 비전-언어 모델(VLM)들이 픽셀 정보를 직접 보면서도 텍스트 사전 지식에 쏠리는 **언어적/텍스트 사전 편향(Linguistic/Text-Prior Bias)**과 2차원 기하학적 구조 추적에 실패하는 **기하학적 인지 맹목성(Geometric Blindness)**을 내재적으로 지니고 있다고 지적한다 (Rahmanzadehgervi et al., 2024; Vo et al., 2025; Section 1). 기존 벤치마크들이 이러한 맹점을 검증하지 못하는 구조적 이유는 다음과 같다:

  1. GDPval 및 APEX-Agents: 다중 파일 오피스 환경을 다루지만 태스크 핵심 신호가 텍스트나 표 데이터에 집중되어 있어 시각 도구 없이 파이썬 스크립트나 OCR만으로 성능 손실 없이 우회 완수가 가능하다. 실제 GDPval에서 이미지 보기 도구(view_image)를 제거하더라도 Gemini 4 Carbon의 평가 점수(Overall WSR 88.1% vs 88.2%)는 변동이 없었다.
  2. GDP.pdf 및 GDP.xlsx: PDF 또는 단일 Excel 파일 등 단일 포맷에 한정되어 다중 파일 및 모달리티 간 교차 추론을 평가하지 못하며, 단일 턴 텍스트 응답만을 요구한다.
  3. 시각 QA 및 브라우징/GUI 벤치마크: 단일 턴 질의응답에 머물거나(MMMU-Pro), 짧은 문자열 일치만을 평가하거나(BrowseComp), 픽셀 단위 클릭 동작과 추론이 뒤얽혀 결과물의 논리적·구조적 품질을 독립적으로 평가하지 못한다(OSWorld).

2.3. 에이전트 하네스(Stirrup) 및 에이전트형 채점기(Agentic Autorater) 평가 체계

[사실 (Fact)]

1. 에이전트 실행 환경: Stirrup (v0.2.1)
  • 격리 샌드박스 사양: Debian 기반 Python 3.13 격리 샌드박스 (python:3.13-slim-trixie), 4 vCPU, 128MB 기본 RAM (최대 16GB 동적 버스트), 인터넷 접근 허용. /workspace/input에 입력 파일 배치.
  • 사전 설치 실행 환경: LibreOffice, Tesseract OCR, pymupdf, weasyprint 및 주요 파이썬 오피스 라이브러리.
  • 제한 조건: 태스크당 최대 250턴, 8시간 벽시계 시간(Wall-clock limit), 최대 1M 토큰 컨텍스트 지원. 전체 컨텍스트의 70% 도달 시 동적 컨텍스트 압축(Compaction) 수행. 마지막 20턴 남은 시점 경고 전달.
  • 제공 도구 4종: code_exec (Bash/Python 실행, 타임아웃 300초), view_image (이미지/프로그래밍 렌더링 픽셀 로드), web_search (웹 검색, 타임아웃 180초), finish (결과물 검증 및 세션 종료).
2. 에이전트형 채점기 (Agentic Autorater) 구조 및 평가 구현 메커니즘
  • 채점 모델 및 독립 환경: GPT-6 Luna 기반 Stirrup 에이전트. 샌드박스 내 인터넷 접근 차단. 후보 결과물 파일과 최종 텍스트 응답만 /workspace에 로드되며 원본 입력 파일은 제공되지 않음 (루브릭 자체에 정답 기준 및 오차 범위가 완전 수록됨).
  • 시각 렌더링 및 파이프라인 우회 방지 구현 메커니즘 (Appendix A):
    1. 시각적 렌더링 검사: 오피스 및 PDF 결과물 검사 시 CLI 변환 스크립트 실행.
      • LibreOffice 헤드리스 변환: soffice --headless --norestore --nolockcheck --convert-to pdf <filename> --outdir /workspace
      • PDF-to-PNG 해상도 렌더링: pdftoppm -png -r 150 <file>.pdf <prefix> 실행 후 view_image로 레이아웃, 색상, 서식 검사.
      • 스프레드시트는 페이지 영역 잘림을 방지하기 위해 추가로 CSV 변환(soffice --convert-to csv)을 병행하여 픽셀 검사와 계산값 검출을 동시 수행.
    2. 프로그래밍 라이브러리 파싱 및 결함 방지 처리:
      • openpyxl: 수식 셀 계산값이 캐싱되지 않은 경우 data_only=True 사용 시 None을 반환하는 거짓 불합격(False Negative)을 방지하고자 반드시 data_only=False 수식 검사를 병행하거나 LibreOffice 렌더링 계산값을 교차 검증.
      • python-docx: doc.paragraphs가 표(Table) 내부 텍스트, 헤더/푸터를 무시하는 결함을 방지하기 위해 doc.tables의 모든 셀 파이프라인을 정밀 반복 검사.
      • PPTX 슬라이드 개수: 메타데이터 오작동 방지를 위해 ZIP 압축 해제 후 unzip -l <file>.pptx | grep -c 'ppt/slides/slide[0-9]' 명령으로 물리 슬라이드 파일 수 정밀 집계.
3. 채점 루브릭 구조 및 수학적 평가 지표
  • 루브릭 구성: 총 14,284개 기준 (태스크당 평균 71.4개, 중앙값 68.5개, 범위 20~150개). 각 기준 $j$마다 1~5점 가중치 $w_{ij}$ 부여 (1점: 21.6%, 2점: 26.2%, 3점: 26.1%, 4점: 21.4%, 5점: 4.7%). 주 목표(Primary) 94.5%, 부 목표(Secondary) 5.5%. 전체 기준의 29.5%(4,217개 기준, 190개 태스크)는 메타데이터 상에 방향성 비순환 그래프(DAG) 의존성을 명시함.
  • WSR (Weighted Satisfaction Rate) 정의: $$\text{WSR}i = \frac{\sum_j w{ij} s_{ij}}{\sum_j w_{ij}} \quad (s_{ij} \in {0, 1})$$ 작성자 clarification: MKA 채점 체계는 DAG 선행 조건이나 통과 여부로 하위 점수를 0점 처리(Gating)하지 않고, 각 가중 기준 $w_{ij}$에 따라 독립적으로 점수를 합산한다. 이는 70개 이상의 루브릭 항목 중 단 하나의 미세한 오류로 태스크 전체 점수가 0점 처리되는 올패스(All-Pass) 방식의 취약성과 높은 분산을 방지하기 위함이다.
  • 성능 분할 지표:
    • Climb-WSR (핵심 프론티어 역량 지표): 이전 세대 모델 패널 4종(Gemini 3.8 Flash, Gemini 3.6 Flash, Claude Sonnet 5.5, GPT-6.1 Sol)이 3회 실행 중 2회 이상 통과하지 못한 난이도 높은 7,888개 기준 대상 평가.
    • Regression-WSR (기존 역량 보존 지표): 이전 세대 모델 패널이 안정적으로 통과(3회 중 2회 이상 통과)한 6,396개 기본 기준 대상 평가 (180개 태스크 대상).
    • Overall WSR: 전체 14,284개 루브릭 기준 대상 종합 평가 점수.

5. 한계와 불확실성 (Limitations & Uncertainties)

소스 논문 연구진이 Section 6(Limitations)에서 명시한 연구의 한계 및 미확인 요소는 다음과 같다.

연구진이 밝힌 6가지 연구 한계점
  1. 실행 변동성 포착 미흡: 각 모델당 태스크별 1회 실행 및 1회 채점만 진행하여, 신뢰구간이 태스크 샘플링 차원은 반영하지만 에이전트 행동 및 채점기의 실행 간(Run-to-Run) 변동성을 완벽히 포착하지 못함.
  2. 인간 일치도 검증 대상의 한계: 인간 전문가 일치도 연구(50개 태스크)가 고가중치 기준(가중치 3~5점)에 집중되어 있어, 1~2점 수준의 저가중치 세부 레이아웃 검사 항목으로 그대로 확장되지 않을 수 있음.
  3. 시각 소거 실험의 단일 모델 한정: 시각 도구 제거(view_image Ablation) 실험이 Gemini 4 Carbon 모델에 대해서만 수행되어 타 프론티어 모델의 시각 의존도 수준은 확인 불가.
  4. 인터넷 허용으로 인한 정보 우회 가능성: 샌드박스 내 인터넷 접근이 허용되어 있어, 에이전트가 파일 내부 시각적 extraction 대신 웹 검색을 통해 일부 정보를 획득했을 가능성이 존재함.
  5. Climb/Regression 분할의 패널 의존성: 난이도 분할 기준이 이전 세대 Gemini/Claude/GPT 모델 패널의 해결 능력 결과에 의존하여 정의됨.
  6. API 비용 산정의 시점 한계: API 산정 비용이 논문 작성 당시 제공자의 공시 가격(List prices) 기준이므로 가격 정책 변경 시 변동될 수 있음.
소스 미다룸 / 확인 불가 항목
  • 분야별 도메인 전문가 개별 실명: 10개 분야 83개 직업군 작성자의 실명은 소스에 기재되지 않음 (확인 불가).
  • 타 모델 시각 소거 데이터: Claude Fable 5.2, Claude Opus 5.5, GPT-6 Astra의 시각 도구 제거 시 정량 수치는 소스에서 다루지 않음 (소스 미다룸).
