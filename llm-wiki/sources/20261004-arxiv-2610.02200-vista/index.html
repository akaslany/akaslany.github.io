1. 연구 배경 및 기존 멀티모달 에이전트의 한계

1.1 기존 에이전트 구조의 주요 한계 분석

복잡한 대화형 환경에서 에이전트가 상태를 인식하고 자율적으로 판단하여 문제를 해결하는 기존 방식은 크게 언어 에이전트(Language agent)와 멀티모달 에이전트(Multimodal agent)로 나뉩니다.

  • 언어 에이전트 (Language agent): 환경의 관찰 정보를 텍스트, 코드, 또는 숫자 그리드와 같은 기호적 표상으로 변환한 뒤 대형 언어 모델(LLM)에 전달하여 추론 및 행동을 도출합니다. 그러나 동적이고 복잡한 시각적 환경을 기호나 텍스트로 손실 없이 완벽하게 추상화하는 데는 원천적인 한계가 존재합니다.
  • 기존 멀티모달 에이전트 (Multimodal agent): 시각-언어 모델(VLM)을 활용하여 입력 이미지를 시각 인코더(ViT 등)를 통해 단 한 번 시각 표현으로 인코딩합니다. 그러나 이러한 단일 인코딩 방식은 상호작용 초기에 향후 추론에 어떤 세부 시각 정보가 결정적으로 작동할지 예측하기 어렵기 때문에 손실적 압축(Lossy compression) 문제를 야기합니다. 그 결과, 전개되는 추론 과정에서 요구되는 미세한 시각적 상세 정보가 누락되어 정교한 연속 추론 능력이 저해됩니다.

또한 상호작용 이력이 길어지는 장기 작업(Long-horizon interaction) 환경에서는 모델이 수용할 수 있는 문맥(Context) 크기의 한계로 인해 과거의 시각 관찰 정보가 문맥 창에서 완전히 제거되거나 단순한 텍스트 요약문으로 대체됩니다. 이로 인해 모델은 과거에 확보한 시각적 증거에 재접근할 수 없게 되며, 장기적 시각 추론 지속성이 크게 제한됩니다.

1.2 비스타(VISTA)의 제안 목적 및 저자 보고 명시

연구진(Qiushi Han, Keya Hu, Linlu Qiu, Cathy Wu, Kaiming He)은 기존 에이전트 구조의 한계를 극복하고자 비스타(VISTA: Visual Harness for Reasoning in an Interactive World) 구조를 제안하였습니다.

비스타는 환경의 상태를 텍스트나 숫자 그리드로 변환하거나 코드 형태의 기호 프로그램(Symbolic program)을 구축하는 프로그램 합성(Program synthesis) 방식에 의존하지 않습니다. 대신 렌더링된 시각 관찰 정보를 직접 활용하며, 전체 상호작용 과정에서 반환되는 모든 시각 프레임을 원본 그대로 보존하고 모델이 능동적으로 조회·재구성할 수 있도록 지원하는 무손실 시각 하네스(Visual harness) 메커니즘을 제공합니다.

2. 비스타(VISTA) 시각 하네스의 3대 핵심 구성 요소

비스타의 시각 하네스는 장기 상호작용 환경에서 모델이 시각적 증거를 능동적으로 재방문하고 조작할 수 있도록 돕는 3가지 핵심 요소로 구성됩니다.

2.1 시각 관찰 (Visual Observation)

환경으로부터 렌더링된 고해상도 이미지를 직접 전달받아 관찰 공간을 구성합니다. 렌더링된 이미지는 환경 내 객체의 외형과 공간적 배치 및 상호 관계를 있는 그대로 보존하므로, 모델은 사전 학습 단계에서 축적한 시각적 사전 지식(Visual priors)을 직접 활용하여 물리적·공간적 구조를 직관적으로 파악할 수 있습니다.

2.2 무손실 시각 기억 (Lossless Visual Memory)

환경이 반환하는 모든 시각 프레임을 압축이나 해상도 저하 없이 원본 그대로 저장하는 무손실 기억 저장소입니다.

  • 중간 프레임 보존: 에이전트의 액션 실행 결과로 발생하는 동적 중간 애니메이션 프레임(Intermediate animation frames)까지 원본 상태로 완전히 저장합니다.
  • 색인화 및 문맥 독립성: 모든 프레임은 상호작용 턴(Turn) 번호와 프레임(Frame) 번호(예: t67 f0~f5)로 색인화되어 관리됩니다. 이 저장소는 모델의 대화 문맥 제한과 물리적으로 독립된 외부 저장소로 작동하므로, 장기 상호작용 이력 전체를 정보 손실 없이 유효하게 유지합니다.
2.3 능동적 조회 및 입력 재구성 (Active Retrieval & Visual Inspection)

모델은 추론 과정에서 필요한 시각적 증거를 능동적으로 조회하고 입력을 재구성하는 도구 호출 메커니즘을 통해 공간 및 시간에 걸친 재주의(Re-attention across space and time)를 수행합니다.

  • 시간·공간적 재주의 사례 (원문 그림 10a 참조): 중력 반전(Red click) 및 게임 리셋이 발생한 상황에서, 에이전트는 이전 22개 턴에 걸쳐 저장된 4개의 과거 프레임(t125, t128, t139, t145 등)을 단 1회의 inspect 도구 호출로 동시 조회하여 전체 지형 구조와 낙하 위치를 재구성합니다.
  • 국소 시각 상세 조회 사례 (원문 그림 10b 참조): 512x512 전체 이미지 관찰 시 확인하기 어려운 세밀한 영역을 원본 해상도 대비 약 13배 확대 조회(inspect)합니다. 이를 통해 빨간색 가드(Red guard) 블록 A(1,2), B(1,3), C(3,0)의 측면에 부착된 보라색 표식(Purple marker)의 정확한 방향(각각 오른쪽, 아래, 오른쪽)을 판별하고, 방어되지 않은 안전한 방향을 파악하여 올바른 파괴 순서(A $\rightarrow$ B $\rightarrow$ C)를 도출합니다.
  • 픽셀 값 읽기 (read pixels): 선택한 국소 영역 내 픽셀들의 정밀한 RGB 수치를 직접 반환받습니다. 이는 모델의 대화 문맥에 고해상도 전체 이미지를 반복 입력하지 않고도 국소 영역의 시각적 모호성을 정량적으로 완전히 해소하는 기술적 이점을 제공합니다.

3. 비스타(VISTA)의 상호작용 파이프라인 및 메모 구조

3.1 턴(Turn)별 대화 파이프라인 과정

비스타의 하네스는 학습된 별도의 모델이 아닌 순수 기계적(Mechanical) 인터페이스로 작동하며, 모델과 하네스 간의 다중 턴 대화 구조로 상호작용을 진행합니다.

  1. 관찰 (Observe): 턴 시작 시 에이전트는 최신 관찰 프레임과 실행 가능한 액션 목록을 전달받습니다.
  2. 추론 (Reason): 자유 형식의 자연어(Free-form natural language)를 통해 현재 상태를 분석하고 가설을 설정하며 계획을 수립합니다. 액션을 실행하기 전, 에이전트는 횟수 제한 없이 시각 기억 조회(inspect) 및 픽셀 읽기(read pixels) 도구를 자유롭게 호출할 수 있습니다.
  3. 행동 (Act): 추론이 완료되면 도구를 호출하여 액션을 실행합니다. ARC-AGI-3 환경에서는 play 도구를 사용하여 1회 게임 액션을 수행하며, GameWorld와 같은 확장 대화형 환경에서는 act 도구를 통해 키 조합 및 시간 지연 매개변수(예: act W+D 0.5 s 또는 act wait 0.4 s)를 정밀하게 제어합니다. 액션 실행 결과로 반환된 프레임들은 무손실 시각 기억에 색인화되어 즉시 저장되며, 마지막 프레임이 다음 턴의 관찰 정보가 됩니다.
3.2 지속적 노트 파일 활용 (GUIDE.md 및 WORKING.md)

에이전트는 환경에 대한 지식을 체계적으로 축적하고 유지하기 위해 두 가지 지속성 노트 파일을 자율적으로 관리합니다.

  • GUIDE.md: 레벨이 변경되어도 유효하게 유지되는 게임의 내구성 있는 규칙, 메커니즘 및 환경 상호작용 법칙을 기록합니다.
  • WORKING.md: 현재 진행 중인 레벨의 상태 분석, 특정 구역의 지형 파악, 단기 작업 계획 등을 기록하는 일종의 연습장(Scratchpad) 역할을 수행합니다.
3.3 문맥 인계 및 지속성 관리

상호작용이 길어져 모델의 최대 대화 문맥 제한에 도달할 경우, 에이전트는 핵심 추론 상태와 진행 상황을 요약한 요약 인계(Handoff summary)를 작성합니다. 이후 완전히 새로운 문맥(Fresh context)에서 대화를 재개할 때, 작성된 요약 인계문과 함께 기존 노트 파일(GUIDE.md, WORKING.md), 무손실 시각 기억 저장소, 액션 이력이 그대로 인계되므로 정보 손실 없이 장기 추론을 지속할 수 있습니다.

4. 실험 조건, 평가 지표 및 주요 결과 분석

4.1 평가 벤치마크 및 지표 조건
  • ARC-AGI-3: 명시적인 규칙이나 목표가 제공되지 않는 25개 공개 대화형 시각 게임으로 구성됩니다.
    • 평가 지표 (RHAE): 상대적 인간 액션 효율성(Relative Human Action Efficiency)을 측정합니다. 완료된 레벨은 처음 참여한 인간 플레이어의 액션 수와 동일할 경우 100% 점수를 받으며, 더 적은 액션을 사용할 경우 최대 115%까지 부여받습니다. 더 많은 액션을 소모하면 부분 점수가 부여되고, 미완료 레벨은 0점 처리됩니다. 점수 산출 시 후반 레벨일수록 가중치가 높게 부여되며, 각 게임별 최종 점수는 완료한 레벨의 가중 비율(Weighted fraction of levels completed)에 의해 캡(Cap)이 적용됩니다.
  • 기타 확장 벤치마크:
    • GameWorld: 34개 브라우저 게임 (성공률 및 진행도 측정).
    • AI GameStore: 10개 브라우저 게임 (인간 중간값 100 기준 정규화 점수의 기하평균).
    • BabyVision: 39개 시각 추적 문제 (정확도 측정).
  • 기반 백엔드 모델 및 추론 노력(Effort) 조건:
    • Claude Opus 5.0 (Claude Code CLI 적용, extra-high 추론 노력)
    • GPT-5.6 Sol (Codex CLI 적용, max 추론 노력)
    • GLM-5.3 Flash 320B (오픈소스 기반 모델)
4.2 주요 성능 평가 결과

실험 보고에 따른 비스타의 주요 시스템 성과는 다음과 같습니다.

  • Claude Opus 5.0 기반 VISTA: ARC-AGI-3의 25개 공개 게임을 모두 완료하여 RHAE 점수 100.00의 완벽한 성과를 달성하였습니다. 총 사용 액션 수는 7,302회로, 처음 참여한 인간 기준(17,135회) 대비 57.4% 적은 액션만을 소모하였습니다.
  • GPT-5.6 Sol 기반 VISTA: 25개 공개 게임을 모두 완료하며 RHAE 점수 99.00을 달성하였습니다.
  • GLM-5.3 Flash 320B 기반 VISTA: 오픈소스 모델 환경에서도 RHAE 점수 66.93을 기록하여 공식 기본 하네스 대비 압도적인 성능 향상을 입증하였습니다.

5. 소거 연구(Ablation Study) 및 주요 한계점

5.1 하네스 구성 요소별 단계적 성과 기여도

GPT-5.6 Sol (max effort, 200K context) 모델을 바탕으로 비스타의 하네스 구성 요소를 단계적으로 확장함에 따른 성과 변화는 다음과 같습니다 (원문 그림 5 참조).

  1. 공식 구현 (텍스트 그리드): RHAE 13.33 (총 액션 10,619회, 완료율 4%)
  2. 이미지 관찰 전환 (i): RHAE 47.32 (총 액션 16,343회, 완료율 36%) — 2D 시각 관찰 도입의 기여도 입증.
  3. 액션 및 시간 제한 완화 (ii): RHAE 51.66 (총 액션 22,544회, 완료율 44%)
  4. 연속 대화 및 문맥 압축 (iii): RHAE 65.82 (총 액션 28,626회, 완료율 60%)
  5. 노트 파일(GUIDE.md, WORKING.md) 추가 (iv): RHAE 70.05 (총 액션 23,702회, 완료율 76%)
  6. 무손실 시각 기억 및 조회(inspect) 추가 (v): RHAE 94.10 (총 액션 12,261회, 완료율 96%)
  7. 정확한 픽셀 값 읽기(read pixels) 추가 (vi, 전체 VISTA): RHAE 99.00 (총 액션 9,126회, 완료율 100%)
5.2 관찰 표현, 문맥 크기, 이미지 스케일 변화 분석

  • 텍스트 그리드 vs 2D 이미지 관찰: 64x64 텍스트 그리드 방식(RHAE 96.75, 액션 10,614회, 게임당 71.9M 토큰소모)과 512x512 2D 이미지 방식(RHAE 99.00, 액션 9,126회, 게임당 30.7M 토큰소모)을 비교할 때, 2D 이미지 방식이 더 적은 액션으로 우수한 점수를 기록하였습니다. 특히 토큰 소비 측면에서 텍스트 그리드는 프레임당 약 4,000 토큰을 소모하는 반면, 2D 이미지는 프레임당 약 308 비전 토큰만을 소모하여 토큰 효율성을 2배 이상 개선하였습니다.

  • 최대 문맥 크기 영향:

    • 100K 설정: RHAE 98.60, 게임당 약 18.5M 토큰 소비. 토큰 사용량이 절반으로 감소하면서도 RHAE 점수 하락은 0.4에 불과하여 짧은 문맥 환경에서의 뛰어난 효율성을 입증하였습니다.
    • 200K 설정 (기본): RHAE 99.00, 게임당 30.7M 토큰 소비, 총 액션 9,126회로 가장 최적화된 연산 대비 성과 효율을 달성하였습니다.
    • 780K 설정: RHAE 99.00, 총 액션 8,812회, 게임당 105.7M 토큰 소비. 문맥 크기를 대폭 확대하더라도 성능 향상 효과는 미미한 반면 토큰 소비량만 급증하였습니다.

  • 입력 이미지 스케일 영향:

    • $2\times$ 스케일 (128x128): 프레임당 $\approx 20$ 비전 토큰, 총 액션 12,590회, 게임당 39.8M 토큰 소비. 해상도 부족으로 인해 추론 정밀도가 떨어지고 액션 수가 증가하였습니다.
    • $4\times$ 스케일 (256x256): 프레임당 $\approx 77$ 비전 토큰, 총 액션 8,849회, 게임당 28.2M 토큰 소비. 기본 설정 대비 비전 토큰을 75% 절감하면서 동등 이상의 높은 성능을 보였습니다.
    • $8\times$ 스케일 (512x512, 기본): 프레임당 $\approx 308$ 비전 토큰, 총 액션 9,126회, 게임당 30.7M 토큰 소비.
    • $16\times$ 스케일 (1024x1024): 프레임당 $\approx 1,229$ 비전 토큰, 총 액션 15,331회, 게임당 71.1M 토큰 소비. 해상도를 지나치게 높일 경우 비전 토큰 소비가 폭증할 뿐만 아니라 문맥 내 불필요한 시각 정보가 늘어나 오히려 총 액션 수가 증가하고 추론 효율성이 저해됨을 확인하였습니다.
5.3 논문의 평가 조건 상 한계 및 시사점
  • 관찰 해상도와 비전 토큰 간의 균형: 관찰 해상도를 높이는 것이 성능 향상과 직결되지 않으며, 적절한 이미지 스케일을 설정해야 연산 자원 및 추론 효율성을 극대화할 수 있습니다.
  • 상호작용 연산 비용: 모델이 상호작용 턴마다 자유 형식 언어로 추론하고 반복적인 시각 도구 호출(inspect, read pixels)을 수행함에 따라 발생하는 실행 시간 및 추가 비전 토큰 비용에 대한 고려가 필요합니다.

6. 결론 및 요약

비스타(VISTA)는 대화형 환경에서 복잡한 시각 추론 문제를 해결하기 위해 시각 관찰(Visual Observation), 무손실 시각 기억(Lossless Visual Memory), **능동적 조회 및 입력 재구성(Active Retrieval & Visual Inspection)**을 체계적으로 통합한 범용 시각 하네스 구조입니다.

비스타는 기존의 코드 기반 프로그램 합성(Program synthesis)이나 기호 환경 모델링 방식에 의존하지 않고, 무손실 시각 기억 저장소와 도구 호출 기반 재주의(Re-attention) 메커니즘만으로 ARC-AGI-3 벤치마크에서 Claude Opus 5.0 기반 RHAE 100.00점(25개 공개 게임 전체 완료, 인간 대비 57.4% 적은 액션 소모)을 달성하였습니다. 본 연구 결과는 적절하게 설계된 시각 하네스 구조가 결합될 때 멀티모달 모델이 복잡한 장기 대화형 환경에서도 완벽에 가까운 추론 능력을 발휘할 수 있음을 성공적으로 입증합니다.
